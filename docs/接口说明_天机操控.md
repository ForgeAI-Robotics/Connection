## 2. 职责与流程边界

- 大脑：判断当前区域有无可清理目标，分配任务／步骤／尝试／命令身份，调用并核验原子能力。正式任务状态仍由原 Runtime 唯一维护。
- 天机 VLA：持有模型、相机和机械臂控制，判断实时执行准入，执行动作、停策略、保持、撤手，生成可信效果及退出证据。
- 天机导航：按已标定坐标到站、确认导航停止；与 VLA 共同定义可运输姿态、当前持物和控制归属交接。VLA 不直接派发导航。
- 原子接口只处理一次命令的 I/O 和核验，调用者持久保存原请求／尝试与消费事件的事实；不另建业务账本、任务循环或自动恢复控制器。
- 天机在现有任务管理与控制器中提供兼容路由，不另启一套操控执行系统。真实启动、部署及动作验证由现场负责人按授权安排，不因收到本文自动执行。

已确认的首版路线为门口→点位1→点位1旁的桶→点位2→同一桶→点位3→同一桶，底盘沿桌边平行直线往返、朝向不变。每点到位后观察，无垃圾则进入下一点，不确定则重观察／确认；有目标才抓取。每点一个目标时为 12 个动作阶段，观察与 HTTP 消息另计。实际坐标由导航标定，示意像素不是执行坐标。

## 3. 与 G1 的统一部分及天机扩展

正式请求复用 G1 六字段：`contract_version/task_id/command_id/operation/object_id/target_area`。**天机增加必填 `arm`，明确 `left` 或 `right`。**这是显式天机扩展，不改变 G1 六字段请求，也不要求 G1 现有执行器接收新操作。

| 项目 | 统一后的天机合同 |
| --- | --- |
| 版本 | `fq/reception-lan/v1`；当前天机草案 `cleanup.v0.1-draft` 单独按第 8 节读取 |
| 操作 | `grasp_trash`、`dispose_trash`，各自是独立原子能力 |
| `task_id` | 大脑一轮业务任务身份，对应旧草案的 `mission_id` |
| `command_id` | 大脑单次动作尝试身份，对应旧草案的单动作 `task_id`；不能与整轮任务混用 |
| `run_id` | 天机受理后生成并绑定的一次真实执行身份，在回执中返回；同命令不换 run |
| 执行臂 | 单臂 `arm=left/right`；双臂请求及聚合未在本版本定义 |
| 目标及作业区 | `object_id` 为本次目标身份，`target_area` 为桌面点或桶位身份；不是任意服务器文件路径 |

每次真实重试使用新的大脑 `command_id` 和天机 `run_id`，保留旧记录。旧／新身份映射存于原执行器任务记录及原大脑尝试，不靠全局“最后一个结果文件”猜测。

无需在任务中传模型路径、输出路径、导航坐标、自由控制参数、任意程序名、旧 `navigation_proof`、SONIC 授权或 O6 标识。策略及物体支持范围由 VLA 的可信配置与能力声明确定，具体定位／机械臂准入由 VLA 执行端核对。

## 4. 正式 HTTP 接口

业务接口使用 JSON 与 `Authorization: Bearer <token>`。大脑服务器只调用，模型、判别器与控制器留在天机侧。

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| GET | `/health` | HTTP 健康，不是机器人或动作就绪证明 |
| GET | `/v1/vla/capabilities` | 分别声明抓取、投放是否配置及支持的执行臂 |
| GET | `/v1/vla/control/status` | 活动命令、当前持物／运输交接事实及隔离实例声明 |
| GET | `/v1/camera/frames/latest?camera=ego_view` | 独立读取头部主相机新帧，供抓取前 VLM 观察；不创建动作任务 |
| POST | `/v1/vla/tasks` | 提交抓取或投放；200／202 仅表示受理／返回原事务 |
| GET | `/v1/vla/tasks/{command_id}` | 只查询原命令，不补发、不重试、不启动策略 |
| POST | `/v1/vla/tasks/{command_id}/cancel` | 请求取消原命令，之后查询退出事实 |

G1 的 `/pause`、`/finish` 是其效果确认扩展。本版不要求天机复制冰箱人工完成流程，也未实现天机自动 finish 调用；效果由可信 VLA 观察／现场确认生产者在原任务内形成。大脑不能在普通动作请求里注入一份“成功证据”直接完成任务。

### 4.1 请求案例

以下均为格式示例，物体、位置与任务身份须在实际调用前确认。

抓取：

```json
{
  "contract_version": "fq/reception-lan/v1",
  "task_id": "cleanup-demo-001",
  "command_id": "grasp-table1-001",
  "operation": "grasp_trash",
  "object_id": "trash-cup-001",
  "target_area": "table_1",
  "arm": "left"
}
```

投放：

```json
{
  "contract_version": "fq/reception-lan/v1",
  "task_id": "cleanup-demo-001",
  "command_id": "dispose-bin-001",
  "operation": "dispose_trash",
  "object_id": "trash-cup-001",
  "target_area": "bin_1",
  "arm": "left"
}
```

四个 ID 字段采用 1～128 位机器标识，允许字母、数字、`_.:-`，首字符为字母或数字。不能缺字段或增加未约定字段。投放前 VLA 必须从自己的当前任务／持物记录核对该臂确实持有本任务物体，并关联原抓取命令；大脑写入 `object_id` 不构成持物证明。

`target_area` 须与天机导航标定的实际作业区对应；本文 `table_1/bin_1` 是示例名称，若实际登记为其他名称，由双方统一映射，不直接复用 G1 同名点的地图或业务含义。

受理示例，HTTP 202：

```json
{
  "contract_version": "fq/reception-lan/v1",
  "accepted": true,
  "task_id": "cleanup-demo-001",
  "command_id": "grasp-table1-001",
  "run_id": "controller-grasp-run-001",
  "state": "accepted",
  "accepted_at": "2026-11-13T14:00:00+08:00"
}
```

受理前须持久化命令和 run 身份，可立即按原 `command_id` 查询。同 ID 同请求返回原事务、不再执行；同 ID 改参数返回 409 `COMMAND_ID_CONFLICT`，不覆盖原记录。单个操控执行槽忙碌时明确拒绝，不增加自动队列。新尝试不能抢占未知的旧动作。

### 4.2 查询、完成与退出

状态：`accepted/preparing/running/waiting_result_confirmation/stopping/succeeded/failed/cancelled`。本版大脑只将后三项当终态；等待确认不调用自动 finish。正常运行允许 `result=null`，不能因尚未结束就报格式缺失。

所有命令回包原样回传请求七字段，提供 `execution_mode=direct`、`run_id`、`accepted_at/started_at/completed_at`。时间使用带时区 ISO 8601；未开始／未完成对应时间为 null。身份或 run 映射未知时保留 UNKNOWN，不能拿其他任务、其他臂的结果顶替。

抓取成功案例：

```json
{

  "task_id": "cleanup-demo-001",
  "command_id": "grasp-table1-001",
  "operation": "grasp_trash",
  "object_id": "trash-cup-001",
  "target_area": "table_1",
  "arm": "left",
  "execution_mode": "direct",
  "run_id": "controller-grasp-run-001",
  "event_id": "controller-grasp-run-001:completed",
  "state": "succeeded",
  "accepted_at": "2026-11-13T14:00:00+08:00",
  "started_at": "2026-11-13T14:00:01+08:00",
  "completed_at": "2026-11-13T14:00:20+08:00",
  "result": {
    "execution_mode": "direct",
    "success": true,
    "object_grasped": true,
    "holding": "trash-cup-001",
    "holding_at_event": true,
    "carrying_posture_confirmed": true,
    "arms_clear": true,
    "policy_stopped": true,
    "publisher_stopped": true,
    "action_port_released": true,
    "evidence": {
      "contract_version": "fq/reception-lan/v1",
      "task_id": "cleanup-demo-001",
      "command_id": "grasp-table1-001",
      "operation": "grasp_trash",
      "object_id": "trash-cup-001",
      "target_area": "table_1",
      "arm": "left",
      "run_id": "controller-grasp-run-001",
      "event_id": "controller-grasp-run-001:completed",
      "source": "visual_verifier",

      "observed_at": "2026-11-13T14:00:19+08:00",
      "target_identity_verified": true
    }
  }
}
```

这只是格式示例，不是真实成功记录。`evidence.source` 可为 `visual_verifier` 或 `operator_observation`，必须来自真实观察／现场确认，且与原任务七字段、run 和 event 一致。`reference` 应可追溯，观察时间须在本次开始与完成之间，完成时间不能在接收端未来。当前杯／瓶抓持概率本身不提供 `target_identity_verified=true`，必须另有目标身份核验；缺证据返回 UNKNOWN，不强填。

| 判据 | 抓取 | 投放 |
| --- | --- | --- |
| 目标效果 | `object_grasped=true`、`holding=object_id`、`holding_at_event=true` | `released=true`、明确的 `holding=null`、`object_at_target=true`、`bin_verified=true` |
| 撤手／姿态 | `arms_clear=true`、`carrying_posture_confirmed=true` | `arms_clear=true`，确认撤离桶口 |
| 任务退出 | `policy_stopped=true`、`publisher_stopped=true`、`action_port_released=true` | 同左 |
| 完成证据 | 原身份、有效时间、目标身份已核验、可追溯的本次 run／event | 同左，目标为本次桶位 |

投放回包沿同一完整结构，七字段和证据切换到该投放命令，使用投放自己的 run／event，不复用抓取完成事件。不能把抓取判别器取反或空爪当落桶成功。失败、取消也须保留真实退出字段，不因进程退出或 HTTP 202 自动填 true。

`action_port_released` 只表示本次操控输出通路已退出；`publisher_stopped` 不要求关闭维持必要夹持的底层控制器，不证明全身断电或全部资源释放。不得为模仿 G1 字段而停止持物保持或伪造反馈。

### 4.3 取消与错误

取消原命令的请求体：

```json
{"task_id": "cleanup-demo-001", "reason": "operator_cancelled"}
```

响应需 `accepted=true` 并回传相符的 `task_id/command_id`。大脑始终把取消受理与完成分开，再 GET 原命令核对终态和退出；重复取消幂等，旧取消／迟到停止不能影响新命令。已成功命令保留成功事实，停止证据可补充，不能覆盖原首因或刷新旧完成时间。

投放未就绪的正式兼容错误示例，HTTP 501：

```json
{
  "success": false,
  "error": {
    "code": "CAPABILITY_UNAVAILABLE",
    "message": "真实投放技能尚未就绪",
    "retryable": false,
    "details": {
      "task_id": "cleanup-demo-001",
      "command_id": "dispose-bin-001",
      "action_started": false,
      "action_state_uncertain": false,
      "original_code": "SKILL_NOT_READY"
    }
  }
}
```

| 情况 | 正式兼容返回 |
| --- | --- |
| 请求／身份／执行臂错误 | 400／422 `INVALID_REQUEST` 或 `UNSUPPORTED_CONTRACT_VERSION` |
| 模型／技能未实现 | 501 `CAPABILITY_UNAVAILABLE`，明确两个 false 标记并保留原码 |
| 控制器未接通或当前作业条件不满足 | 409 `SAFETY_NOT_READY`，仅在确知未开始时提供对应事实 |
| 机械臂忙碌 | 409 `VLA_BUSY`，`details.active_command_id` 为确切的其他活动命令 |
| 同命令改参数 | 409 `COMMAND_ID_CONFLICT`，保留原事务 |
| 持物与本任务／物体不符 | 409 `HOLDING_STATE_CONFLICT` 或明确的 `SAFETY_NOT_READY` |
| 命令不可查 | 404 `TASK_NOT_FOUND`，不证明动作从未执行 |
| 执行中失败 | 原命令 GET 返回 failed，原始错误与结果／退出事实分别保留 |

受理前拒绝不携带非空业务 state、`accepted=true` 或 `started=true`，身份必须一致。现有旧网关的 503 顶层 code 不是上述正式错误，不能直接当作大脑已识别的未执行凭证；普通 503／500、超时、断线和冲突保持未知。大脑使用 VlaClient 按原 ID 有界重查，不自动重复 POST，不因错误更换 run／command ID。等待超时也不会隐式取消。

## 5. 能力与当前持物

`GET /health` 至少返回 `contract_version=fq/reception-lan/v1` 与健康状态；正式 `/v1/vla/capabilities` 示例：

```json
{
  "contract_version": "fq/reception-lan/v1",
  "real_action_enabled": false,
  "operations": {
    "grasp_trash": {"configured": true, "arms": ["left"]},
    "dispose_trash": {"configured": false, "arms": []}
  },
  "camera": {
    "head_rgb": true,
    "views": ["ego_view"],
    "frame_schema": "fq/vla-camera-frame/v1"
  }
}
```

如实列出两项，包括尚不可用的投放。configured 表示接入范围，不是机器人当前就绪；具体准入由实际执行端处理。大脑不因为技能未就绪而自动改为遥操、固定轨迹或 mock。

`/v1/vla/control/status` 返回合同版本、`active_command_id`，并如实区分 `holding_at_event`、`holding_now`、可运输姿态及 `nav_ready`。当前旧网关不具备这些实时保证，不得把历史成功当成当前持物。控制／导航侧还需明确来源、时间、实例、有效性和失效处理；**结果接收 TTL 5 秒不是持物租约**。

本次原子技能输出的 `navigation_allowed=false` 固定表示“该调用不签发导航权限”，即使任务判 PASS 也不自行调导航。后续 SOP 必须另核对当前持物、姿态、控制交接和导航条件。正式任务终态应在原执行器记录中持久保留，不能每次 GET 都重读过期 5 秒文件而遗忘已确认终态，也不能通过刷新事件时间让旧成功变新；历史终态与当前持物是不同事实。

### 5.1 抓取前的头部图片接口（参考 G1 当前实现）

**天机必须提供这个独立只读接口，供大脑在发起抓取前查看当前桌面。**当前下载包没有这一路由，不能把判别器内部能读取相机等同于大脑已能取图。天机侧复用现有唯一相机采集服务，不让大脑直接打开相机，也不为 HTTP 另开一套 USB 采集。

```text
导航到作业点并确认停止
    → 获取该边界之后的头部 ego_view 新图
    → 大脑 VLM 判断当前可达区域是否有明确可丢弃目标
       true：选择目标后再调用 grasp_trash
       false：记录该区域观察为空，再由后续流程决定下一点
       null／取图失败：重拍或请求确认，不视为无垃圾、不自动抓取
```

#### HTTP 请求与回包

只请求 `GET /v1/camera/frames/latest?camera=ego_view`，使用同一服务地址和 Bearer。此处 `ego_view` 固定映射天机真正的头部主相机；不能用腕图、俯视仿真、录像、布局示意或历史图片替代。它不要求已有抓取任务、执行臂或 `command_id`；抓取前任务尚未创建，不伪造 G1 动作绑定的 frame/v2。

HTTP 200 格式示例（图片内容、哈希和实例名为占位，不能直接当真实回包测试）：

```json
{
  "schema": "fq/vla-camera-frame/v1",
  "camera_key": "ego_view",
  "frame_id": "head-receiver-001/frame-120",
  "service_instance_id": "tianji-vla-service-001",
  "camera_receiver_instance_id": "head-receiver-001",
  "robot_serial": "actual-tianji-robot-id",
  "captured_at": "2026-11-13T14:00:01.100+08:00",
  "received_at": "2026-11-13T14:00:01.120+08:00",

  "content_type": "image/jpeg",
  "sha256": "REPLACE_WITH_SHA256_OF_JPEG_BYTES",
  "image_base64": "REPLACE_WITH_BASE64_OF_JPEG_BYTES"

```

| 字段／条件 | 交付与校验要求 |
| --- | --- |
| schema／视角 | 固定 `fq/vla-camera-frame/v1`、`ego_view`，不回落其他视角 |
| frame_id | 实际源帧身份；新传感帧才推进，不能每次 GET 把旧图片换个帧 ID |
| 服务／接收实例／机器人 | 三个非空身份字段均提供；采集器重启更换实例，可在调用时指定预期 robot_serial |
| captured_at | 真正采集时间，带时区；不能用 HTTP 响应时间或文件下载时间替代 |
| received_at | 相机服务接收该帧的时间，带时区且不早于采集时间 |
| age_ms／received_age_ms | 有限非负数，分别对应源和接收年龄；大脑加上请求往返耗时后均不得超过 500ms |
| 跨端时间 | 大脑还校验采集／接收绝对时间，拒绝旧图与超过原 G1 50ms 容差的未来时间；须同步时钟 |
| 图像与大小 | JPEG，解码字节不超过 2MiB；JSON 响应不超过 3MiB；图像不超过 800 万像素 |
| 宽高与完整性 | 整数宽高匹配实际 JPEG；SHA256 针对解码后的原始 JPEG 字节，不是 base64 文本 |

接口设置 `Cache-Control: no-store`，客户端请求 `no-cache`。无相机、新帧过期或编码失败时明确返回相应 503 错误，鉴权失败返回 401；不返回旧图冒充正常。能力声明中的 `camera.head_rgb=true` 表示接口已配置，不代替实际 GET 的新鲜帧检查。

500ms 是沿 G1 当前实现复用的取图／传输检查，不是新设的持物期限或模型推理时限。VLM 完成时间单独记录，不能刷新图片采集时间；模型返回较晚、场景／机器人位置变化时，后续调度须判断是否重拍。这个单次取图能力不自动签发抓取或导航权限。

```json
  "active_command_id": null,
  "nav_ready": false,

```

每个命令 GET 另带 `simulated=true`、`physical_execution=false`、`test_evidence.execution_count` 和 `test_evidence.motion_output_count`；计数来自隔离执行器真实启动与输出路径，幂等测试要求前者 1、后者 0。离线客户端缺隔离声明时不 POST；真实客户端拒绝模拟结果。不能将真机输出打开后仅修改这些字段就叫隔离。

| 合成物体 ID | 行为 |
| --- | --- |
