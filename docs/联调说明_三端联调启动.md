# 联调说明：三端联调启动

初版日期：2026-09-17  
当前更新：2026-09-20  
适用范围：从冷机到能发真机接待任务的完整启动顺序，包含大脑进程、DREAM/NX/VLA 一键启动、导航人工闸门、操控侧独立检查与重启、三端预检、发任务和收工。  
本机开箱、仿真四宫格、网页 / 飞书发任务见 [项目 README](../README.md)；三端 HTTP 契约分别见对应的 `接口说明_*`。

> 2026-09-24 工程入口更新：正常大脑为 `python -m brain`，网页为 `entries.web`，飞书为 `entries.feishu`，面板为 `ops`，启动前安装项目。飞书地址改为 `:5000`。当前代码使用统一 Runtime，`kernel_enabled=false`；本文历史真机启停步骤不构成本轮开关放行。真机切换先满足规划第 9.7 节，工程重启核对第 15.16 节。

## 1. 开机（大脑侧）

冷机只有面板自启，业务进程默认全停：

```bash
sudo systemctl status fqplanner-panel   # 不在就 sudo bash infra/systemd/install_panel.sh
```

浏览器开 `http://192.168.5.35:5678`，按卡片顺序点「重启」：

1. **Redis** —— 仅需 Slaver 的工具路径依赖；Desk 直连、观察、假接待可不启动。
2. **Master** —— `:5000`，真正执行任务。当前 `collaborator.clear: false`，重启不会主动清空 Redis 协作库，但会中断当前 Master 进程，所以面板仍会先弹确认。
3. **Deploy** —— `:8888`，网页入口，把请求转给 Master。
4. 按需：**飞书桥接**（飞书入口）、**Slaver**（MuJoCo / 3DGS 工具路径需要）、**Desk `:5008`**（通用任务 mock 后端）、**MuJoCo `:5001`**（几何仿真）、**3DGS `:5002`**（扫描场景看图，观察配置选中后提供画面，不自动跨环境回落）。

固定真机接待不经 Slaver 和 Desk，Master 直连 DREAM / VLA。每个服务一个 tmux session，名字就是服务 id（`tmux attach -t master`），日志统一在 `logs/YYYY-MM-DD/<服务>/`。`systemctl restart fqplanner-panel` 只重拉面板本身（单元 `KillMode=process`），不会带走业务进程。

## 2. 起真机三端

**开始之前的物理前置**：机器人在支撑架上、肩带挂好、急停在人手里、MID-360 视野内无人靠近。这一条不满足就不要往下点。

面板 DREAM 卡片点「启动」，等价于导航机上 `bash tools/g1_three_party_oneclick.sh start`（DREAM 项目根目录）。面板把它跑在导航机 tmux 会话 `g1_panel_oneclick` 里，输出经 `pipe-pane` 落到导航机 `/tmp/fqplanner_dream_oneclick.log`，面板 `tail -F`，所以面板重启不带走编排、也不丢日志。要接手就 `tmux attach -t g1_panel_oneclick`。

不用面板时，导航机上执行：

```bash
ssh dream
cd <DREAM_ROOT>
tmux new-session -s nav 'bash tools/g1_three_party_oneclick.sh start'
```

脚本要求真 TTY；tmux 用于避免 SSH 断开带走编排。

脚本内部顺序是：网络自检 → NX SONIC（冷机在这里启控制器）→ 相机、灵巧手 → 4090 Brain HTTP 8091 与导航 relay 5556 → DREAM 定位工作流。人工闸门按出现顺序四道：

| 序号 | 闸门 | 超时 | 面板对应 |
| --- | --- | --- | --- |
| 1 | 输入 `READY` | 无 | 面板自动代填 |
| 2 | `adapter` 窗口第一次 Enter（接管，等同手柄 A+X+B+Y，肩带保持挂着） | **600 秒** | 点「站立 Enter」 |
| 3 | 同窗口第二次 Enter（进 POSE 站立，等 stage 1 稳定后再点） | **600 秒** | 再点一次「站立 Enter」 |
| 4 | `strap-check` 窗口回车（站稳、解肩带、视野清空后） | **600 秒** | 无按钮，必须人到导航机确认 |

闸门 2/3 的 600 秒是硬超时。超时会打 `POSE ready file was not created; navigation remains locked.` 并退出编排，此时机器人还能靠 Enter 站起来，但 `arm`、地图、孪生和 9882 都不会再起，只能 `stop` 后 `resume`。

过了第 4 道闸门，coarse 定位、孪生、9882 才会起来。

### 2.1 面板 DREAM 按钮

- **启动**：在导航机 tmux `g1_panel_oneclick` 中执行官方 `start`，自动输入 `READY`，日志写入 `/tmp/fqplanner_dream_oneclick.log`；
- **站立 Enter**：每点一次只向 `g1_fixed_map_relocalize_navigation:adapter` 发送一个 Enter，两次分别对应接管和 POSE 站立；
- **停止**：执行官方 `stop` 并收掉 `g1_panel_oneclick`；
- **打开 9882**：打开经大脑机转发的审核页，服务未就绪时按钮为灰；
- 面板不会代替解肩带确认，也不会自动点击 9882 Approve。

`resume` 不提供面板按钮；发生人工闸门超时后必须先 `stop`，再手工执行 `bash tools/g1_three_party_oneclick.sh resume`。

## 3. 9882 点初始位姿

9882 默认只 bind `127.0.0.1`，局域网直连是 `ERR_CONNECTION_REFUSED`。面板在启动时已把它转发到大脑机，就绪后会自动弹窗，也可以点卡片上的「打开 9882」，地址 `http://192.168.5.35:9882`。不用面板可通过已配置的 DREAM SSH 别名开隧道：`ssh -L 9882:127.0.0.1:9882 dream`。

在页面上点机器人当前的初始位置和朝向，再 Approve。这一步永远是人工，面板不代点。Approve 之后定位收敛，8001 才真正可接任务。

## 4. 操控 VLA 检查与独立重启

正常冷机流程由 DREAM 一键脚本依次启动 NX SONIC、相机、灵巧手、VLA HTTP/relay 和导航工作流。本节只用于单独核查或重启操控侧，不能代替冷机一键流程。

### 4.1 操控侧前提

- 机器人有可靠支撑，急停由现场人员掌握；
- SONIC 已进入稳定站立，是物理 `rt/lowcmd` 所有者并启用 persistent controller；
- NX 相机 `:5555`、SONIC state `:5557` 和 LinkerHand 在线；
- 当前没有正在执行或状态未核清的 VLA 任务；
- 只允许一个合法发布者占用工作站 `:5556`。

安全门控位于 `<VLA_PROJECT_ROOT>/sonic_safety_gate/config.env`。现场默认：

```bash
SONIC_SAFETY_GATE_MODE=automatic
```

`automatic` 要求安全门启用、supervisor 在线且为 `WAITING`。`off` 只允许用于尚未移植 vendor 安全运行时的设备，并要求运行中 SONIC 同样显示为 `legacy/off`。

### 4.2 静态与实时依赖检查

```bash
ssh gpu4090
cd <VLA_BRIDGE_ROOT>

./run_agent_vla_runtime.sh check
./run_phase_aware_action_stack.sh live-dependencies
```

两项检查均不执行 pick/place。实时检查必须确认 SONIC、状态、相机、LinkerHand、LowCmd 所有权和安全模式一致，并且没有第二个不受管的 `:5556` publisher。

### 4.3 独立启动与状态

只重启 VLA HTTP `:8091` 和受管导航 relay `:5556`：

```bash
cd <VLA_BRIDGE_ROOT>
BRAIN_VLA_REAL_ACTION_ACK=PHYSICAL_ESTOP_READY \
  ./run_agent_vla_runtime.sh start

./run_agent_vla_runtime.sh status
curl --noproxy '*' -s \
  http://127.0.0.1:8091/v1/vla/control/status \
  | python3 -m json.tool
```

`BRAIN_VLA_REAL_ACTION_ACK` 只表示现场已完成人工安全确认，不能替代支撑、急停和在线依赖检查。独立启动不会启动第二个 SONIC，也不会直接执行动作。

状态至少核对：

- `service_ready=true`；
- `policy_running=false`；
- `active_command_id` 为空；
- 导航 relay 是常态所有者；
- 相机、SONIC 和灵巧手满足动作前置。

`startup_safety_attested=true` 只证明启动时检查通过；每个 pick/place hook 在取得 `:5556` 前仍会重新检查实时依赖。

### 4.4 place 人工批准

place 通过 DREAM 凭证校验后进入 `waiting_operator_approval`：

```bash
cd <VLA_BRIDGE_ROOT>
./run_brain_vla_bridge.sh attach
```

现场确认目标、机器人状态和急停后，在该终端按 Enter。超时或取消时不得启动 place；大脑、面板和脚本都不能模拟该批准。

### 4.5 无动作安全自检与实现测试

安全门闭环 shadow 测试：

```bash
cd <VLA_PROJECT_ROOT>
./sonic_safety_gate/manage.sh closed-loop-shadow-test
```

该测试只注入隔离 SOC 序列，不启动 `wbControl`、不发 FSM、不写 LowCmd。

脚本语法、Python 编译和单元测试：

```bash
cd <VLA_PROJECT_ROOT>
bash -n g1_brain_vla_bridge/*.sh
g1_groot_n17_inference/.venv/bin/python \
  -m py_compile g1_brain_vla_bridge/*.py
g1_groot_n17_inference/.venv/bin/python \
  -m unittest discover -s g1_brain_vla_bridge/tests -v
```

测试通过不等于真机动作已经验收。

### 4.6 独立停止

```bash
cd <VLA_BRIDGE_ROOT>
./run_agent_vla_runtime.sh stop
```

该命令只停止 Brain HTTP 和受管 relay，不停止 SONIC、相机或灵巧手；任务执行中会拒绝停止。如果策略或 `:5556` 所有权未核清，先处理原任务，不能强杀进程伪造安全收尾。

## 5. 发任务前的只读预检

不发动作，先确认三端都在：

```bash
curl -s http://127.0.0.1:5000/api/task_status
curl -s -X POST http://127.0.0.1:5000/api/task_preflight \
  -H 'Content-Type: application/json' -d '{"task":"开始接待"}'
```

`task_preflight` 只读下游状态，不提交导航或抓放。`required && !ready` 时 Master 的 `POST /publish_task` 会直接返回 `status=rejected`，所以 DREAM 不通时，网页点和飞书确认都应该在日志里看到 `[task] preflight … ready=false`，而不是跑进接待 skill 再 `FAILED FETCHING_WORLD`。面板真机层两张卡片同时绿灯，是同一件事的可视化。

## 6. 发任务

先核对运行模式：环境变量 `RECEPTION_MODE` 非空时优先于 `config/brain.yaml` 的 `reception_real.enabled`。公开模板 `config/examples/env.example` 默认是 `mock`；真机联调必须设置 `RECEPTION_MODE=real` 或移除该覆盖，并重启 Master。

两个入口，等价，都落到 Deploy `:8888` → Master `:5000`：

- 网页 `http://192.168.5.35:8888`。任务控制台四宫格是**当前仿真后端的四路相机**（不是四个仿真）：3DGS `:5002` 起来是扫描室内，否则 MuJoCo `:5001` 是几何厨房。直播是现渲，回放是该任务逐步截帧。
- 飞书私聊直接发，群里 `@机器人 /task <内容>`。运动类任务要原发送者确认；只读的「桌上有什么」不用确认。`LARK_TASK_MODE=dry_run` 只发卡不提交，`active` 才真发。

看执行过程：面板日志区或 `logs/YYYY-MM-DD/master/`，正文看 `[task]` / `[reception]` 行，Flask 访问日志只有方法和路径。DREAM / VLA 的探测和 SSH 输出在当天的 `monitor.log`。任务结束后飞书卡片会带「复盘」摘要；账本在 `data/memory/reflections/`，不改真机 Pipeline。闲聊/预检日志不再沿用上一次 `task_id`。

真机接待中途失败（例如停在 `NAVIGATING_TO_RELAY2`，VLA 仍持有 `cola_can_1`）时：先修现场，再在 `:8888` 点 **断点继续**（`resume: true`），从 `failed_phase` 接着发，不重开、不重抓。不要再点「开始接待」走新任务预检——空手门会挡住持物状态。确认要整单重开时才用 `force_new_task`。细节见 [接口说明_大脑 Brain §9.1](接口说明_大脑%20Brain.md)。

**证据等级**：当前 `vla_result_policy: hand_state_only`，抓取和放置两个照片判真开关都关。完整流程的终态是 `COMPLETED_HAND_STATE_ONLY`，只代表左手开合确认加至少 3 帧证据，**不等于**图像证实可乐在手上或已放到桌面。对外不要说成视觉验收通过。

## 6.1 首次三方动作联调顺序

首次部署、接口变化或真机链路大改后，不要直接跑完整单罐流程。按以下阶段逐级验收：

1. **零动作接口**：只读检查 DREAM/VLA 健康、世界、关系图、控制状态、幂等和错误响应；
2. **table2 + pick**：只导航到 table2 并执行一次 pick，保存终态和控制通路证据后停止，暂不进入 relay2；
3. **单独 place**：在受控现场验证 `waiting_operator_approval`、人工 Enter、释放终态和安全收尾；
4. **完整单罐**：前三阶段都有可复查证据后，再运行 table2 → pick → relay2 → relay3 → table1 → place。

任一阶段失败只处理本阶段，不用完整任务掩盖接口或控制权问题。涉及真实动作时继续遵守支撑、肩带、急停和现场人员授权。

## 7. 收工

顺序反着来：

1. 任务跑完或主动停任务，确认机器人不在动。
2. 面板 DREAM 卡片「停止」，等价 `g1_three_party_oneclick.sh stop`。它只关 DREAM 与 VLA 的 HTTP/relay，日志会打 `NX SONIC/camera/hand preserved`，机器人仍靠 SONIC 站着。面板同时收掉 `g1_panel_oneclick` 会话。
3. 机器人要坐下 / 控制器要退出，人到现场物理确认站稳后再 `bash tools/g1_fixed_map_relocalize_navigation_workflow.sh shutdown-sonic`。这条未经实跑验证，首次执行前先和导航组确认。
4. 大脑侧按需在面板停 Deploy / Master / Redis（顺序无所谓，但 Redis 最后）。面板本身留着。

## 8. 卡住时先看哪一条

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 9882 打不开、`connection refused` | 只 bind 了 `127.0.0.1`，或第 4 道闸门还没过、web 窗口没起 | 用面板的转发 / 自己开隧道；确认 `strap-check` 已回车 |
| 编排报 `POSE ready file was not created` | 两次 Enter 超过 600 秒 | `stop` 后 `resume`，只重起 DREAM |
| 冷机停在 `SONIC status/safety attestation failed` | 4090 runtime 要求 SONIC 已持有 `rt/lowcmd` | 已由导航组把 SONIC 提到 bridge 之前，2026-09-17 16:03 起修复 |
| `:8091` 在线但 `service_ready=false` | HTTP 存活但动作依赖未齐 | 查看 `/v1/vla/control/status` 的 blocker，回到 §4.1–4.3 |
| VLA stop 被拒绝 | 存在活动任务 | 跟踪原 `command_id`，等待或执行受控取消 |
| `:5556` 空闲但动作不能启动 | 仅端口空闲不构成合法交接 | 核对 relay ACK 和 DREAM 权威凭证 |
| place 一直等待 | 正在等待人工批准 | 按 §4.4 进入 Bridge tmux；不得远程伪造 Enter |
| 启动早期 `Host key verification failed` | 旧脚本对退役的 Windows 大脑 `192.168.0.108` 做 SSH 探测 | 已由导航组默认跳过，需要时 `G1_CHECK_AGENT_SSH=1` |
| 面板日志停更但导航机还在跑 | 面板重启、`tail -F` 断了 | 刷新面板会重建 follower；原始日志始终在导航机 `/tmp/fqplanner_dream_oneclick.log` |
| 任务秒变 `rejected` | 预检判定 DREAM 未就绪 | 回到第 2–3 步，别在 Master 侧找原因 |
| 预检报仍持有 `cola_can_1` | 抓取后失败又点了「开始接待」 | 修现场后点「断点继续」，不要 `force_new_task` 除非整单重开 |
| Redis 里协作数据没了 | 重启 Master 会清协作库 | 别把重启 Master 当健康检查 |
