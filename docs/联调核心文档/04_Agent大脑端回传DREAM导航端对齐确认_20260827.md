# Agent大脑端回传DREAM导航端对齐确认

日期：2026-08-27  
双方契约版本：`fq/reception-lan/v1`  
DREAM地址：`http://192.168.0.185:8001`  
依据：DREAM组《Agent大脑端对接DREAM导航端实施说明_20260827》

## 1. 对齐结论

Agent大脑端已经按照DREAM交接文档完成本地实现。双方对任务编排、四段导航、状态轮询、导航成功证据、动作通路互斥、关系图合同核对、幂等和不确定事务恢复的理解一致。

当前尚未完成的是同一局域网内的在线只读核验及真机三方联调。本机对`192.168.0.185:8001`的最近一次只读GET探测5秒超时，因此本文确认的是代码和接口契约对齐，不代表现场链路已经验收。

## 2. relay点职责确认

双方采用以下职责划分：

```text
Agent大脑：
决定何时执行relay2/relay3，并在POST请求中下发完整目标参数。

DREAM：
不自动调度relay，不自动触发下一段；加载审核副本仅用于安全校验，
确认Agent请求与已审核门段一致后执行。
```

关系图核对不会让Agent采用或覆盖DREAM坐标。Agent本地固定值仍是实际请求来源；DREAM关系图合同只作为发送前一致性检查。

## 4. 启动时只读核对

Agent启动接待任务时依次读取：

```http
GET /health
GET /v1/status
GET /v1/world
GET /total_scene_graph_latest.json
```

Agent核对关系图：

1. `contract_version=fq/reception-lan/v1`；
2. 根级`frame_id=map`；
3. `agent_navigation_contract.frame_id=map`；
4. `agent_navigation_contract`中leg1～leg4各出现一次；
5. 每段`target_id/route_phase/leg_index/goal_xyt/motion_mode/require_final_orientation`与第3节完全一致；
6. `nodes.door_1.evidence.navigation_contract.door_approach`与relay2一致；
7. `nodes.door_1.evidence.navigation_contract.door_lateral_exit`与relay3一致。

核对结果处理：

```text
完全一致 → 允许进入leg1
字段缺失或任何值不一致 → 停止在FETCHING_WORLD，不发送导航
```

Agent可接受`agent_navigation_contract`使用不同的外层嵌套形式，但每个包含`goal_xyt`的leg对象必须提供完整字段，并通过唯一`leg_index`识别。

## 5. 每段提交前的动作通路门

每次调用`POST /v1/navigation/goals`前，Agent都会轮询：

```http
GET /v1/status
```

只有以下字段成立才发送：

```text
navigation_transport_ready == true
```

等待上限为30秒。超时后停止当前Pipeline，不会在VLA仍占用动作通路时发送导航。

Agent不会因为以下字段暂时为false而把HTTP服务判定为故障：

- `motion_ready`；
- `localization_approved`；
- `gateway_ready`；
- `token_ready`。

这些状态继续由DREAM事务状态和现场9882流程表达。

## 6. 导航提交和成功证据

Agent调用：

```http
POST /v1/navigation/goals
GET /v1/commands/{command_id}
```

HTTP 202只记录为事务已接收。Agent仅在以下四项全部成立时推进：

```text
state == succeeded
result.success == true
result.reached == true
result.navigation_stopped == true
```

缺少任意字段都不视为到达，也不会调用VLA或下一段导航。

## 7. 请求持久化和幂等

Agent在每次真实POST前先原子保存：

```text
task_id
command_id
完整请求payload
runtime_phase
verified_state
```

存储方式：

```text
current_task.json.tmp
→ flush/fsync
→ 原子替换current_task.json

events.jsonl
→ 追加保存请求、远端终态和状态变化
```

本轮不使用数据库，不进行无人值守自动续跑。

## 8. POST响应不确定和轮询异常

Agent已按DREAM要求实现：

```text
POST连接异常
→ 不创建新command_id
→ 有界查询GET /v1/commands/{原command_id}
→ 找到事务则继续轮询原事务
→ 连续无法确认或连续404
→ RECOVERY_REQUIRED
→ 等待现场人工处理
```

轮询运行中事务时发生连续断线或404，同样进入`RECOVERY_REQUIRED`。Agent绝不会为“不确定是否已经执行”的运动重新生成command_id并补发。

确定收到的HTTP 4xx契约错误不会当作网络不确定，而是保存DREAM错误payload并停止Pipeline。

## 9. 与VLA衔接

```text
DREAM leg1真实成功并停止
→ Agent显式调用VLA pick
→ VLA终态成功、策略停止、navigation_port_ready=true
→ Agent获取动作后新图并完成VLM+LLM判真
→ DREAM /v1/status navigation_transport_ready=true
→ Agent提交leg2
```

table1后的place采用相同门控。DREAM不调用VLA；Agent不依赖`/nav_done`或`/grasp_done`。

RealSense本轮由VLA唯一打开，Agent不调用DREAM相机和inspection接口。
