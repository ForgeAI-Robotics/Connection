## 2. 正常启动

导航机上执行，脚本要求真 TTY，外面套 tmux 只是为了 SSH 断开不带走编排：

```bash
ssh dream
cd <DREAM_ROOT>
tmux new-session -s nav 'bash tools/g1_three_party_oneclick.sh start'
```

只想单独重起操控侧（8091 HTTP + 导航 relay，不动 SONIC / 相机 / 灵巧手）：

```bash
ssh gpu4090
cd <VLA_PROJECT_ROOT>
BRAIN_VLA_REAL_ACTION_ACK=PHYSICAL_ESTOP_READY ./run_agent_vla_runtime.sh start
```

收工：`bash tools/g1_three_party_oneclick.sh stop`。它只关 DREAM 与 VLA 的 HTTP/relay，日志会写 `NX SONIC/camera/hand preserved`，机器人仍靠 SONIC 站立。真要让控制器退出，另有 `bash tools/g1_fixed_map_relocalize_navigation_workflow.sh shutdown-sonic`，且必须先物理确认站稳；这条命令 2026-09-17 没有实际执行过，只是从脚本里读出来的。

## 3. 三个人工闸门

| 闸门 | 位置 | 超时 | 动作 |
| --- | --- | --- | --- |
| `READY` | 一键脚本前台 | 无 | 确认支撑、肩带、急停就位后输入 `READY` |
| 两次 Enter | 工作流会话 `g1_fixed_map_relocalize_navigation` 的 `adapter` 窗口 | **600 秒** | 第一次接管（等同手柄 A+X+B+Y），等 stage 1 稳定；第二次进 POSE 站立 |
| 解肩带确认 | 同一会话的 `strap-check` 窗口 | **600 秒** | 站稳且 MID-360 视野清空后回车 |

600 秒来自 `tools/g1_fixed_map_relocalize_navigation_workflow.sh:563`。超时脚本打出 `POSE ready file was not created; navigation remains locked.` 并退出；此时 `adapter` 仍活着，两次 Enter 依然能让机器人站立，但编排已经不在，`arm`、地图、孪生和 `web`（9882）窗口都不会再创建。2026-09-17 就是这么损失了一轮：闸门 16:12:52 出现，Enter 16:25 才按下。

编排退出而真机还站着时的恢复：先 `stop`（工作流会话必须不存在 `resume` 才肯跑），再 `bash tools/g1_three_party_oneclick.sh resume`，它只重起 DREAM，不重起 SONIC / relay / 相机 / 灵巧手。

## 4. 9882 审核页

`tools/g1_hybrid_localization_web_view.py` 的 `--bind` 默认取 `G1_WEB_BIND`，否则 `127.0.0.1`，而工作流启动这个窗口时没传 `--bind`，所以 `http://192.168.5.18:9882` 从局域网访问是 `ERR_CONNECTION_REFUSED`。两种访问方式：

```bash
ssh -L 9882:127.0.0.1:9882 dream   # 然后开 http://127.0.0.1:9882
```

或者用面板：它在启动时自动把导航机的 `127.0.0.1:9882` 转发到大脑机，浏览器开 `http://192.168.5.35:9882`，9882 一通面板还会自动弹出该页面。审核页上点初始位置和朝向再 Approve 始终是人工操作，面板不代点。

## 5. 面板 `:5678` 的对应关系

DREAM 卡片四个按钮：

- 启动：SSH 到导航机，在导航机 tmux 会话 `g1_panel_oneclick` 里跑他们原样的 `g1_three_party_oneclick.sh start`，输出经 `pipe-pane` 落到导航机 `/tmp/fqplanner_dream_oneclick.log`，面板 `tail -F` 它。`READY` 由面板用 `send-keys` 递入。想接手直接 `tmux attach -t g1_panel_oneclick`。
- 站立 Enter：每点一次只向 `g1_fixed_map_relocalize_navigation:adapter` 发一个 Enter，点两次对应两个阶段，发完回显该窗口最后若干行。不代解肩带。
- 停止：官方 `stop`，并收掉 `g1_panel_oneclick` 会话。
- 打开 9882：走上面那条转发；9882 未起时按钮为灰。

`resume` 不做按钮，太少用且必须先 `stop`，需要时按 §3 手敲。

## 6. 已修正的历史问题

- `g1_sync_reception_network.sh` 的 `check` 曾对 `Administrator@$G1_AGENT_HOST` 做 SSH 探测并带 `HostKeyAlias=192.168.0.108`，指向已退役的 Windows 大脑，必然报 `REMOTE HOST IDENTIFICATION HAS CHANGED` 后 `Host key verification failed`。导航组 2026-09-17 15:44 改为默认跳过大脑 SSH 与旧 Windows 配置检查，保留 VLA / NX 校验，并提供可选的 `G1_CHECK_AGENT_SSH=1`。
- `g1_agent_vla_integrated_start.sh` 的 `start` 曾把 `start_brain_vla_runtime` 排在 `start_sonic_if_needed` 之前，而 4090 runtime 要求 SONIC 已是 `rt/lowcmd` 拥有者，冷机必然停在 `SONIC status/safety attestation failed`。导航组同日 16:03 把 SONIC 提前到相机、灵巧手和 bridge 之前。
- 面板早期用一条 `ssh -tt` 前台持有脚本、靠进程内线程转发日志，面板重启即断流，导致导航机的超时报错看不见。现已改为导航机 tmux 托管加 `pipe-pane` 落盘，面板只读文件。
