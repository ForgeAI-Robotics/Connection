# 多端联调：Connection 本地图像 API 替换

发生日期：2026-10-20。用户要求继续优化，并明确只讨论替代云端识别图像的 API，不替代文本 API。本轮检查专用图像入口，补齐本地后端参数和鉴权支持，在阻止非本机模型请求的条件下调用真实 Qwen3.5-9B，并更新本机配置。

## 1. 发现的问题与改动

原现场描述已经指向本地，但接待视觉核验仍配置云端；桌面双图判断、视频抽帧消费者没有完整转发关闭 thinking 等参数。部分入口还强制要求云端 API Key。旧 Slaver 相机诊断遇到模型异常或空回答时，甚至会返回 normal。

本次沿现有入口修改：

- `shared/vision_options.py` 统一构造请求选项，不读取或另建模型端点配置。SDK 请求保留 `extra_body`；原始 HTTP 请求将其中字段展开到请求体。禁止 extra_body 覆盖模型、消息、流式方式和标准生成参数。
- `auth_required: false` 显式允许无鉴权的本地模型，使用占位凭据；默认仍要求各自配置的云端凭据。不存在失败后切回云端的逻辑。环境变量更换端点时不自动继承本地免鉴权属性。
- 本机回环地址的 SDK 客户端不继承桌面 HTTP/SOCKS 代理，避免已出现的不兼容代理 scheme 阻止本地调用；远端客户端不因此改变网络路径。
- 现场描述、桌面双图判断、Slaver 相机描述、候选物体识别和独立接待视觉核验转发显式生成参数、超时及本地非思考设置。抽帧学习复用这些选项，但本轮没有重测其视频理解能力。
- Slaver 诊断遇到异常、空输出或无法识别的状态时返回 unknown，现场工具返回 failure，不再把它伪装成 normal。
- 未改变 Runtime、执行反馈要求、任务／命令身份、核验阈值、LLM 裁决规则或照片核验启用开关。

## 2. 今天的运行环境

开始时本地模型服务不在线。按昨日长上下文配置启动时，检查到可用显存仅 24.14 GiB，小于启动要求的 33.15 GiB，启动失败。其他 GPU 作业仍在运行，没有停止它们来腾显存。

改用已有低显存候选 `channel3`：完整 BF16、MTP、4 执行序列、65536 上下文、2.5 GiB KV 和可扩展显存分配器；启动参数增加 `--gpu-memory-utilization 0.50`，显式 KV 字节预算仍独立生效。该百分比不是 GPU 硬上限。客户端仍保留原图，没有增加 4MP 限制。

服务随后启动成功，交付检查 `/v1/models` 实际报告 65536 上下文。默认启动脚本档仍为 parallel4，此次运行显式选择 channel3；不能把今日结果写成昨日 262K 配置的无条件复现。启动失败和成功日志分别保留在模型目录 `server-20261020.log`、`server-lowmem-20261020.log`。模型服务仍是临时用户服务，生产常驻、自启和预热就绪门尚未完成。

## 3. 实际图片调用验证

使用保存的仿真图片和用户桌面原图替代相机输入，保留真实模型 HTTP 调用。测试清除 VLM／CLOUD／OPENAI API Key 等环境变量，禁用 .env 加载，并拦截非 `127.0.0.1:18035` 模型请求。没有连接真实相机、移动机器人或执行抓放。

最终一轮：

| 入口／样本 | 完整调用耗时 | 本次可证明的结果 |
| --- | --- | --- |
| Brain 现场描述：有物体桌面 | 0.930 秒 | 原 capture_scene 接口收到本地回答 |
| Brain 现场描述：空桌画面 | 0.939 秒 | 原接口收到本地回答，未给整段描述做准确性评分 |
| Slaver 现场描述 | 0.509 秒 | 返回 described；模型请求确实到达本地 |
| 桌面关系判断：同一张实拍照片作为当前／标准图 | 9.828 秒 | 双图和 SOP 进入本地模型，返回可解析列表，未产生 clean／organize 动作建议 |
| 抓取图像核验：可见蓝色圆柱，未在夹爪中 | 0.903 秒 | 目标可见且未抓住的字段比较通过 |
| 抓取图像核验：目标可乐罐不存在 | 0.951 秒 | 目标不可见、未在夹爪中的字段比较通过 |
| 放置图像核验：目标可乐罐不存在 | 1.032 秒 | 目标不可见的字段比较通过 |
| Slaver 候选物体识别 | 0.234 秒 | 保存图像进入本地模型，返回候选中的蓝／红圆柱，无手机 |

**五类专用图像入口共 8 次真实模型调用，全部本地、占位鉴权、关闭 thinking，均正常 stop，无长度截断。** 原生回答仍可能带代码块，沿用原有解析行为；本轮没有靠清理答案后重新宣称严格裸 JSON 合格。

首轮另有 7 次真实调用，首次现场描述 11.691 秒、双图关系判断 13.758 秒，均保留。首轮候选物体识别的取图夹具配置不完整，返回空集合却没有调用模型；该项不能计为替换验证通过。修正夹具后，最终一轮以实际模型请求数量核对入口均被执行。最初脚本还因缺少仓库导入路径未运行，这不算模型失败或成功。

这是一组接口和有限负例验证，不是完整精度评测。没有真实抓住目标的正例、真实动作前后照片闭环或机场样本。桌面判断将部分应 keep 的个人物品写成 skip，虽然当前规划同样不生成移动技能，但语义不完全相同；自然语言形状、位置描述也未证明全部正确。因此不能据此声明模型效果等价于云端或所有图片都稳定 3～5 秒。

## 4. 本机配置、生效范围与保留项

已修改忽略提交的本机配置：

- `config/slaver.yaml` 的 `camera.vlm`：本地 Qwen 端点、`auth_required: false`、关闭 thinking，原有图像精度保持。
- `config/brain.yaml` 的 `reception_real.verification.vlm`：改为本地 Qwen，显式免鉴权和非思考参数，输出预算 1024，HTTP 超时保持 120 秒。
- 大脑主文字模型、独立文字裁决器均保留 DeepSeek，前后配置比较相同。
- `grasp_photo_verification_enabled`、`place_photo_verification_enabled` 原来均为 false，本次仍为 false；没有因模型接口接通而启用照片判真。

备份位于本机 `data/local_vlm_switch_20261020/`。Brain 现场描述与桌面判断按调用读配置；接待核验器持有大脑初始化时的配置，旧 Slaver 相机模块在导入时读取配置，已有进程需要按运行状态安排重新加载／重启。本轮没有重启现有生产大脑或 Slaver，也没有部署到其他服务器，跨机器模型地址不能照搬回环地址。

预留的 Slaver“带原始图像进行工具选择”路径仍使用其文字／工具模型配置，属于另一接口，不在本轮专用图像 API 替换范围；未为它改动文本模型。抽帧学习参数通过离线测试，但实际视频理解未复验。保留这些边界，不能笼统声称所有扩展路径都已经切换和验收。
