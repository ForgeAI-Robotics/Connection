# 多端联调：VLM、VLA 显存及仿真同机实测

发生日期：2026-10-20。用户要求核实 VLM 日常显存、是否跑过仿真，以及 VLA 项目启动和运行显存。本轮实际调用本地视觉模型，复跑隔离的大脑仿真任务，再加载项目真实 GR00T 权重做策略推理及同卡压力测试。没有启动实体机器人动作发布器。

## 1. 测量对象与口径

工作站为约 48GiB 显存的 RTX 4090。通过 NVML 约每 0.5 秒读取整卡、计算进程和图形进程显存，同一 PID 去重；按实验服务控制组或本次创建的 VLA PID 归属。以下统一使用 **GiB（1024³ 字节）**，为采样值，不保证捕获所有瞬时峰值。

| 对象 | 本次实际配置 |
| --- | --- |
| VLM | Qwen3.5-9B 原始 BF16，channel3 档，64K 上下文、2.5 GiB KV、最多 4 序列；日常识图请求关闭 thinking |
| VLA | 项目默认双相机 `checkpoint-25000-newBC-inference`，实际 `Gr00tN1d7` 模型与 `PhaseAwareRTCPolicy`，完整加载三份权重分片，3144016000 个参数均为 BF16 |
| VLA 输入／输出 | ego_view＋left_wrist 两路 640×480 保存仿真图、符合契约的均值合成状态；40 行动作块，30→50Hz 时间合同；第一轮普通推理，后续使用 RTC 历史动作 |
| VLA 服务 | 复用项目 PolicyServer／PolicyClient，独立监听本机 18554；计算结果只检查形状、有限性并记录，不发布到 5556 或机器人 |
| 仿真 | 现有实时 MuJoCo 桌面相机，以及独立 Desk 语义抓放后端；不等于完整 G1／Isaac Sim 场景 |
| 大脑 | 独立实验端口 18050，DeepSeek 文本规划＋本地 Qwen 视觉，独立账本；未改生产工作区的文字模型 |

没有使用只初始化架构的 GR00T CI 测试，显式移除跳过模型权重的环境开关。项目 checkpoint 校验通过，实际模型参数及 dtype 在加载后记录。

## 2. 显存结果

| 阶段 | 对应进程显存 | 说明 |
| --- | --- | --- |
| VLM 已预热、空闲 | **22.91 GiB** | 含模型、缓存和上下文；不是仅权重大小 |
| VLM 原图识别、三路短字段、实时仿真识图 | **峰值 22.91 GiB** | 本轮既有缓存高水位下没有明显新增常驻显存；不代表所有输入的硬上限 |
| VLA 加载完成、未进行推理 | **6.33 GiB** | 真实 GR00T 策略模型，非只有 HTTP 桥 |
| VLA 首次及连续推理 | **峰值 6.51 GiB** | 包含 CUDA 上下文和分配器缓存 |
| VLA 推理后空闲 | **6.51 GiB** | 分配器保留已申请显存，没有随着请求结束全部释放 |
| 本轮轻量 MuJoCo 相机渲染 | **约 0.147 GiB** | 不可用于预算完整 G1 或 Isaac Sim |
| Brain／Desk 进程 | 未观测到 GPU 分配 | 本轮文本规划在云端，Desk 为语义状态模拟 |
| **VLM＋一个 VLA＋本轮仿真同时运行，整卡** | **峰值 30.75 GiB** | 包含桌面和其他非模型 GPU 占用，不能全部记到模型上 |

VLM 单独工作阶段整卡曾达到约 24.39 GiB，比其自身 22.91 GiB 高；差额属于其他进程／设备开销。各组件峰值不一定在同一时刻出现，不用简单相加替代整卡采样。

VLA 模型／处理器加载用时约 **8.87 秒**，不含 Python 进程启动和模块导入。PyTorch 加载后 allocated 为约 5.87 GiB；141 次推理的 allocated 峰值约 5.97 GiB、reserved 峰值约 6.06 GiB。它们与 NVML 的 6.51 GiB 统计边界不同，不能混为同一个数字。

此轮没有重启 VLM 测其冷启动峰值；日常常驻和推理占用是在已运行服务上实测。VLA 则从未加载状态实际启动，并覆盖首次推理与预热后的驻留。

## 3. 今天实际跑了哪些仿真

经现有 Connection HTTP 入口执行三项任务：

| 任务 | 耗时 | 结果与边界 |
| --- | --- | --- |
| live_head：实时 MuJoCo 桌面识图 | 1.062 秒 | 任务 succeeded，实际取新帧并调用本地 VLM；不将整段自然语言准确率记为通过 |
| live_empty：实时 MuJoCo 空桌识图 | 0.557 秒 | 任务 succeeded，取图和描述链路完成；仍不是空桌识别准确率验收 |
| generic_success：抓取 milk_1 并放到 milk_area | 2.466 秒 | Desk 语义仿真成功，恰好两次派发，释放与落点核验通过，个人物品状态未变 |

因此，**今天已复跑大脑＋实时 MuJoCo 看图，以及 Desk 抓放仿真**。Desk 物体状态更新不等于物理抓放；上述相机场景与 Desk 语义世界不是一个 GR00T 闭环控制回合。

另有 **141 次真实 GR00T 策略推理**：首次 1 次、稳态 40 次、混合负载 100 次，均正常返回 40 行有限动作数组。没有将输出发送给机器人，也没有让 GR00T 控制物理仿真抓取，不能将“数组有限”写成“抓取成功”。

## 4. 显存能装下，但存在计算争抢

VLA 客户端按部署脚本的 5Hz 查询频率安排请求，200ms 为一个查询周期；服务实际变慢时没有强行补发积压请求。

| VLA 推理负载 | 次数 | 中位数 | P95 | 最大值 | 超过 200ms |
| --- | --- | --- | --- | --- | --- |
| 首次推理 | 1 | 374ms | 不作分布结论 | 374ms | 1/1 |
| 只有 VLA 主动推理，VLM 常驻空闲 | 40 | 56.9ms | **62.1ms** | 66.4ms | 0/40 |
| VLA 与 VLM＋实时渲染混合运行 | 100 | 58.0ms | **396.4ms** | 397.8ms | **36/100** |

混合窗口包含 VLM 正在工作和空闲的时段，所以不能只看约 58ms 的总体中位数。该窗口内 VLM 的 9 次三路短字段请求约 3.78～3.97 秒，但 VLA 出现明显长尾，说明不能仅凭显存剩余判定实时性能合格。5Hz 查询预算也不等同于机器人 50Hz 动作发布频率；本次没有验证真实控制回路的时间安全性。

按当前完整模型和配置，**24GB 单卡无法同时容纳本轮 VLM＋VLA 的负载**。现有 48GB 卡运行了本轮约 30.75 GiB 的组合，但仍需解决／验证算力争抢。结论只覆盖 **一个 VLA 实例**，不能直接外推到三个独立 VLA 策略进程、多个 checkpoint 或附加 CV 模型；机器人 NX 上的 SONIC 等也不在本机显存统计内。

## 5. 实验隔离、失败与收尾

第一次实验已完成 VLM 单独负载采样，随后实验脚本因遗漏 sys 导入失败，尚未执行大脑仿真或加载 VLA。保留失败记录，修正后从剩余阶段继续，没有将该次记作模型错误或仿真成功。

仅调整模型目录下的独立 `http_workspace`：将实验大脑文字规划改为本机当前 DeepSeek 配置，视觉使用本地配置，重启隔离的 qwen35-brain 服务。原实验配置备份及私有 EnvironmentFile 留在本机数据目录；未变更生产配置、未访问 NX、未启动动作发布器、未停止其他 GPU 作业。

结束后只退出本次 VLA 测量进程，18554 已释放；VLM 和原有仿真服务保留。最后隔离大脑任务为 succeeded，未删除任务或命令记录。
