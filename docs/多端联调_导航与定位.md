## 问题与闭环

### 真实链路与测试条件

2026-10-12 最初五轮误用了 O6 固定路点执行器，未经过原 8001／9882／ROS g1pilot。它的偏差、8cm 门限和视频仅属于该执行器，不能用于评价真实导航项目。随后纠正链路，在隔离副本修正规划路径采样后第三轮五点一次完成；保留前两轮失败，且不把隔离修正写成现场已部署。[N2](#e-n2)、[N3](#e-n3)

同一任务是否重试、是否人工跳过、是否重新启动物理回合分别统计。导航使用仿真真值定位不等于真实传感器定位验收；完整接待还依赖操控、停止和交接证据。

### 现场末端失败与人工介入

2026-10-14 的任务 `83365f2a71324d5f89d7fde7c6b35b9c` 在 19 次人工重试后完成。主要证据包括 11 次末端航向相关失败、路径／转向净空拒绝和 3 次电机健康保护拒绝。拒绝的新尝试不计实际行走失败，用户报告的拖动不能当作已由遥测验证的动作时间线。[N6](#e-n6)

`goal_not_reached` 等错误名不足以确认冻结方向、运动跟踪、定位漂移或规划条件中的哪一个根因。实时近障碍和已知自由空间不足也是不同检查，不通过降低门限消除失败。成功回包中的 XY／yaw 偏差不是独立定位测量；后续仍需导航侧依据位姿、路径和速度原始数据复核。

### 控制、定位与批准

#### 7.1 已确认的问题及归因边界

1. **末端保持区无法自行补偿位置漂移。** 原程序关闭 `terminal_control_enabled`。
   `GoalArrivalGate` 在位置已锁定后，若距离超过最终容差、但未超过硬退出半径，返回
   `HOLD_POSITION`；`nav2point` 对应 `HOLD_ARRIVAL_DWELL`，发布零速度而不是恢复位置跟踪。
   精确 table2 的区间为 0.15—0.23 米，默认段为 0.30—0.38 米；本轮失败值与之对应。
   对本轮保存的原源码做无 ROS 离线复现：先以 5 厘米到达并进入转向，再输入 20 厘米或
   31.6 厘米偏差，至第 40 秒仍返回 `hold_position`。这解释保持不动的代码路径，
   不代表已解释全部物理漂移成因。复现和源码在 `20261010-review/source_audit/` 及
   `20261010-review/arrival_hold_reproduction.json`。
2. **横移段发生反复切换与超时。** 06 的该段记录约 150 次状态切换，08 约 392 次，
   主要在 `LATERAL_LEFT` 与 `LATERAL_ALIGN_YAW` 间切换。06 已接近门后目标，08 几乎未完成
   该段位移，不能都描述成“门后差一点”。原 9882 在 180 秒触发目标超时，不是大脑 HTTP 超时。
3. **到达回执不保证收尾后精确保持姿态。** 05 成功但桌前 yaw 误差从约 4.98° 增至 16.26°；
   到达和停稳是两个时刻，不能用成功回执替代抓取所需的实际对齐检查。

优先由导航／底层执行负责人处理末端位置与朝向的联合收敛、停稳漂移和横移模式切换；
不能仅放宽容差来让测试变绿。大脑当前失败拦截有效，但对 `goal timeout` 的中文展示仍较泛化，

#### 10.2 问题处置与验收建议

1. 导航负责人优先检查位置锁定后漂出最终容差的状态迁移：应有重新纠偏或明确退出路径，
   不应只保持零速等待无进展超时。单纯增大距离容差或延长超时不能证明根因已修复。
2. 导航与 SONIC／本体控制负责人一起核对成功回执时机和停稳保持；保留回执时、额外收尾锁定前、
   锁定后 3 秒的位姿，区分漂移发生在何时。不能仅凭 `navigation_stopped=true` 推断身体位姿不再变化。
3. 过门段按实际进入次数单独验收，检查横移／朝向状态切换及实际控制输出。本批原版的 180 秒超时
   是导航目标执行超时，不是 HTTP 请求超时；改通信协议不能据此被认定能解决问题。
4. 大脑侧继续保留原命令、失败和人工处置身份；下一轮真机在同样字段口径下复测，无重试通过和
   重试后完成分别计数。只有错误名称相似而缺少位姿／控制轨迹时，不直接合并根因。

### 五轮问题复核与归因

同日对上述五轮已保存的物理段、正式命令回包、大脑账本与 LLM 建议复核；本节不是新跑五轮。

- **导航侧可确认的问题**：7 次失败的最终位置误差超过 8 厘米，分别为第 1 轮 relay2 13.76 厘米、第 2 轮 relay2 22.13 厘米、第 3 轮 relay1 11.42 厘米、第 4 轮 relay3 9.90 厘米，以及第 5 轮 relay1 14.32、relay2 9.89、relay3 8.58 厘米。全部停止核验为真，朝向误差均在门限内；这些不是冰箱首点失败。五轮物理段没有记录 `physics_failure`。
- **导航侧尚待定位**：内部走路、转向和站稳阶段均记录 `state_reached`，但段末整体位置不达标，说明内部阶段完成不足以保证最终到位。需要进一步核对控制器阶段门限及转向、站稳中的位移，尚不能断定全部由某一种漂移机制引起。这是 SIMPLE 的 O6／SONIC 仿真执行链，不是同事真机导航栈的失败验收。
- **大脑流程核验**：正式下游命令将上述 7 次记录为 `failed`、`success=false`、`reached=false`；大脑保留失败尝试并进入恢复，未跳过失败点。五轮最终 `succeeded` 均建立在重试后通过的证据上。本轮没有发现把这些失败误判成功或错序推进的问题，但不能推论大脑所有功能无缺陷。
- **LLM 与错误信息仍有问题**：同一失败回包含 `error.retryable=false` 与 `result.simulation.retry_allowed=true`。前者在仿真 Store 终态错误中固定写入，后者由 Worker 在同回合可恢复时写入。6 条求助建议中有多条将前者解释为“不可重试”；另有建议读取后者而给出 `continue`。字段层次及语义没有清楚传给模型，建议解释不一致。需要区分原命令重放、以新命令尝试原步骤、人工确认及当前 Runtime 允许动作，不能仅把其中一个布尔值全局改成真。
- **恢复依赖**：8 条建议包含 6 条求助、1 条原命令查询、1 条继续。测试脚本模拟操作者检查并确认恢复，因此“最终完成”不等于 LLM 自主排障成功。第四轮对已明确失败的原命令又查询一次，保留核清价值，但也显示建议可能增加额外查询。

优先改进：先让仿真导航的段末到位稳定满足原门限；并统一错误与受控重试语义，再检验 LLM 建议的一致性。本次仅复核与制作视频，未实施这些修改，未重启服务或下发机器人任务。
