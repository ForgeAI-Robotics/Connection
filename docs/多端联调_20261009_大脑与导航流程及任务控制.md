## 1. 联调流程与证据口径

```text

→ 导航到中转点 2 → 横移到中转点 3 → 导航到 1 号桌
```

### 3.1 中转点 2：当前定位不在可通行区域

原始回执：

```text
NAVIGATION_NO_PATH
9882 rejected /set-agent-world-goal: HTTP 400:
{"error": "localization pose is not in inflated known-free space"}
```

已确认：上一段刚报告到达 2 号桌成功，下一段被当前定位的自由空间检查拒绝。人工继续后，仍使用目标 `[3.733075988421528, 6.215369909530748, 2.718279944258407]`，新命令成功。

责任边界：拒绝来自导航的定位／地图校验，不能翻译成“目标点一定到不了”，也不能据此认定大脑目标坐标错误。需要导航核对到达位置与下一段起点校验的一致性；定位变化、地图转换和膨胀边界是排查方向，尚未证明唯一根因。

## 5. 当天大脑侧修复与控制语义

### 5.1 原因展示和任务状态

- 页面保留中文原因、英文错误码和原始错误，不再把 LLM 异常“分析／建议”混入失败原因；后台反思与建议机制未因此删除。
- 修正 `INVALID_LEG_ORDER` 的中文映射：依据实际前置路段解释，不再固定显示成 relay2 → relay3。
- 区分提交被拒、执行失败和结果未知；明确拒绝只有满足结构化回执条件才视为未开始执行，不能把任意 HTTP 500 或连接错误都当成未执行。
- 展示失败历史、重试次数、人工继续次数；成功、人工跳过、未完成分别统计。人工跳过不伪装成成功，重试后成功也不删除旧失败。
- 控制按钮随任务状态启用，页面回执跟随当前任务更新；旧请求绑定任务、步骤和命令身份，避免误操作后续步骤。

### 5.2 四个按钮的最终约定

| 按钮 | 当天修改后的行为 |
| --- | --- |
| 暂停 | 大脑关闭后续派发；有当前在途命令时请求停止并查询确认。停止未确认时明确显示该状态 |
| 继续 | 恢复当前流程；未下发的先重新检查条件，已下发的先核对原命令。确认未完成且满足停止、资源等条件后，以新命令 ID 重试当前环节；原动作已成功则核验，不重复执行 |
| 跳过继续 | 放弃当前步骤并保留人工跳过记录，推进下一动作；执行中会先请求停止，停止或资源未核清时仍拒绝推进 |
| 取消任务 | 仅废弃大脑本轮任务、关闭后续派发和本地等待；不向导航／操控发送停止或撤回请求，不等待远端回执。保存历史和取消时的远端已知状态，不伪造停止证据 |

“取消”已改名为“取消任务”。该决定对应现场废弃整轮并另行重启导航的使用方式；任务显示取消不代表机器人已停止。文字入口的“停止”归暂停，“取消任务”归任务取消。

大脑本地取消同时处理阻塞等待和迟到结果，避免旧执行或模型回包继续推进已废弃任务。相关实现见 `src/brain/kernel/runtime.py`、`src/brain/application.py`、`src/brain/service_support.py` 及任务网页模板。

1. 导航修复并复测起点校验与末端超时；四段导航无需人工重试、无需跳过，一次完成。
