只有导航，没有 GR00T 推理、开门、抓取、放置；保留 O6 开手保持及原启动控制。
定位为仿真真值，扫描为合成，不能代表真实传感器或真机验收。

## LLM 与录像故障

这次实验入口读取了当前项目模型配置，但继承运行终端的 SOCKS 代理，客户端初始化报错：
`Using SOCKS proxy, but the 'socksio' package is not installed`。
异常建议 `source=rules`、`action=query_original`，没有实际完成 DeepSeek 推理，也没有执行该建议。
不能把它描述成 LLM 自主排障或将这个隔离进程的环境问题直接归因为主大脑模型不可用。
随后仅在本地测试进程去掉继承的 `ALL_PROXY/all_proxy`，配置中的模型客户端可正常初始化；
该检查未发送 API 请求，不算真实模型调用通过。

录像收尾存在本次适配错误：仅导航移除了 `SonicPhysics.bridge` 操控对象，但 O6 节点的 `finally`
仍先读取 `node.sim.bridge.logs`。该行 `AttributeError` 阻止后面的物理状态、接触记录及回放轨迹写盘，
容器因此退出码为 1。原始命令、大脑账本、导航日志和地图行走轨迹仍保留，不能据此复原完整关节录像，
也不能声称碰撞样本为零。视频未生成，原始轨迹不能由插值或另一回合代替。

本地已修正准备脚本：去掉无操控模式的收尾引用，增加运行中逐帧追加的轨迹文件、每秒刷新，
收尾先关闭轨迹流再保存完整物理数据。使用真实节点源码中的收尾逻辑，离线验证在无操控对象时
五个证据文件正常写出且保存的姿态不变。随后用户明确授权持续复验，后续结果另列，不修改首轮记录。

## 路径跟踪问题与隔离修正

用原规划器、原地图及第二轮 relay1 的实际起点离线复现，得到三点折线：
`(16.625, 10.875) → (10.125, 10.675) → (9.4, 11.7)`。
路径简化后的长线段没有中间跟踪点，而原跟踪器的最近点推进和前视目标选择基于离散路径点。
因此长线段上的偏移不能按密集局部路径及时纠正。实际轨迹在旧取物桌旁偏离后进入障碍停车。
这支持路径采样与跟踪接口不匹配的诊断，不把所有历史失败都归为同一原因。

第三轮在独立副本的 `dijkstra_planner.py` 发布路径前，沿已核验折线按最大 0.05 米间距补点。
离线检查确认：原拐点和终点精确保留，总长度一致，所有新增点位于原线段上；空路径和重合点正常。
不修改全局路径几何、目标坐标、横移模式、到达门限、障碍停车距离或大脑核验规则。
原 9882 与 nav2point 保持来源版本；规划器这处补点修改单独保留差异和前后哈希，不能称为整个导航源码未改。
修正仅用于仿真实验副本，未部署到同事导航工程或真机。
