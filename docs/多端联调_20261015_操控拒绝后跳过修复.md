# 操控明确拒绝后无法跳过

日期：2026-10-15。任务 `f3eba751c0774c7491cf4fcee2743fdd`，导航真机＋操控模拟。
用户报告模拟抓取不能跳过，随后明确要求修复。

## 现场事实与原因

11:25:52，用户跳过导航到 2 号桌，大脑核对原导航停止回执后推进到模拟抓取。
原导航回执为 cancelled、reached=false、navigation_stopped=true；人工跳过不等于到达。
模拟抓取原命令 `vla-pick-4fcee2743fdd` 因导航凭证不满足要求而明确拒绝：

```text
NAVIGATION_PROOF_INVALID
模拟操控的原导航到达及停止回执未确认
```

11:26:01 和 11:26:14 的两次跳过被大脑拒绝，提示“原动作停止或资源释放尚未确认”。
11:26:20 用户点击继续，生成 `vla-pick-4fcee2743fdd-r1`，再次因同一前置条件被拒绝。

Runtime 已记录 outcome=rejected、accepted=false、started=false、停止与资源已确认，且没有 open_command_id。
但跳过分支按 submitted=true 查找命令，把“已发出请求”误当成“下游已创建动作”，
重新查询并不存在的模拟抓取命令，导致跳过无法完成。这是大脑跳过逻辑问题；
操控拒绝缺少到达凭证的请求本身符合合同，不应通过伪造到达或成功来绕过。

## 修复

跳过时重新验证原拒绝回执的任务、步骤、尝试和命令身份及拒绝合同，排除这类未创建的执行命令。
此前仍有实际提交命令时，继续查询其停止和资源释放；不存在此前命令时可直接引用已核实的拒绝回执。
裸 404、网络异常、同 ID 冲突、身份不符的回执不获得该例外。
抓取与抓稳核验均记为人工跳过，保留原失败尝试、命令与物体状态，推进到中转点 1；
后续真实导航仍须通过自身执行条件。网页补充导航凭证缺失的中文解释。

## 验证与证据

复现用户顺序：导航失败 → 人工跳过导航 → 抓取拒绝 → 人工继续再次拒绝 →
重启附着 → 跳过抓取。验证不查询被拒绝的模拟命令，仍核对原导航停止；
抓取与抓稳核验不记成功、不伪造持物，下一段导航可在模拟端下发。
额外覆盖此前导航未停止，以及拒绝回执身份不符、裸 404 和命令冲突，仍阻止跳过。
