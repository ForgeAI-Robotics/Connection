# 多端联调：本地与云端 VLM 同图对照

发生日期：2026-10-19。用户提供一张办公桌照片，先要求本地 Qwen 识别，再要求与 Connection 配置的 VLM API 比较速度。本次仅调用模型接口，没有运行大脑任务、采集相机、派发机器人动作或修改服务默认配置。

## 1. 实际配置与方法

- 本地服务：Qwen3.5-9B，原始 BF16、视觉与 MTP 保留，当前 262144 上下文／10 GiB KV 档。首次识图开启 thinking，32768 输出预算，官方通用采样参数。
- 本机 `config/slaver.yaml` 的 `camera.vlm`：`qwen3-vl-plus`，DashScope 国际站兼容 API，`max_tokens=400`；适配器未配置 temperature 时取 0。照片核验配置也指向该模型，但本次直接使用现场描述适配器的端点和凭据解析，不代表验证了远端运行进程的生效配置。
- 原始 JPEG 为 934897 字节，客户端没有缩图。所有请求使用同一原图与同一问题，问题要求列出主要物品、位置并说明不确定处。
- 共 8 次流式请求：云端现有生成配置 1 次、本地原 thinking 配置 1 次，以及两端各 3 次非思考对照。后者统一 `max_tokens=2048`、`temperature=0`、`top_p=0.95`、`presence_penalty=0`、`seed=42`，分别使用各端支持的关闭 thinking 字段；其他后端默认参数不保证一致。
- 请求顺序为云端现配、本地 thinking、本地／云端第一对、云端／本地第二对、本地／云端第三对。请求串行、SDK 自动重试为 0。计时从客户端发起到流结束；首字指首个非空最终回答片段，不把 thinking 或空元数据帧当作回答。
- 终端代理变量为当前 HTTPX 不支持的 SOCKS URL，最初客户端初始化失败、未发送模型请求；正式对照两端均使用 `trust_env=False` 直连。这个网络路径不一定等同其他机器或运行服务的代理路径。

## 2. 实际结果

| 条件 | 首个最终回答片段 | 完整响应 | 输出与结束情况 |
| --- | --- | --- | --- |
| 首次本地原图识别，thinking 开启，非流式 | 未测 | 31.33 秒 | 820 completion tokens，正常结束；该数量包含思考输出 |
| 本地 thinking 流式重测 | 9.05 秒 | 15.62 秒 | 首段 thinking 1.58 秒，714 completion tokens，正常结束 |
| 云端现有 400-token 配置 | 31.90 秒 | 42.22 秒 | 400 tokens，`finish_reason=length`，末尾停在未完成描述 |
| 本地非思考，第 1／2／3 轮 | 1.74／1.56／1.56 秒 | 5.14／5.11／5.10 秒 | 各 197 tokens，均正常结束 |
| 云端非思考，第 1／2／3 轮 | 39.83／84.15／21.77 秒 | 53.23／135.20／38.72 秒 | 840／833／874 tokens，均正常结束 |

同图非思考对照中，本地完整响应中位数 **5.11 秒**、首字中位数 **1.56 秒**；云端分别 **53.23 秒、39.83 秒**。这组端到端时间没有显示本地比云端慢，云端本次波动明显，不能推广为长期服务性能排名。

两端虽然输入字节相同，服务端处理量并不相同：本地报告 12345 prompt tokens，云端 2548，其中云端图像 tokens 为 2496。分词、图像预处理与后端实现不同，不能把 token 数或生成速度直接当作同等计算量比较。

云端非思考回答为 1274／1286／1332 字符，本地每次为 340 字符。云端拆分项目、描述细节与不确定性更多，但也出现“100%”字样和具体充电器型号的表述；本地描述更短。这里仅保留模型输出差异，没有逐物体人工标注评分，不能据此宣称云端更准，或关闭本地 thinking 完全无损。

## 3. 解释与限制

- 本地 thinking 重测在约 1.58 秒开始返回思考，直到约 9.05 秒才有最终答案；思考确实占用等待时间。但首次 31.33 秒与本轮 15.62 秒还有缓存状态、生成内容、共享 GPU 负载及流式方式的差异，不能把差值全部归因于 thinking。
- 多次使用同一图片，未清理本地前缀或图像缓存；本轮非思考时间属于重复同图测量，不是全新图片冷启动保证。实验期间 GPU 可能与导航仿真共享，没有隔离其他进程。
- 云端首字延迟包含网络上传、服务端排队、视觉编码和预填充等，未获取内部追踪，无法精确拆分。一次同域名未认证 `/models` 小请求约 1.54 秒返回 401，只说明该次基础连接可达，不能据此排除大图上传的网络影响。
- 云端现有 400-token 上限在本题造成截断；加到 2048 后三次均正常结束，但这不是已应用的生产配置变更。
- 所有非思考设置仅对单次对照请求生效。本地默认仍开启 thinking，云端项目配置仍为原值；未量化、重启或切换模型服务。

## 5. 同日追加：大脑 LLM 与视觉 VLM 分开实测

- 文字组：三道不同的合成 SOP 判断题，两端各调用一次。覆盖“已受理但没有完成反馈，查询原命令而非重新派发”“阴性结果属于其他事务，不能放行”“交接区遮挡且缺少到位反馈，交接未知且不推进”。预先定义关键字段期望值，要求简短 JSON。没有实际建立或推进任务。

## 6. 后续只读网络核对与“直连”措辞修正

后续检查发现，两个 API 域名均解析到本机使用的 198.18 地址，`ip route get` 均指向 `Mihomo` 接口及路由表 2022。因此，本文前述 `trust_env=False` 的“直连”只代表忽略应用层代理变量，**没有绕过系统 TUN**；实际代理节点及分流规则尚未核对，不把经过 TUN 等同于必然使用海外代理。

无凭据小请求分别约为：视觉端点 0.99 秒、大脑端点 0.41 秒；显式使用本机 HTTP 代理后分别约 0.93 秒、0.41 秒。这不能代表大图片上传速度。现有证据仍是图片请求体发送阶段显著阻塞，尚未通过真正不同的网络路径隔离根因。本次没有改动系统代理或路由。
