# 接口说明：天机导航接入大脑

更新日期：2026-11-10。状态：**大脑原子调用接口与离线工具已实现；天机兼容服务待实施、待双方联调与真机验收**。

本文是交给天机／灵猴 S100 导航维护方的接口改造要求。以本项目当前宇树 G1 导航合同为基线，保持大脑发送的请求字段、坐标格式、命令身份及查询方式不变。这里的“G1 规范”指本项目使用的业务合同，不是宇树厂商通用标准。

天机现状依据对方提供的《天机与灵猴_导航API与大脑对接说明_20261110.txt》，尚未登录远端核实源码和运行实例。大脑侧本次仅新增独立原子技能和测试入口，未接入 Planner／接待流程，未重启服务或改变现场运行配置。

**这是一份可单独交接的文档。**天机负责人只需本文及第 11 节的大脑服务器访问权限，即可查看代码、运行自检并连接自己的隔离导航服务。正文给出完整调用合同与案例，文末仓库链接只作为维护参考，不是理解或执行测试的前置资料。

**给天机导航负责人及其 AI：本次交接包含适配完成后的文档回写要求，必须阅读第 14 节。**适配、后续接口更新与测试结果均回写大脑服务器上的本文件；不能只修改天机本地副本或在聊天中报告完成。

## 1. 改造目标与职责

```text
大脑 Runtime 编排业务、保存 task_id / command_id
    → 天机兼容接口接收一次坐标目标
    → 原导航任务管理、定位、规划、执行及停止
    → 按原 command_id 查询真实进度和结果
    → 大脑核验后决定下一步
```

- 大脑决定去哪里、何时执行下一步；天机导航不自动触发抓取、投放或后续导航。
- 天机侧在原服务及任务管理中增加兼容入口，复用现有导航核心、心跳、互斥、持久化和停止机制，不另起任务执行循环。
- 大脑不需要使用天机专用 SDK、逐帧发速度或续租，也不依赖 GUI 常驻。
- 天机保留本机定位、碰撞、姿态及运动准入检查。G1 的 SONIC 选源机制不照搬到天机。
- 大脑的 `TianjiNavigationSkill` 原子接口已提供独立的提交、执行等待、查询、取消和元数据检查；复用 G1 的 `DreamClient`、Runner、Verifier。调用者保存原请求及任务／尝试身份，技能本身不另建业务账本。
- 该技能未注册到 Planner 或接待流程。多机器人流程选择、Runtime 任务绑定和操控交接仍待后续接入，不代表只换 IP 就已支持两台机器人。

本文件完整规定本次天机接口。仓库内通用 NAV 合同仍在导航 NAV 文档维护；外部交接不需要取得其他文档。大脑 Runtime 仍是正式业务任务的唯一状态权威，本次原子测试不创建或接管正式业务任务。

## 2. 现有差异与修改清单

| 项目 | 天机说明中的现状 | 本次要求 |
| --- | --- | --- |
| 目标输入 | `goal=1/2/3`，按场景选择编号 | 新增直接接收 `map` 坐标目标的执行能力 |
| 提交 | `POST /v1/navigation/tasks` | 提供 `POST /v1/navigation/goals` 兼容入口 |
| 查询身份 | 服务生成内部任务 ID | 对外使用大脑原 `command_id`，内部 ID 保留关联 |
| 幂等 | 请求头 `Idempotency-Key` | 直接使用请求中的命令身份实现幂等，大脑不增加必填请求头 |
| 坐标系 | 点位说明使用 `session_base_start` | 明确对外 `map` 及内部转换依据 |
| 成功结果 | `SUCCEEDED`、`result.arrived` | 返回 `succeeded`、`success/reached/navigation_stopped` 等兼容字段 |
| 取消 | 按内部任务 ID 取消 | 接收大脑 `task_id + command_id` 并取消对应原任务 |
| 健康／状态 | `/healthz`、`capabilities/readiness` | 补齐 `/health`、`/v1/status` 及世界元数据入口 |
| 运动模式 | 说明记录 `motion_enabled=false` | 如实展示并明确拒绝运动请求；实际启用另行安排 |

不能只把收到的坐标匹配到最近的 1/2/3 号点后执行。原编号接口可保留为调试入口，但本次交付必须能让原规划、执行链路接受指定坐标目标。

## 3. HTTP 接口

请求和响应使用 JSON，业务接口沿用 `Authorization: Bearer <token>`。IP、端口和令牌通过部署配置确定，公开文档不写真实凭据。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 服务健康；不表示允许运动 |
| GET | `/v1/status` | 当前运动就绪、阻塞原因与活动命令 |
| GET | `/v1/world` | 对外坐标系、地图和关系图入口 |
| GET | `/total_scene_graph_latest.json` | 场景目标与导航能力声明 |
| POST | `/v1/navigation/goals` | 提交一次坐标导航 |
| GET | `/v1/commands/{command_id}` | 查询原导航命令 |
| POST | `/v1/navigation/cancel` | 取消指定原命令 |

`/map.yaml`、`/map.pgm` 按 NAV 通用合同作为可选地图资源；只有实际提供的资源才发布 URL。现有规划、事件、测试及原始日志接口可继续保留用于排障，不成为大脑提交导航的必需调用步骤。

## 4. 导航请求与坐标

`POST /v1/navigation/goals`，以下坐标仅为报文示例，不是真机执行点位：

```json
{
  "contract_version": "fq/reception-lan/v1",
  "task_id": "reception-demo-001",
  "command_id": "nav-table-001",
  "target_id": "work_table",
  "route_phase": "",
  "leg_index": 1,
  "frame_id": "map",
  "goal_xyt": [1.2, -0.8, 1.57],
  "motion_mode": "forward_path",
  "require_final_orientation": true
}
```

| 字段 | 大脑当前发送方式及天机处理要求 |
| --- | --- |
| `contract_version` | 固定为 `fq/reception-lan/v1` |
| `task_id` | 整轮业务任务身份，原样保存、回传 |
| `command_id` | 一次导航尝试身份，提交、查询、取消共用 |
| `target_id` | 业务目标标识，原样保存、回传；实际目标由坐标指定 |
| `route_phase` | 业务路段，可为空；原样保存、回传 |
| `leg_index` | 正整数段序，原样保存、回传；不硬编码成 G1 接待路线 |
| `frame_id` | 固定为 `map` |
| `goal_xyt` | 三个有限数 `[x, y, yaw]`，单位米、米、弧度 |
| `motion_mode` | 当前大脑使用 `forward_path` 或 `lateral_path_aligned` |
| `require_final_orientation` | 当前大脑显式发送 `true`，必须核验最终朝向 |

不得新增必填的 `goal` 编号、`scene`、速度、内部任务 ID 或 SDK 参数。场景、限速及内部转换依据由执行端现有配置确定并在受理时绑定；不能要求大脑改变当前报文。

运动模式须按 NAV 语义执行。特别是 `lateral_path_aligned`，不能仅因底盘支持某种平移就声明兼容；不能保持所需身体朝向或不支持请求模式时，返回 `INVALID_MOTION_MODE`，不得静默改用普通导航。

### 4.1 对外 map 的定义

- 明确天机地图原点、轴向、yaw 正方向、地图版本及可用范围。
- 内部使用 `session_base_start` 等坐标系时，由天机侧完成受控转换。不能仅把字段名称改为 `map`，也不能每接一条任务都将当前位置重新设为地图原点。
- 转换与该命令的地图、定位依据绑定；不可用时等待或明确拒绝，不盲目执行。
- `result.final_xyt` 必须转换回请求使用的同一对外坐标系。
- 格式与单位保持不变，天机目标坐标值按天机地图标定；不直接复制 G1 地图中的坐标值。
- 提供桌面、垃圾桶、让行点等业务点位的坐标及语义，最终点位与流程由双方确认，不在接口层硬编码业务顺序。

## 5. 身份、受理与幂等

在原有任务记录中持久化关联以下信息，不另建平行任务账本：

```text
大脑 task_id / command_id / 原始请求
    ↔ 天机内部任务 ID / 请求幂等身份 / 目标与地图快照 / 结果
```

1. 同一 `command_id`、相同请求返回原事务，不重复导航；同 ID 不同请求返回 HTTP 409 `COMMAND_ID_CONFLICT`，不得覆盖旧记录。
2. 对外查询以 `command_id` 定位，不要求大脑先拿到天机内部任务 ID。内部 ID 可作为附加诊断字段保留。
3. HTTP 接受回执发出前，命令及身份关联已持久化，并可通过原命令 GET 查询。天机可内部生成幂等键，大脑不另传 `Idempotency-Key`。
4. GET 查询只读取原任务，不规划、不补发、不创建新任务。POST 回包丢失后，大脑默认查询原命令，不能要求必须再次 POST 才能找回任务。
5. 网络断开或大脑等待超时不自动取消执行。服务重启不自动重放旧动作，保留中断、停止已确认或未确认的真实结果。
6. 同命令网络重传与失败后的新尝试分开：前者沿用原 ID，后者经大脑授权使用新 ID，旧结果保留。
7. 大脑串行派发。最小实现可在忙碌时返回 HTTP 409 `NAVIGATION_BUSY`，不新增自动队列；如支持替换目标，先确认原目标取消与停止。
8. 命令结果至少保留通用 NAV 合同要求的一小时，并明确跨服务重启、运行目录变更及清理后的查询边界。身份映射与结果必须共同保留；不能把查不到解释为动作未执行。

接受示例，HTTP 202 仅表示受理：

```json
{
  "contract_version": "fq/reception-lan/v1",
  "accepted": true,
  "task_id": "reception-demo-001",
  "command_id": "nav-table-001",
  "target_id": "work_table",
  "state": "accepted",
  "status_url": "/v1/commands/nav-table-001",
  "accepted_at": "2026-11-10T16:00:00+08:00"
}
```

## 6. 状态与结果

`GET /v1/commands/{command_id}` 返回原命令状态。所有状态均回传原 `contract_version`、`task_id`、`command_id`、`target_id`、`route_phase`、`leg_index`，不能遗漏空字符串或改变段序。

| 天机原状态 | 对外映射要求 |
| --- | --- |
| `ACCEPTED` | `accepted` |
| `STARTING`、`PLANNING` | `planning`，原阶段保存在 `progress` |
| `WAITING` | `waiting_safety_ready`；确实为人工审核时可用 `waiting_operator_approval`，保留真实原因 |
| `RUNNING` | `navigating` |
| `CANCELING` | `cancelling`，非终态，继续查询 |
| `SUCCEEDED` | 全部完成判据满足后才返回 `succeeded` |
| `FAILED` | `failed`，保存原始错误 |
| `CANCELED` | `cancelled`，停止事实另行核对 |
| `INTERRUPTED` | `failed`，保留中断原因，停止未核清时不得填写已停止 |
| `PLAN_READY`、`TEST_COMPLETE` | 保留于原规划／测试接口，不映射为真实导航成功 |

只使用 `succeeded / failed / cancelled` 作为兼容导航终态。其他执行阶段不要求机械地逐个经过。

命令包含 `accepted_at`、`started_at`、`completed_at`，使用带时区的 ISO 8601。未开始／未结束时对应时间为 `null`；`started_at` 不单独证明身体已经运动。非终态允许 `result=null`，并通过 `progress.message`、原始原因等解释等待与执行阶段。

### 6.1 成功回包

以下时间和坐标同样仅为格式示例：

```json
{
  "contract_version": "fq/reception-lan/v1",
  "task_id": "reception-demo-001",
  "command_id": "nav-table-001",
  "target_id": "work_table",
  "route_phase": "",
  "leg_index": 1,
  "state": "succeeded",
  "accepted_at": "2026-11-10T16:00:00+08:00",
  "started_at": "2026-11-10T16:00:01+08:00",
  "completed_at": "2026-11-10T16:00:20+08:00",
  "result": {
    "success": true,
    "reached": true,
    "navigation_stopped": true,
    "final_xyt": [1.2, -0.8, 1.57],
    "message": "目标已到达，导航停止已确认"
  }
}
```

大脑通过条件为：身份匹配、有效带时区完成时间，并且 `state=succeeded`、`result.success=true`、`result.reached=true`、`result.navigation_stopped=true` 同时成立。

天机说明中既有的 ARRIVED、`finished=true`、`cleanup_pending=false`、进程正常退出、距离误差不超过 0.05m、朝向误差不超过 1°及稳定检查应保留，不能因接口适配放宽。大脑当前不根据 `final_xyt` 独立重算误差，因此到位、朝向和停止判据由天机执行端负责。

`navigation_stopped` 必须有真实导航停止依据。进程退出、取消完成或租约过期本身不能单独替代确认，也不证明双臂、全身均停稳或所有控制资源已释放。失败／取消时仍分别填写真实的 `reached` 与停止事实；停止未核清不填 `true`，并保存原因和证据来源。

## 7. 取消与迟到结果

`POST /v1/navigation/cancel` 请求：

```json
{
  "task_id": "reception-demo-001",
  "command_id": "nav-table-001",
  "reason": "operator_cancelled"
}
```

- 校验任务、命令关联，只取消对应原任务，不取消其他命令。重复取消应幂等。
- 返回 200／202 只说明处理／受理情况；继续通过原命令 GET 核对终态和 `navigation_stopped`。
- 原命令已经成功时保留成功结果，不强行改成取消；失败或取消后的停止证据可补充，保留原错误与首次终态时间。
- 旧取消、旧进程收尾和迟到回包不能停止或覆盖新任务。不能以全局 stop 盲目代替按命令身份取消。
- 大脑整轮任务结束、导航命令结束和身体停止是不同事实，分别保存。

取消受理示例，HTTP 202：

```json
{
  "accepted": true,
  "task_id": "reception-demo-001",
  "command_id": "nav-table-001"
}
```

随后查询原命令：只有相符身份的终态及 `result.navigation_stopped=true` 才确认该导航已经停止。原子技能的取消返回 `completed=false`，不使用受理回包冒充停稳证明。

## 8. 错误返回与分类

受理前拒绝示例，HTTP 409：

```json
{
  "success": false,
  "error": {
    "code": "SAFETY_NOT_READY",
    "message": "导航运动模式未启用",
    "retryable": false,
    "details": {
      "task_id": "reception-demo-001",
      "command_id": "nav-table-001",
      "action_started": false,
      "action_state_uncertain": false,
      "original_code": "MOTION_DISABLED"
    }
  }
}
```

| 情况 | 对外返回要求 |
| --- | --- |
| 请求／版本／坐标错误 | 400／422，使用 `INVALID_REQUEST`、`UNSUPPORTED_CONTRACT_VERSION`、`INVALID_FRAME_ID`、`INVALID_GOAL_XYT` 等对应错误码 |
| 不支持请求运动模式 | 400／422 `INVALID_MOTION_MODE`，不得静默降级 |
| 运动关闭或执行准入不满足 | 409 `SAFETY_NOT_READY`，保留 `MOTION_DISABLED` 等原码与原因 |
| 已有活动命令 | 409 `NAVIGATION_BUSY`，有确切关联时提供对外 `active_command_id`；不伪造其他入口的命令身份 |
| 同 ID 不同请求 | 409 `COMMAND_ID_CONFLICT`，保留原事务 |
| 命令不可查 | 404 `COMMAND_NOT_FOUND`，不证明动作从未执行 |
| 受理后规划／执行失败 | 原命令 GET 返回 `failed`，保留具体错误、原规划结果引用与停止事实 |
| 通信异常／服务器错误 | 保留不确定性，不能伪装成受理前拒绝或成功 |

受理前拒绝回包不填写非空业务 `state`，也不填写 `accepted=true` 或 `started=true`。本次天机拒绝采用表中的校验／准入错误码，使用 400／409／422 等相符 HTTP 状态；忙碌拒绝需有与本请求不同的确切 `active_command_id`。身份字段若提供，必须与原请求一致。只在确有证据时填写两个“不曾开始／不确定性为否”的字段；任意新错误码不保证被现有大脑识别。

`COMMAND_ID_CONFLICT`、404、网络错误和 5xx 不证明原命令没有执行，大脑保留 UNKNOWN，不自动改 ID 补发。大脑本地派发开关关闭或元数据检查失败时返回 `TIANJI_DISPATCH_BLOCKED`，仅表示本次调用未 POST，不证明该命令在过去从未执行。

失败回包继续携带第 6 节全部命令身份及时间；`error` 保留 `code/message/retryable/details`，`result` 分别表达动作效果与停止。不能仅把所有失败压成“NO PATH”；保留 `NO_CHECKED_PLAN`、`PLANNING_PROCESS_FAILED`、起点碰撞、目标碰撞或搜索超时等原始原因及日志引用。

## 9. 状态与世界元数据

- `/health` 至少返回合同版本、服务标识、健康状态和接口在线情况，健康不代表运动获准。
- `/v1/status` 至少提供 `contract_version`、`interface_online`、`motion_ready`、`motion_blockers`、`active_command_id`、`active_command_state`；无活动命令时明确返回空值。就绪信息不能代替执行期间的实时准入。
- `/v1/world` 声明 `frame_id=map`、可用资源入口和更新时间；附带真实地图版本／哈希等诊断身份。
- 关系图中的目标标识与请求一致，提供真实业务点位。`agent_navigation_contract` 声明合同版本、坐标系、支持模式及参考路段，供当前大脑只读预检。
- 独立坐标目标能力实施完成后，能力声明使用 `goal_admission.strategy=independent_map_goal`，如实声明参考坐标和路段是否强制；不能先写能力已支持再等待实现。具体示例见下文。
- 运行时反馈相机净空强制放行、固定夹爪姿态等测试条件，不能描述为传感器实测通过。天机原文所列动态绕障、规划稳定性及移动操作限制不会因接口适配自动解除。
