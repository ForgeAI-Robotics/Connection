## 问题与闭环

### 查询、重试和停止的边界

2026-08-31 的抓取后导航控制未恢复，以及 2026-09-17 的导航启动人工闸门超时，分别保留端口／本体接管和现场启动事实。[B1](#e-b1)、[B2](#e-b2) 中的分析是当时线索，不是所有控制器版本通用的已确认根因。

后续控制机制以原任务、步骤、尝试和命令身份查询与核验。大脑任务结束、下游命令结束与机器人停止分开记录；网络异常、超时、查不到命令不能推断动作未执行。实际控制器实例、代次和接管凭证仍需相应执行端证据。

### 异常建议与失败后推进

2026-10-15 派发延迟记录中的一段等待约 94 秒。修复针对模型建议同步阻塞，增加阶段日志并允许原 Runtime 继续处理控制请求；建议依然绑定任务、命令和账本版本，迟到或失效建议不能推进新状态。

同日操控明确拒绝的修复使用原拒绝回包，而非查询一个未被接收的命令。它没有放宽未知命令处理，也不改变成功门限。以后复验这两项时，应分别覆盖明确拒绝、受理后失联、迟到结果和新旧尝试混淆。

## 待验证事项

- 真实控制器接管与停止保证：不能以 HTTP 可达、无活动命令或大脑终态代替本体确认。
- 人工物理介入如何进入验收表达：导航记录中已有用户报告拖动，但缺少完整结构化时间线，见[现场介入问题](多端联调_导航与定位.md#现场末端失败与人工介入)。
- 复验只覆盖对应版本和环境；未复验的现场问题保留为未闭环，不根据后续一次成功自动关闭。
