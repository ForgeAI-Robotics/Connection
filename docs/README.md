## 维护规则

### 更新哪一类

| 变化 | 维护位置 |
| --- | --- |
| 字段、功能、配置、错误、按钮或启动步骤变了 | 对应接口说明，即使只是小变化也同步更新 |
| 实际跑了一轮，出现问题、修复或完成复验 | 按真实日期新增或补充同一主题的多端联调 |
| 模块职责、调用方向、核心机制或扩展方向变了 | 系统架构与演进；涉及接口时同时更新接口说明 |

一类事实只留一个主位置，其他文档链接过去。接口说明不追加每轮调试流水；架构文档不复制完整 HTTP 表；联调保留当时的真实结果，后续修复另补日期，不回改旧失败为成功。无需为每次小改创建新的架构文档。

### 命名与内容

```text
接口说明_端或模块.md
多端联调_YYYYMMDD_主题.md
架构设计_系统架构与演进.md
```

不再新增独立规划说明、联调说明、案例排障、使用指南或“最终版”等平行类别，不增加子目录。日期未知时写明待确认，不用整理日期冒充实验日期。

- 接口说明写更新时间、用途、当前能力、调用或操作方式、成功判断、错误出口和限制；远端未验证部分注明基线日期。
- 多端联调写发生日期、环境与版本、任务及命令身份、过程、失败原文、归因依据、修复、复验结果和证据路径。明确哪些仅来自旧记录，哪些本次重新验证。
- 架构设计分清已实现、待验证、待实施；未完成项写依赖与完成标准，重要变化简要记录日期、理由、关联接口与联调。

代码可调用、下游自报成功、大脑核验通过、物理验收通过是不同事实。一次成功不等于稳定成功率；软件回归不等于真机验收。推断明确标注，不把 LLM 建议当作确定根因。

### 核准与收尾

当前行为首先对照代码、生效配置和接口响应，再看有日期的现场证据。发现不一致时修正主文档；历史记录只证明当时版本。任务控制详细语义以大脑接口为维护点；远端能力必须保留其验证范围。

修改后检查旧名称、链接与章节锚点，核对证据和日期，运行 Markdown 链接检查及 `git diff --check`。文档整理不需要为此重启服务或执行机器人动作；引用的历史测试数量必须标明当时结果。

公开文档不放密码、令牌、私人路径和实验数据原文；SSH 使用角色别名，部署路径用占位符。具体任务 ID、必要错误和本地证据相对路径可用于追溯，日志、轨迹及视频继续保留在 `data/` 等数据目录，不复制进 Docs。`data/memory` 的运行时经验不属于本目录分类。
