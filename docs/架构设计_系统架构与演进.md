更新日期：2026-10-20。范围为 Connection 大脑、独立入口、执行后端与学习模块的职责、设计理由和后续演进。当前结构按本仓库代码核对，现场通过范围按带日期的联调证据引用；本文不代表重新验收真机或改变部署配置。

本文合并原三端架构、重构前后对比和重构规划，作为唯一架构与演进主文档。接口字段、操作步骤在对应接口说明维护；验证结论、问题闭环与待验证项在对应模块的多端联调持续更新，日期标在正文。已过时的实施步骤、临时目录和迁移过程保留在 Git 历史，不再作为当前运行指南。

## 1. 当前架构

### 1.1 系统职责与调用方向

Connection 是任务级大脑，不直接控制电机。Runtime 是任务状态唯一权威；Planner 生成计划，业务包定义固定流程，Runner 执行既定步骤，Verifier 核验证据。

```mermaid
flowchart TD
    W[网页入口 8888] --> A[Brain API 5000]
    F[飞书入口] --> A
    Y[语音文本入口 8890] --> A
    X[外部 API] --> A
    A --> S[任务选择与业务包]
    S --> P[Planner / 固定步骤]
    P --> R[Runtime]
    R --> U[Runner]
    U --> B[执行与观察适配器]
    B --> D[DREAM / VLA 真机接口]
    B --> T[Desk / SIMPLE / 协议模拟]
    B --> G[Redis / Slaver / MuJoCo / 3DGS]
    B --> C[当前观察后端]
    B --> V[Verifier]
    V --> R
    R --> L[持久任务账本]
    L --> E[异步反思 / 候选评测 / 发布]
    E --> N[新任务规则快照]
    N --> R
    O[Ops 5678] -.服务管理与环境配置.-> A
```

| 模块或端 | 负责 | 边界 |
| --- | --- | --- |
| 网页、飞书、语音文本入口 | 接收输入、必要确认、转发与展示 | 各自直连大脑，不持有另一份业务任务账本 |
| Brain 应用层 | 组装模块、工作器生命周期、API 与快照 | 一个大脑进程管理有界后台工作器；慢模型和执行调用不应阻塞控制请求 |
| Runtime | 任务、步骤、尝试、状态、恢复与事实落账 | 只读状态查询不推进任务；旧任务迟到结果不能覆盖新任务 |
| Planner / 业务包 | 能力约束内规划；定义固定 SOP | 模型不向固定接待流程注入坐标、跳步或额外动作 |
| Runner / 适配器 | 请求构造、提交、原命令查询、证据转换 | 不自主更换目标或路线，不把网络异常当作已停止 |
| Verifier | PASS / FAIL / UNKNOWN | 下游声称成功仍需身份、时间和效果证据；缺证据不能升级为成功 |
| DREAM | 定位、审核、路径规划、导航准入及执行终态 | 不自动调用 VLA；大脑不绕过导航安全链 |
| VLA | 抓放、策略停止、动作通路归还及操控证据 | 不决定下一段导航，不启动第二个 LowCmd 控制器 |
| NX / SONIC | 本体控制、输入采纳、本地保护 | 端口可用不等于本体已接管，物理保护不能由任务恢复解除 |
| Ops | 服务启停、健康、日志、运行环境 | 不发布接待任务，不充当第二个任务调度器 |
| learning | 反思、示教候选、评测、影子、发布与回滚 | 不在线改内核代码，不改变已经打开任务的规则快照 |

DREAM/VLA 使用 `fq/reception-lan/v1`。真机层常见导航端口 8001、VLA 8091、审核页 9882；实际地址来自 `config/networks.yaml` 当前网络和有效覆盖，不在架构文档维护第二张固定 IP 表。真机侧策略、relay、相机和控制器的详细操作见[控制面板](接口说明_控制面板.md)、[导航](接口说明_导航NAV.md)和[操控](接口说明_操控VLA.md)。

### 1.2 业务与执行后端

接待、通用任务、现场观察、桌面整理及历史演示共用 Runtime。明确登记触发词直接选业务；其他表述由 LLM 按登记范围选择。超范围需求应澄清或拒绝，不能静默套入固定 SOP。

单罐接待为版本化 `reception.single_can`：v1 保留原四段导航，v2 使用新坐标并在抓取后增加 relay1；抓放及 relay3 横移保持。准备、可选检查、核验和交接节点由同一编译器展开。模型不能改写路线。`reception.single_can.nav_only` 仅由明确触发词选择，从同版本定义派生所有导航；成功只表示仅导航测试完成。

接待顺序与参数由随包封存的 YAML Skill 定义提供，`packages/reception_skill.py` 负责读取、校验并编译
为现有 `StepSpec`，不新增执行循环、账本或状态机。参数、导航点与抓放凭证关联属于定义；
物体效果证据、交接和安全收尾要求由编译器与现有 Verifier 保证，定义不能关闭。
Skill schema 1 保持原四段精确校验，schema 2 校验可配置坐标、连续段序、动作引用及门段约束。
LAN 请求格式保持 v1，真实执行端仍独立核准路线。旧协议模拟保持原四段准入；SIMPLE 按服务声明的完整路线与任务快照比对，
新版 O6 新房子物理回合增加独立 relay1 到达段，并可配置仅导航模式；所选 SOP 必须与健康声明的路线及模式一致，
不兼容的新定义在端口创建前拒绝。仅导航删除物理抓放步骤，完整接待仍保留原持物约束。新增参数不等于新增操控能力或远端部署。

业务选择在模型调用前读取并校验定义，正式接待把定义和内容摘要绑定到原任务的 `selection`；
Planner 使用该快照展开步骤，Runtime 持久保存每步的导航参数与凭证来源。文件变化只影响后续新任务，
恢复沿用原步骤和原命令。旧账本的缺省字段仅兼容原固定 v1，不重读新定义改写旧任务。
格式、配置与预览入口统一见[接待 Skill 定义](接口说明_大脑%20Brain.md#111-接待-skill-定义与任务快照)。

`INITIALIZING`、`FETCHING_WORLD` 仍为本地节点。明确接待触发词在真机后端的 `/api/task_preflight`
只读核对导航接口与 Skill 定义，不占用 Runtime 状态写入线程，不创建任务或下发动作。
固定合同冲突在提交前指出；独立目标模式非强制的参考点位差异仅提示，业务流程仍归大脑。
预检不是定位批准、运动许可或三端能力验收，继续旧任务仍按原快照及实际派发门检查。
页面的请求等待与过期标记只描述通信，命令阶段和可复制总结均派生自 Runtime 账本，不另建任务状态机。
具体字段、范围与边界见[大脑接口](接口说明_大脑%20Brain.md#81-流程与请求身份)。

| 后端 | 当前用途与限制 |
| --- | --- |
| 真机接待 | 大脑直连 DREAM / VLA；由实际派发许可和下游闸门决定准入，不能写死“当前始终关闭” |
| `reception_mock` | 历史接待演示，标记 `reception.demo`；不等于正式单罐 HTTP 接待 |
| `reception_protocol` | 独立 NAV/VLA 协议模拟，覆盖合同、异常和控制流程；不是物理运动证明 |
| `reception_simple` | SIMPLE O6 连续 MuJoCo 回合，复用接待客户端与核验；执行器可选旧房间或新办公室，验收按场景分别记录 |
| Desk | 通用抓放和整理的抽象状态后端，直接 HTTP，无实时相机 |
| `simple_o7` | SIMPLE O6 通用单步抓取，与 `reception_simple` 的连续接待能力区分 |
| MuJoCo / 3DGS | 既有通用工具路径继续经 Redis / Slaver；各自的运动与抓放真实性边界见联调记录 |
| 现场观察 | 使用显式选择的观察后端，不生成身体命令，不在后端不可用时自动换另一台相机 |

运行环境由全局模式加接待、通用执行、观察模块覆盖组成。草稿在 `config/execution.yaml`，生效快照在 `data/system/execution.json`；新任务绑定执行身份与环境版本，恢复附着原后端。切换需经过准入检查、健康核查、应用及失败回退，不能通过删除任务账本清除阻塞。未接入的通用真机能力明确不可用，不回落仿真。

混合接待变体绑定 `reception_real_sim_manipulation` 后端，从同一 Skill 快照展开完整流程，
由专用 BodyAdapter 组合真实导航客户端与本地操控模拟客户端。模拟端复用既有操控结果轮询与 Verifier，
只模拟抓放命令和结果，不新增任务调度循环或持久任务账本，不连接 VLA 或切换实体控制权。
已核验的模拟终态从 Runtime 账本恢复；缺失回执仍为 UNKNOWN。任务、节点、原始回执及交接记录明确标注模拟范围，
模拟持物状态不作为真实世界物体事实。边界和操作见[当前接待流程](接口说明_大脑%20Brain.md#81-流程与请求身份)。

同一模拟操控组件可与原导航项目的隔离 O6 仿真组合，使用独立
`reception_ros_sim_manipulation` 任务身份；准入校验要求原 ROS 桥接场景声明和匹配路线，
不与固定路点执行器或真机模式混用。

## 2. 核心机制与设计理由

### 2.1 任务、命令与恢复

任务表示整轮目标，步骤表示流程中的环节，尝试记录一次执行，`command_id` 标识下游事务。保留这几个层级是为了区分“查询旧动作”和“再做一次动作”，避免超时、丢回包或重启造成重复抓放。

- 查询必须使用原命令；404、HTTP 500、连接断开本身均不能证明动作未执行。
- 可识别的提交拒绝与不确定提交分开保存；原命令已成功时先核验，不能因为用户点继续就重复动作。
- 新尝试须按当前控制规则确认原动作未开始或已结束，并保留旧请求和失败记录；重试用新的命令号。
- 暂停保留流程并请求停止当前动作；继续核查当前环节；跳过保留人工放弃记录。含跳过的流程结束不记全部成功。
- 跳过的停止证据区分已创建的执行命令与明确提交拒绝。后者复用原始、身份匹配的拒绝回执；仍核查此前实际命令，不将“请求已发出”当成“下游已创建动作”。
- **取消任务只结束大脑编排与本地等待，不调用导航或操控取消接口，不声明本体已停。** 导航重启及现场停止独立处理。进程退出也不是物理停止证明。
- 取消关闭派发并隔离旧作业结果，避免迟到规划、执行或反思污染新任务。只读查询不增加重试次数。

此处解释机制，接口参数、可操作状态和详细判据以[大脑控制接口](接口说明_大脑%20Brain.md#12-任务控制接口)为唯一维护点。

### 2.2 核验与跨端交接

效果达成、原策略停止、动作出口归还、本体采纳新控制源是四件不同的事。手闭合不等于抓住物体，TCP 端口空闲不等于 NX 已接管。Verifier 检查身份、带时区时间、效果及停止证据；`hand_state_only` 不能让物体抓放通过。

Desk 的通用计划在任何动作派发前逐项核对单动作语义，拒绝把抓取、放置合并的步骤截断为其中一个动作。
这防止“某一步效果通过”被错误地用于表示模型原计划中遗漏的动作也已完成；规则与复验见
[大脑接口](接口说明_大脑%20Brain.md#11-共用任务选择与异常建议)和 [Qwen 本地测评](多端联调_模型接入与评测.md#e-m2)。

当前大脑普通交接先查询原命令、导航和操控状态；无控制器凭证时，可以按原命令成功且已停、资源已释放、两侧无活动命令及通路就绪放行，记录 `transport_ready_without_receipt`。如果下游返回凭证，仍核查身份与有效期。跨越人工跳过的交接有显式例外，记录 `manual_skip`，不把原失败命令伪造成成功，下一端仍可按自身前置条件拒绝。具体实现与最终收尾见[大脑交接规则](接口说明_大脑%20Brain.md#83-控制交接与人工跳过)。

这些联调放行规则不等于真实控制器接管协议已经验收。不得将现有通路证据写成来源、代次、控制器实例均已被本体确认。5556 单发布者、现场定位批准、操控批准及本体保护继续属于对应端职责。

### 2.3 记忆、模型建议与学习

短时窗口只裁剪读取视图，默认最近 20 条、30 分钟；不删除事件账本或未核清命令。PASS 建立的进展保留来源，不随短时窗口过期；其他观测须带来源、观测时间和有效期。过期观测降为线索，冲突保留双方证据，不能拼成确定位置。实现见 `kernel/memory.py`。

模型参与通用规划、范围受限的业务选择及异常建议。异常建议绑定原任务、命令与账本版本，`automatic=false`；迟到或无效建议不能执行控制，格式非法时回退规则建议。默认网页显示中文原因与原始英文错误；当前版本可按配置展示建议并确认一次受限操作，详见第 3.1 节。LLM 分析不作为确定根因；API 保留 `recovery_advice`。

正式大脑的入口分流／闲聊及后台反思也使用大脑主模型配置，避免更换规划模型后仍隐式依赖旧服务。
视觉核验保持独立模型配置。供应商切换不改变 Runtime 权威、已绑定计划或执行合同；字段与生效方式见大脑接口说明。

2026-10-20 本地图片后端接入补齐：视觉适配器共享请求选项构造，端点仍由既有的
`camera.vlm` 与 `reception_real.verification.vlm` 分别维护，不增加第二套配置来源。
图片模型与文字裁决继续分开，免鉴权须显式配置；异常或无有效视觉结论不得冒充正常。
共享选项层不持有任务状态、不下发动作，实际切换及尚未验证范围见
[本地图像 API 替换](多端联调_模型接入与评测.md#e-m6)。

反思读取执行快照，在在线执行闭环之外生成经验。保存反思文件不等于经验已生效：可归因的失败模板进入候选，经过离线评测和不派发动作的影子验证，才允许发布。单次首次成功、人工完成或同一步重试不能冒充自主改进证据。发布合并原活动规则并保留 `parent_id`，回滚沿父版本；新任务绑定快照，旧任务不随发布变化。

当前实现是有限规则和场景的学习切片，不代表通用自主学习、自动修代码或自动物理重试。相关代码为 `learning/reflection.py`、`releases.py` 和 `kernel/verifier.py`；示教保存也只进入候选。后台反思是否启用由配置和任务设置决定，不用文件是否存在推断本轮实际收益。

### 2.4 为什么保持这些工程边界

独立入口便于故障隔离，网页关闭后大脑仍可处理已接受任务；核心使用一个进程及受管理工作器，避免多个服务争写同一任务。Redis 只为仍依赖它的 Slaver 路径保留，不能为了统一目录删除执行底座，也不需要为此新增消息总线或工作流平台。

接口、账本与实际动作以任务和命令关联。日志是诊断证据，不是状态权威；查询和监测不自动推进任务。后端可替换，但不能通过降低核验标准“统一”真机与仿真。每次环境切换、部署和恢复都需区分进程在线、协议可用和物理动作通过。

### 3.1 第二阶段：LLM 异常建议与人工确认（已实现）

2026-10-12 确定本阶段目标：固定接待 SOP 正常运行；出现异常或等待人工时，LLM 根据原任务证据提出受限建议，
网页展示依据，用户确认后由同一个 Runtime 执行并核验。确认仅授权本次操作，不自动改 Skill、提示词或长期规则。
本阶段先在独立 worktree 实现与验证，随后按用户授权应用到真实项目并启用。公开模板默认关闭 `brain.reasoning.confirm_recovery_advice`；本机开关与已运行版本的证据见本轮联调。

**现有基础与缺口。** `brain/reasoning.py` 已按允许动作产生建议；`service.py` 在流程阻塞后发起分析；
`kernel/runtime.py` 保存 `recovery_advice`，并丢弃过期模型结果。现有状态接口提供建议和 `applicable`。
本阶段补齐网页呈现、确认身份与一次授权的记录，以及建议操作到原 Runtime 控制的连接；不另建决策服务或任务账本。

**本阶段范围。** 先覆盖接待及仅导航变体的 `waiting_human`、`recovery_required` 和需要分析的暂停状态。
正常成功节点仍按冻结的 Skill 推进；明确暂停、继续、跳过、取消保持现有入口与语义，暂停不等待模型。
本阶段不包含自然语言重新绑定取放参数、多流程组合、观察能力扩展、自动重试或自动固化处理经验。
这些属于后续独立验收项，不因模型提出建议而视为已经接入。

建议的动作边界如下；已实现的确认 API 与配置见[大脑接口](接口说明_大脑%20Brain.md#112-异常建议的人工确认)：

| 建议 | 用户看到的操作 | 允许产生的效果 |
| --- | --- | --- |
| `query_original` | 查询原命令结果 | 只查询并记录原命令证据；不生成新尝试、不自动派发下一步。确认完成后仍经核验，后续推进需另行确认 |
| `continue` | 继续当前环节（可能重试） | 复用现有继续语义，重查原命令、停止与资源；原动作已成功则核验，确认未完成才允许新尝试，前置条件仍生效 |
| `cancel` | 结束本轮任务 | 复用任务取消，只结束大脑编排；明确不等于机器人停止 |
| `wait` / `request_help` | 等待／查看人工处理说明 | 展示和记录处理意见，不伪造动作回执，也不自动联系外部人员 |

不把跳过、改坐标、改路线、任意工具调用加入模型可选动作。既有人工跳过按钮独立保留。
`Runtime.requery()` 可能更新任务状态，因此建议查询使用 `query_advice_original()` 只保存同一原命令的证据，
不调用 `continue_current()` 或核验推进。模型只能从程序根据当前证据计算的动作集合中选择。

**已实现路径与约束。**

1. 完成服务端建议合同与确认约束。扩展现有建议记录，关联建议身份、任务、控制步骤、尝试、原命令、
   账本版本和执行环境；程序提供可引用的事实摘要，模型输出建议及理由。模型超时、格式错误或越权时，
   明确显示规则回退来源，不能冒充 LLM 判断。
2. 在现有 Brain 应用层和 Runtime 上增加建议确认能力。客户端只提交建议身份与其所见任务上下文，
   不提交任意执行参数。服务端在现有任务串行化和互斥机制内检查建议仍适用，并持久化本次确认。
   任务或命令变更、建议失效、重复点击、确认与取消并发都不能重复派发；确认后崩溃或断网也不能重放动作。
   原有命令查询与新尝试身份继续保留，外层建议确认不能绕过下游停止及资源核查。
3. 网页增加“异常处理建议”区域，展示当前环节、已确认事实与未知项、LLM 建议和理由、具体操作按钮、
   处理回执及核验结果。区分建议生成中、待确认、已失效、处理中、被拒绝和处理完成；点击受理不能显示为动作成功。
   刷新页面只读状态；过期建议不可执行，服务端仍作最终校验。模型文字按纯文本展示。
4. 隔离测试覆盖身份、并发、迟到结果、规则回退和网页展示；接口说明维护当前能力；应用和环境切换单独记录。

建议确认记录作为原 Runtime 账本／事件的补充，关联到由既有控制逻辑创建的尝试和最终结果；
不以网页按钮状态、日志文字或 LLM 描述替代 Runtime 状态。正式应用的异常建议使用独立有界工作器，
不在 Runtime 所属线程同步等待，也不占用新任务规划工作器；继续／跳过后的驱动无需等待模型分析。
最多一个分析在执行和一个最新上下文待处理，结果以控制队列回到原 Runtime 进行任务、版本、状态和命令校验；
后台线程不写账本、不下发动作。关闭期间不投递迟到结果，重启不重放分析动作。
这是旁路分析的调度修正，不新增任务执行循环或状态权威。

**完成标准。**

- 导航失败且停止、资源已核清：产生受限建议；未确认时零新增命令，确认后最多授权一次继续处理，保留原失败。
- 回包超时、404 或停止未知：不推荐直接重发；查询保持原命令身份；查询得到成功后不能重新执行该动作。
- 旧建议、旧任务、旧步骤、迟到模型输出、双击、并发确认和暂停／取消：拒绝或返回同一处理回执，不误操作新任务。
- 模型不可用、越权输出及不可信回包内容：保留事实与错误，规则回退可识别；原有任务控制仍可用。
- 重启或确认响应丢失：不自动再次执行已批准的动作；核对原任务、命令和确认记录后再处理。
- 网页能完整追踪“证据 → 建议 → 人工确认 → 执行／拒绝 → 核验”，并明确只有本次授权，没有修改长期规则。
- 既有接待、仅导航、任务控制和迟到结果测试通过；完整离线回归使用 `venv/core/bin/python scripts/run_tests.py`。
  物理复验仍使用 SIMPLE O6 新房子，单独记录每次建议、确认、原命令和最终结果；离线假服务不冒充物理验收。

**验证状态。** 已完成隔离离线回归及 O6 新房子仅导航物理复验。真实模型本轮提出人工处理建议，
确认后由测试脚本模拟人工评估并选择既有继续操作，没有自主重试。
隔离验收后已应用真实项目，正式服务再次完成 O6 导航 7/7 并回切真机；实体动作仍待联调。详细计数、代理失败、模型输出、确认与核验边界见[隔离复验](多端联调_大脑任务与恢复.md#e-b4)与[正式项目应用复验](多端联调_大脑任务与恢复.md#e-b4)。

**实施与应用。** 开发阶段使用独立 worktree、配置和临时账本，未影响现场实例。隔离验收后，
按用户明确授权更新真实项目、启用功能并通过正式面板重启大脑／网页，切换到 SIMPLE O6 验证。
应用与回切须核对任务终态、下游命令及生效环境；源码修改和进程生效仍是不同事实。
