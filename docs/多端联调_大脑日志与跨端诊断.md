### 3.1 最小诊断约定 v1（本轮实施范围）

1. **业务身份不变。** 原 task_id／command_id 继续为任务主线；人工重试沿 Runtime 新尝试规则，查询保留被查询命令身份；大脑 control_id 与网关 request_id 各自保留。
2. **trace_id 表示一次入口请求或后台操作链，call_id 表示一次实际出站调用。** 同链显式传递上下文，每次 HTTP 查询有自己的 call_id，并关联原命令／请求。后续人工查询可以有新 trace_id，仍通过业务身份串起原任务；重启观察使用新实例／新调用身份，不伪造旧上下文。禁止依赖进程全局“当前任务”推断后台归属。
3. **本轮不新增诊断 HTTP 头。** trace_id／call_id 仅在各自本端使用，跨端靠原业务 ID 及明确关联记录。业务 body、request_digest、签名和幂等键保持原样；后续如扩展头部，先冻结名字、限制与信任边界并做兼容测试，不通过真实动作试探。
4. **统一记录允许原生日志映射。** 本轮公共字段包括 log_schema_version、event_id、time、service、component、level、service_instance_id、code_revision、event 及已知业务身份；未知身份保持缺失。各端无需同时更换日志格式；人工摘要与结构化记录用同一 event_id 关联。
5. **本端观察与对端事实分开。** 事件 time 是本端记录时间；对端 observed_at／completed_at 等在原回包路径保留，不提升为统一语义。VLA 顶层 observed_at 会随查询刷新，completion.evidence.observed_at 才是原效果观察时间。不同机器单调时钟不可直接相减；墙钟差未经校准不标为网络延迟；不得将每次 GET 当前时间填成原 completed_at。
6. **关键证据变化必须可见。** 同状态下停止／释放／效果／故障详情变化也产生记录，相同轮询累计次数并低频汇总。完整脱敏证据保留引用；超大内容明确截断或存附件；附件缺失、写入失败及事件丢失可辨认。
7. **诊断包仅包含已取得证据。** 对端日志不可访问时列出缺项、主机角色和查询键，不声称已收齐。日志与跟踪头不能充当授权、动作成功或 Runtime 状态权威。

### 3.2 实施分工

大脑沿现有模块完成回包证据投影、诊断写入隔离、后台异常、等待耗时、脱敏和本地检索；NAV、VLA、网关分别增强本端记录与只读提取。三端原生事件不要求使用相同日志文件名，由大脑导入时保留服务和来源映射。网关只输出选源事实，不承担 NAV／VLA 根因分析或新增机器人状态检查。

### 10.2 日常查询、导出与 E01 关联

面板新增“诊断查询”区域，使用现有主日志窗口之外的只读查询；参数、429 并发限制见[面板接口](接口说明_控制面板.md#diagnostic-query)。默认实时日志刷新保持。页面“导出本次结果”下载已显示快照，改条件后的迟到响应不能覆盖新条件。

在 Connection 仓库内执行下列命令仅查询已有本机文件。示例身份为占位符，需替换；对端文件须事先取得并保存为脱敏 JSONL，不能把 URL 当成本机文件。

```bash
# 查大脑已有任务记录；日期可省略，未命中不证明任务没有执行。
venv/core/bin/python scripts/brain_diagnostics.py --task-id TASK_ID --date-from 2026-11-02 --limit 500

# 按原命令或选源请求定位。
venv/core/bin/python scripts/brain_diagnostics.py --command-id COMMAND_ID
venv/core/bin/python scripts/brain_diagnostics.py --request-id REQUEST_ID

# 合并显式提供的对端事件和录制清单；不会连接远端或读取 bag 内容。
venv/core/bin/python scripts/brain_diagnostics.py --task-id TASK_ID \
  --peer-events nav=/tmp/nav-events.jsonl \
  --peer-events vla=/tmp/vla-events.jsonl \
  --peer-events gateway=/tmp/gateway-events.jsonl \
  --attachment /tmp/session-manifest.json > /tmp/brain-diagnostics.json
```

诊断包 schema 为 `fq/brain-diagnostics/v1`。`records` 保存原事件及来源文件／字节偏移，`service_instances` 和 `identity_links` 辅助关联；`coverage`、`peer_evidence`、`missing_evidence` 明确扫描和证据范围。单次最多 128 文件、16 MiB 扫描字节、50,000 条扫描记录、2,000 条返回记录、4 MiB 记录结果；另有目录项、关联键和附件预算，以响应及源码常量为准。

按 task_id 查询时，可从本机 master 的 TASK/runtime 与 GATEWAY 已保存意图／核对事件建立显式关联，将只有 command_id／request_id 的对端记录纳入结果。对端原生身份不改写，补充关联单列为 correlation，并附来源 event_id／位置。任务、命令、接收实例冲突，关联多义或本机扫描不完整时，不猜测填充。窄日期范围可能排除早期关联，需扩大范围重查。时间归一到 UTC 排序只方便阅读，不证明跨机因果或网络耗时。

E01 接受原生 `g1/rosbag-evidence-manifest/v1` 和通用 `fq/diagnostic-attachment/v1` JSON 清单。保留会话路径、主机／boot、起止时间、本机单调时间、可空录制状态、bag 话题统计和文件字节等元数据，**不打开清单引用文件、不启动或停止录制**。网关 snapshot_consistent 只表示其清单快照语义；大脑导入仍标为 metadata_only_unverified，不能据此证明文件可读、无丢帧或动作完成。

如需明确关联，在已复制的诊断清单中添加 `associations`，不要修改执行账本或原业务请求：

```json
{"associations":[{"task_id":"TASK_ID","command_id":"COMMAND_ID","request_id":"REQUEST_ID"}]}
```

仅填写实际已知身份，未发生选源 PUT 时省略 request_id；允许一个任务多个会话或一个会话多个命令。导出标注关联由操作者提供，无法对应本次查询的附件单列，不根据相同 run_id 或时间重叠自动关联。缺 bag、话题、时间段或对端日志均不补造。

### 12.1 每轮生命周期与身份

- 新建任务完成执行后端选择，且为真机路由、`brain.diagnostics.enabled=true` 时，大脑通过现有有界工作器登记诊断 run。run_id 按原 task_id 确定，网络重试保留同一 body、时间和事件身份，不换 ID 重录。
- 模拟任务不发起真实采集。混合任务发送 navigation_physical／manipulation_physical 的路由适用性声明；它们不证明该阶段实际执行或成功。实际执行看原命令索引。
- 注册和启动录制是异步的，不阻塞 Runtime 的业务控制；开始过晚、订阅发现延迟和前缀缺口必须由 window／quality 报告，不能把 task_opened 时间伪装成已开始录制。
- recovery_required 保持同一个诊断 run，以允许原任务后续人工恢复；succeeded／failed／cancelled 触发诊断收尾。新任务替代旧任务或达到采集预算时可用 superseded／capture_timeout 关闭旧诊断窗口，但不改写旧业务任务的成功／停止结论。
- 网关收尾保留有界尾窗，再结束本次录制并分析。finish 精确绑定原 run_id／task_id，不能停掉新 run 或外来手动录制。旧窗口释放和新 run 登记优先于晚到元数据，明确 BUSY 时同原请求有界等待。
- 大脑和网关重启不重放旧录制意图。大脑对恢复任务只查询确定的原 run，404 是该查询范围没有报告，不表示机器人没执行过；不返回 latest 替代。
- 对端命令终态时若小摘要仍在生成，即使整轮任务仍是 recovery_required，大脑也按该原命令开启有界补查窗口，再补发索引事件；不要求先结束整轮录制。每个命令最多 4 次／120 秒，约在 0、10、40、105 秒尝试，以覆盖 NAV 排队 60 秒＋构建 30 秒的预算；最多跟踪 4 个待完成命令。窗口结束不因重复旧 pending 快照重开，超过预算明确缺项。用户 GET／HEAD 查询及刷新本身不会启动采集、收尾、重算或上传索引。

### 12.2 冻结的网关 API

复用原网关 HTTPS 地址、CA 及大脑 Bearer，严格源选择合同不变。诊断请求最多 16 KiB，报告最多 64 KiB，诊断 ID 为 1—128 位 ASCII 字母数字及 `_.:-`，路径使用的 run_id 禁止 `.`／`..`；task_id／command_id 继续遵循原业务标识约束。请求时间必须带时区；实际录制起止尚未知时允许 null。

| 接口 | 请求／响应 | 行为边界 |
| --- | --- | --- |
| POST `/v1/diagnostics/runs` | run_id、task_id、started_at、profile=navigation、command_ids、request_ids；首次 202、原 body 重试 200 | 注册本轮；真实采集由网关独立开关允许，未开启返回 recording_disabled，不伪报就绪 |
| POST `/v1/diagnostics/runs/{run_id}/events` | event_id、task_id、at、source、kind；可选 command_id／request_id／source_instance_id／evidence_ref／summary | 只记录有限元数据；finish 后允许同任务晚到索引更新小报告，不重开录制或重扫大包 |
| POST `/v1/diagnostics/runs/{run_id}/finish` | task_id、ended_at、reason、command_ids、request_ids；首次 202、原 body 重试 200 | reason 为 completed／cancelled／failed／timeout／interrupted／superseded／capture_timeout；原意图幂等 |
| GET `/v1/diagnostics/runs/{run_id}/report` | 已预生成的 `fq/robot-diagnostic-report/v1`；存在 200，不存在 404 | 仅读小报告；不在 GET 中扫描 bag、运行模型、发动作或启动采集 |

command_ids／request_ids 每个列表最多 64 项；source 为 brain／nav／vla／sonic／gateway，kind 为 task／command／request／evidence／failure。事件 summary 最多 16 个标量字段，字符串最多 256 字符；高频内容不进入该接口。

错误 400 表示请求合同不符，401／403 表示鉴权问题，503 表示不可用／存储或队列问题。只有 `409 DIAGNOSTIC_BUSY` 可按原意图有界等待；DIAGNOSTIC_RUN_CONFLICT／TASK_CONFLICT／FINISH_CONFLICT／EVENT_CONFLICT 是身份或幂等冲突，不换 ID 绕过。大脑每次调用使用 2 秒网络超时配置，默认最多 3 次诊断意图尝试；诊断故障不改变业务回包或任务控制。任务已经结束且 begin 确定尚未进入发送边界时，会放弃未送出的采集，不事后首次录制；已发出但回包未知则仍按原 run 查询／收尾。

### 12.3 小报告的含义

报告包括 run_id、task_id、status、generated_at、window、quality、findings、evidence_refs、limitations、state_authority=false。诊断 status 为 registered／recording_disabled／starting／recording／finishing／complete／partial／interrupted；与业务 state 分别解释。findings 和 evidence_refs 各最多 32 项；finding.assessment 为 confirmed／suspected／unknown，引用为惰性短标识，不提供任意文件下载。

| 报告部分 | 读取方式 |
| --- | --- |
| window | requested_start/end 与 recording_start/end 分开；不同 UTC offset 按实际时刻比较；未知不补零 |
| quality.topics | 实际记录数、Hz、最大／P95 间隔、首尾位置、采样跨度；能够解析时才报告 Header 重复／回退／年龄，否则 null |
| source stamp | Header 含义未验证时标 unverified_source_semantics；派生话题重新打戳不能证明源传感器新鲜 |
| loss_visibility | 本轮始终 unknown；消息数量、无警告、SQL 可读不能证明端到端无丢失 |
| quality.analysis | pending／running／finished／failed，实际扫描量、消息／字节／时间预算、错误与 truncated；到预算不报全量检查完成 |
| quality.capture／archive | 资源采样、录制 CPU 累计预算、归档／哈希实际工作量及截断；文件级明细留本端 manifest |
| external_summaries | NAV／VLA 的声明，verification=source_declared；大脑已核对原 task/command，但未自动读取引用文件 |
| recorder_released | 仅该诊断录制器是否释放，不是机器人已停止，也不是允许运动的凭据 |

真实完整报告样例：[网关合成报告](../tests/contracts/robot_diagnostic_report_complete.example.json)；它声明 complete，但仍明确 whole_robot_complete=false、loss_visibility=unknown。禁用样例见[未采集报告](../tests/contracts/robot_diagnostic_report.example.json)。二者都不是现场执行证明。

### 12.5 各端增量与资源边界

**NAV：** 原命令终态和关键停止证据变化经 `AgentBridge._diagnostic_command → AutoArchive.notify` 自动提交有界后台封存，同命令合并；构建期间出现新收尾证据会再封存，旧 generation 不覆盖新结果。失败／超时返回 error＋quality.partial，内存小缓存用于文件写入失败兜底，不让 GET 一直只给 pending。默认 32 待处理、128 缓存、合并约 1—2 秒、构建 30 秒、排队 60 秒、看门狗 0.25 秒。实际消费者统计沿原回调和诊断模块增加，区分接收、源戳接受／拒绝、缓存更新、门禁检查、处理／锁等待；不改 0.30／0.50 秒等业务阈值。高频路径只更新固定大小计数／直方图，后台约每秒写摘要；缺少任务关联时明确未关联。命令事件另有实例独立的受控归档，预算耗尽保留旧证据并报告截断。原命令 GET 可选带 `diagnostic_summary`，只读预生成缓存，不能把 GET 当作归档启动器。NAV 不由本轮做 Git 操作，不自动执行正式一键入口。
