### 1. 发现的问题与改动

原现场描述已经指向本地，但接待视觉核验仍配置云端；桌面双图判断、视频抽帧消费者没有完整转发关闭 thinking 等参数。部分入口还强制要求云端 API Key。旧 Slaver 相机诊断遇到模型异常或空回答时，甚至会返回 normal。

本次沿现有入口修改：

- `shared/vision_options.py` 统一构造请求选项，不读取或另建模型端点配置。SDK 请求保留 `extra_body`；原始 HTTP 请求将其中字段展开到请求体。禁止 extra_body 覆盖模型、消息、流式方式和标准生成参数。
- `auth_required: false` 显式允许无鉴权的本地模型，使用占位凭据；默认仍要求各自配置的云端凭据。不存在失败后切回云端的逻辑。环境变量更换端点时不自动继承本地免鉴权属性。
- 本机回环地址的 SDK 客户端不继承桌面 HTTP/SOCKS 代理，避免已出现的不兼容代理 scheme 阻止本地调用；远端客户端不因此改变网络路径。
- 现场描述、桌面双图判断、Slaver 相机描述、候选物体识别和独立接待视觉核验转发显式生成参数、超时及本地非思考设置。抽帧学习复用这些选项，但本轮没有重测其视频理解能力。
- Slaver 诊断遇到异常、空输出或无法识别的状态时返回 unknown，现场工具返回 failure，不再把它伪装成 normal。
- 未改变 Runtime、执行反馈要求、任务／命令身份、核验阈值、LLM 裁决规则或照片核验启用开关。

共 **688 次视觉 API 请求**：

- 两轮主对照各 316 次，共 632 次：每轮候选与 9B 各 158 次。
- Connection 原图接口两轮各 16 次；4B 双图超限后追加双方各 8 次的 4MP 复测，共 48 次。

同轮两端的图片字节、问题、采样和输出预算相同：temperature 0、top_p 0.95、presence_penalty 0、seed 42、max_tokens 1024，关闭 thinking。每次使用新图片 UUID 和前缀 salt；约束 JSON 只限定结构和类型，不提供正确答案。原图开放描述及原始接口测试未缩图；标注题、并发及明确标记的接口复测限制 4,194,304 像素。

测试在约 48GiB 的 RTX 4090 上，候选依次运行，与始终驻留的 9B 交替调用。服务器原有其他 GPU 作业，本次未停止它们，背景负载在两轮间发生变化；完整进程显存与 GPU 利用率采样保留。应比较每个候选与其同轮 9B，不把两轮时延当作完全隔离条件下的硬件排名，也不直接套用此前 FP8 的最快结果。

这组五次调用全部成功，耗时分别约 2.26、1.53、0.98、6.53、2.43 秒；内存任务不代表物理抓放测试。

实际调用千问、约 5.95 秒返回，无新增经验，来源记录为 `LLM(qwen3-vl-plus)`。

### 同日切回 DeepSeek

2026-10-15 下午，用户确认服务恢复并要求切回 DeepSeek。使用原有凭据和 `ModelClient`
发送构造文本，无动作连通测试约 0.93 秒返回正确 JSON。首个探测进程因继承终端 SOCKS 代理且
缺少 socksio 而未发出请求；仅在探测进程清除代理后通过，不将该本机依赖错误记为 DeepSeek 故障。

新进程日志确认实际调用 `deepseek-chat`，HTTP 200。本次仅验证模型连通与正式入口，未重跑 O6 或真机任务。
