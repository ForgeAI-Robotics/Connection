## 2. 本轮流程、入口与证据要求

真实业务路线为：导航到冰箱前 → 开门 → 效果确认 → 抓可乐 → 效果确认 → 中转点 1、2、3 → 1 号桌。当前不执行关门或放置；具体目标与参数只维护在绑定的 Skill，不由联调文档另起坐标配置。

| 页面入口 | 本轮验证用途 | 不能替代的证据 |
| --- | --- | --- |
| 左上：导航真机＋操控真机 | 验证整条真实链路 | 初始化和读取现场成功不代表导航已到位；人工跳过不能记为全流程成功 |
| 右上：导航真机＋操控模拟 | 验证导航与流程衔接，保持已跑通路径 | 模拟开门、抓取和持物不证明实物效果，也不切到真实 VLA |
| 左下：导航模拟＋操控真机 | 在现场已摆好作业位置时单独验证操控 | 模拟导航不会移动机器人，不生成真实到位证明，也不证明真实运送 |

流程中的证据链：

```text
大脑下发 NAV 目标 → 查询原命令 → 到位／停止回执
→ 大脑选择 VLA，接收端确认 → 提交开门任务
→ VLA 内部准备与执行 → 暂停、真实效果确认、查询终态
→ 同源继续抓取 → 确认物体与手臂已离开冰箱并保存持物事实
→ 选择 NAV → NAV 恢复所需 Planner 通信／模式 → 逐段导航并核验
```

大脑不直接发 SONIC START／STOP，不操作 O6 CAN，不重复检查 VLA 的模型、相机和身体模式。VLA 停止策略／发布、O6 保持、SONIC 身体收尾、关闸成功和业务成功分别记录。当前 VLA STOP 的具体姿态影响仍在执行端讨论与验证，不能把“输出停止”自动解释为“原姿态冻结”或“已安全撤离冰箱”。

启动顺序按[面板说明](接口说明_控制面板.md#三端启动与任务发布)：原独立导航入口启动配套 NAV／SONIC；相机卡片先开启头部和双腕，再启动 VLA HTTP。**面板原 NAV 启动脚本仍为旧 unified，与 brain-navigation-start 不等价；启动按钮和后端 start／restart 已暂时禁用，待导航同步后再对齐。** 变更需重载面板生效，详见面板说明。相机端口绿灯不证明三路图像新鲜，VLA HTTP 在线不证明任务可执行。

## 6. 每次更新如何避免版本串线

1. 先记录各端源码／安装版本、实际进程是否已重载，以及本次真实／模拟组合。仅修改代码、仅安装、仅健康检查分别说明。
2. 保留 task_id、步骤、尝试和原 command_id。受理、执行、终态、效果、停止与选源分别核对；新任务拒绝不能写成动作执行失败。
3. 对同一问题补充原模块的失败、修复、复验与未通过项，本页更新跨端验收结论及直达链接。不要因新版本通过而删除旧失败。
4. 稳定的接口字段在接口说明修正，职责变化在架构中修正，现场证据在模块联调中修正；检查当前与历史措辞、索引、链接和锚点。
5. 操作／实验按用户当次授权执行。文档整理、查日志和离线测试不会自行重启服务、解除保护、补发动作或清理未知账本。
