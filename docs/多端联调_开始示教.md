## 3. Skill 流程与会话生命周期

建议包名 `teaching`、SOP ID `teaching.capture`、首版版本 `1`，仅在示教实例显式启用；这些均待实现。“拿取当前点位”表示**读取当前位置与朝向快照**，不导航到某个点，不自动建立导航目标。

```text
任务：开始示教

○ 接收真机语音识别结果，识别示教开始意图
○ 初始化示教任务，保存原 ASR 文本与来源
○ 只读获取当前机器人位姿
○ 核验位姿来源、地图／坐标系、时间与有效性
○ 保存本轮示教起始点位
○ 检查目标头部相机，取得有效新帧
○ 启动本轮头部录像
○ 录制中，等待“结束示教”或本轮显式取消
○ 停止本轮录像并完成文件封装／刷盘
○ 核验视频、帧索引与位姿快照关联
○ 示教完成，返回结果与文件位置
```

“已开始录制”只表示启动成功，整轮任务保持活动；文件封装和核验完成后才能报告示教完成。无需人为移动机器人来验证首版，真实动作、拖动或操控示教不属于本文授权范围。

### 3.1 开始、结束和重复触发

- 开始事件保存本次 `task_id`、步骤／尝试／命令身份、原 ASR、来源机器人和事件标识；保留原文，关键词归一化不覆盖原文。
- 同一个语音事件的网络重试保持原身份，不能每次生成新任务再启动录像。已录制时重复“开始示教”，返回当前会话或明确忙碌，不覆盖文件、不重新记录另一份起点。8 秒冷却只能减少连发，不能替代幂等。
- “结束示教”映射为当前示教任务的结束请求，必须在**新任务准入前**处理；不能当作另一个新业务任务，否则会被当前单任务准入阻挡。它不等同于“取消”，也不能借用 G1 的 VLA finish 或全局任务停止接口。
- 结束请求绑定原 `task_id` 和录制身份；语音未携带目标身份时，只能在来源机器人与当前唯一示教任务匹配时绑定。无会话或归属不明明确返回，不对其他实例／机器人广播结束。
- 明确否定、询问或冲突口令不能仅凭包含“开始示教”就启动。受限解析规则、标点／空格和带任务说明的原句用例须记录；不允许 LLM 生成导航或机械臂动作。
- 显式取消只停止本轮录像并保留已有片段和取消结果，不能停止机器人或关闭公共相机。首版若不支持暂停／续录，明确返回未支持；如实现，保留分段与间隙，不拼成无中断录像。
- 配置录像最大时长、文件／磁盘预算及断流处理期限。达到预算须结束或失败收尾并说明原因，不能无限录制或把截断文件当正常完成。

### 3.2 位姿快照的最小规范

复用原 NAV 的只读定位结果，核对部署后实际路径与字段。已有 `DreamClient.status()/world()` 不保证一定提供所需精确位姿；若缺字段，在隔离适配或 NAV 原服务中补只读接口，并把真实路径、字段、鉴权、时效和部署版本写入[导航接口说明](接口说明_导航NAV.md)。禁止发一个导航目标来“获取点位”。

保存 `robot_id`、来源服务／实例、源采样时间与大脑接收时间、地图身份／坐标系／定位代次、`x/y/yaw`（米／米／弧度）、定位有效性及原响应引用。数值必须有限、时间及时效可核对；未知不能填零、旧目标坐标或上轮任务的 `final_xyt`。只读定位有效性与运动批准是不同事实，不为了读点位自动 Approve、Arm、定位初始化或切源。

把该快照保存为本轮示教的起点，不能自动覆盖导航已标定业务点；起始位姿不代表录像全程位置。首版不要求持续轨迹采集，录像期间移动或重定位时不能把初始快照当作每帧实时位姿。位姿时间与首帧时间偏差预算由负责人配置并回写，过期则重读或拒绝开始，不伪造同步。

### 3.3 头部录像与结果规范

复用已运行的头部相机接收／采集链路；G1 可参考 [VlaCameraClient](../src/brain/adapters/vla_camera.py)，天机可参考其[头部相机适配](../src/brain/adapters/tianji_camera.py)。当前单帧 API 本身不承诺录像帧率，不能把低频重复 JPEG 拼成标称 30 FPS 的连续真机视频。

优先核对原相机服务是否已有可复用的录像功能；若无，由接手者在现有媒体／相机适配边界补有界录像能力，按可用带宽消费头部新帧或既有视频输出。录制组件负责采集和封装，Runtime 仍负责业务状态；不新建另一套任务调度或重复占用相机设备。不能靠取消真机录像路由的拒绝，把仿真 `/record` 接口当成真实实现。

每轮使用独立输出目录，例如示教工作区的 `data/demonstrations/<受控任务目录>/`，保存视频、帧时间／索引及元数据。元数据至少包含：

| 类别 | 保存内容 |
| --- | --- |
| 身份 | task／step／attempt／command；录制 ID、机器人、相机及服务实例，Skill／配置版本 |
| 语音 | 原 ASR、入口、语音事件标识；不保存密钥，不要求首版保存音频 |
| 起点 | 第 3.2 节位姿快照及其源／接收时间 |
| 时间与帧 | 开始请求、实际首／末帧、结束请求及封装完成时间；源帧 ID／时间、有效／丢失／重复帧计数和中断 |
| 产物 | 视频文件位置、容器／编码、分辨率、实际时长与帧率、文件大小及 SHA256；本地可访问路径或实际服务支持的下载方式 |
| 结果 | 正常结束／取消／失败／未知、原始错误和未完成片段；不能把文件存在写成录像已完整 |

第一张有效新帧写入并确认录像工作器正常后才报告启动成功；结束须确认编码器／文件写入结束、视频可解码且帧数／时长合理。重复帧不重复计为新采集，跨时钟按来源时间核对。摄像头、机器人或服务实例中途改变，按断流／分段规则处理，不悄悄混录。

启动或结束回包丢失时按原录制身份查询；重启后核对已有录制器与文件，不自动开启第二个录像或覆盖旧片段。旧会话的结束／取消迟到不能关闭新录像。录制 ID 和产物清单只是执行证据，不能维护一份独立于 Runtime 的业务状态权威。

“结束示教”语音／文本必须分流到同一个原任务结束机制；同事实现后在本文补最终接口、实际 ASR 转发请求和完整返回示例。HTTP 200、录制启动受理、入口健康均不作为录像完成依据；发布／结束超时先查原任务，不自动重发或创建新轮次。
