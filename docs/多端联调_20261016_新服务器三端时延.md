# 多端联调：新服务器三端时延

发生日期：2026-10-16，16:27–16:34，北京时间。本轮测量时段的状态与随后现场操作分开记录。

## 1. 结论与范围

在迁移后的大脑服务器测试实际配置的 Brain、NAV、VLA 服务，未发布机器人任务、重启服务或修改配置。
接口可达，但**通信稳定性不能判为通过**：导航状态查询在主采样中最高 6.38 秒，补测出现一次 10 秒超时。
测量期间导航与操控均报告动作条件未就绪，没有测到真实导航执行、GR00T 推理、抓放或完整接待时长。
不使用 [10 月 10 日协议基准](多端联调_20261010_通信延迟对比实测.md)的模拟接口结果代表新服务器性能。

## 2. 环境、身份与方法

- 本地代码基线 `d6ceef4`，开始时工作区干净；已核对本机监听进程、角色地址、生效环境与实际回包。
- 地址从 `config/networks.yaml` 解析。大脑与 VLA HTTP 桥同机，NAV 位于机器人 NX，并非三个独立计算服务器。`brain.yaml` 中旧 URL 会被统一网络配置覆盖。
- 生效接待环境为 `reception_real`，本轮未切换环境。大脑／网页进程启动于当天 11:44:32，VLA 于 11:03:42；磁盘版本不证明常驻进程已重载最新源码。
- 主采样为 16:30:27–16:32:03。urllib 短连接、禁用代理、单请求串行，7 个接口分别预热 2 次，再各测 3 轮 × 10 次；每个采样位置打乱接口顺序，请求后间隔 100 ms。
- 耗时使用本机单调时钟，包含建连、服务处理、完整响应接收与 JSON 解析，不是纯网络 RTT。P50 为中位数，P95 为排序后 `ceil(0.95*n)` 项。
- socket 超时设为 6 秒，不是请求总截止时间，因此总耗时可能超过 6 秒；补测 curl 使用独立的 10 秒总截止时间。
- 模型测量单独调用 `/api/chat/route`，只返回分类标签，不建任务。
- 这是现场低频采样，没有隔离后台流量；同时间另有[三端启动前只读核验](多端联调_20261016_三端启动前核验.md)。结果不是空载性能或长期 SLA。

### 实际路由与解释

- 新机 → 当前 VLA：`ip route get` 返回 `local ... dev lo`。虽然使用局域网地址，请求仍由本机回环处理，不经过无线链路；亚毫秒健康响应可复现。
- 旧机 → 当前 VLA：走旧机无线网卡 `wlp65s0`。旧／新约 31.9／0.6 ms 的差别主要比较跨机路径与本地路径，不能当作服务器算力对比。
- 新机 → NAV：本轮实际使用有线网卡 `eno1`，源地址也已变为有线接口地址；与 16:53 复测时使用无线的路径不同。该事实同时由路由输出和全部 30 个导航样本的 `local_ip` 确认。
- 旧机 → NAV：仍使用无线网卡 `wlp65s0`。新机导航状态中位数较低，但 P95 接近且本次新机略高，不能宣称所有时延指标均更好。
- VLA 状态接口会同步查询 NAV，因此新机本地状态查询约 56 ms，与不查询下游的健康接口约 0.6 ms 不矛盾。

本轮没有改变网卡、路由、服务或机器人状态；不能将测量期间已存在的有线路由记作本轮修复。
对比只覆盖通信及接口响应，不包含模型推理、策略计算或物理动作耗时。

### 路由核对与结论

- 大脑访问两个地址，路由均为 `local ... dev lo`，本机健康都约 0.6 ms；改目标 IP 没有消除新的网络跳数。
- NX 两条访问都从其 `wlan0` 发出，旧机两条访问都从 `wlp65s0` 发出，来源端仍使用无线。
- NX 和旧机的邻居表均确认：目标无线地址对应目标无线网卡 MAC，目标有线地址对应目标 `eno1` MAC；本次不是两个地址落到同一网卡的假对照。
- 跨机健康请求使用目标有线地址有约 7–8 ms 的中位数收益；完整操控状态仍需同步请求 NAV，本轮没有显示稳定的显著改善。
- 因此，跨机使用有线地址有一定价值，但本机请求基本无收益，也不会让完整跨机状态查询变成亚毫秒。

本轮只测目标地址差异，不改大脑访问 NX 的目标；也未把来源端无线改为有线。
当前背景流量、无线竞争、共享服务处理及 NAV 查询都会影响状态耗时，未做长期稳定性或动作验收。
