# 单罐接待导航／操控协议模拟

用于真机不可连接时验证共用大脑的完整接待链路。两个独立 HTTP 进程分别代替 DREAM NAV 和 VLA，默认每条命令等待 2 秒后按模拟场景返回成功。它是协议与流程模拟，不计算运动物理，也不产生真实相机或传感器证据。

正式任务入口、任务选择、接待 SOP、Runner、Verifier 和账本继续共用。`reception_protocol` 仅选择本机端点，使用同一个 `BodyAdapter`、`DreamClient`、`VlaClient`，没有专用的“模拟即通过”核验分支。与旧 `reception_mock` 会议补货演示无关。

## 从面板使用

1. 启动或重启运维面板，使新服务目录生效：`venv/core/bin/python -m ops`。首次更新代码后，也重启「任务网页」服务以加载新模板；常驻网页进程可能缓存旧模板。
2. 在 `:5678` 的「运行环境」点击「仅接待协议模拟」。应用过程先核对任务空闲，再启动导航与操控模拟服务，核对身份、版本和共享状态，重启本机大脑使配置生效。
3. 在任务网页 `:8888` 首页输入「开始接待」，或使用同一大脑任务 API。流程为 `table_2 → 抓取 cola_can_1 → relay2 → relay3 → table_1 → 放置 cola_can_1`。
4. 网页显示「导航／操控模拟」，成功时显示「协议模拟完成」。任务账本中的 `execution_backend` 为 `reception_protocol`；正式 SOP 为 `reception.single_can` v1。

该预设停用通用执行与画面模块，不需要 Redis、MuJoCo、3DGS 或 GPU；已有 Slaver 的启停仍遵守原有环境切换规则。若需要保留其它模块，可在模块下拉框中单独选择接待的「单罐接待 · NAV/VLA 协议模拟」，再应用当前选择。旧 `/reception` 演示页及 `/api/reception/run` 仍使用旧演示；本流程使用首页任务发布入口。

「运行环境」另有两张服务卡片，可分别查看健康、日志和启停。仅启动进程不会切换大脑路由。有活动任务或未核清命令时，环境切换被拒绝。应用失败按原有事务回退；不会启停远端机器人或修改真机动作许可。切回接待真机仍需独立满足真机许可和实际下游证据。

命令行使用同一套应用流程：

```bash
venv/core/bin/python scripts/execution_mode.py preview --file config/examples/execution_reception_protocol.yaml
venv/core/bin/python scripts/execution_mode.py apply --file config/examples/execution_reception_protocol.yaml
```

正式任务 API 示例：

```bash
curl -X POST http://127.0.0.1:5000/publish_task \
  -H 'Content-Type: application/json' \
  -d '{"task":"开始接待","task_id":"protocol-reception-001","refresh":false}'
curl http://127.0.0.1:5000/api/task_status
```

每轮使用新的 `task_id`。同一任务的恢复使用「继续」按钮，走原任务的继续入口，不创建新的总任务。明确的「开始接待」不需要调用 LLM 重新规划；自然语言选择和异常分析仍按大脑配置运行。

飞书私聊或网页可单独发送「停止/取消」「暂停」「继续」控制当前任务。群聊须 @机器人。控制消息不创建新任务；已经完成时发送停止会回复无需操作。停止受理后仍需原命令的停止与资源归还证据才能报告已取消。客户端可向 `/api/task_cancel`、`/api/task_pause`、`/api/task_continue` 发送 `{"task_id":"原任务ID"}`；任务身份已改变时会拒绝控制。

网页按钮随当前任务状态启用：有未完成任务时不能重复开始，完成/取消后不能继续；控制请求处理中防止重复提交。所有控制绑定当前显示的任务 ID，页面状态与大脑身份不一致时要求刷新。刷新进度只读取状态。

暂停关闭后续下发，并通过现有停止／取消接口停止当前动作，保留总任务和环节。点击「继续」时读取原动作：确认停止和资源释放后，已报告成功的动作进入效果核验，不重复下发；明确失败、取消或确认未开始的动作，则在同一总任务、同一环节准备新尝试，使用新的 `command_id`（例如 `-r1`），前置检查通过后再提交。原命令及其取消／失败回执不会修改。普通轮询、进程重启、LLM 建议均不自动创建新尝试。

动作尚未下发时暂停，继续原计划；临时服务离线造成的交接断点，继续重新核验交接，已准备但未提交的尝试沿用同一个新命令 ID。原动作仍在运行、停止不明、资源未释放或成功报告缺少效果证据时，继续不会盲目重发。导航到位、持物状态、控制器接管与最终放置核验均保留。

### 跳过继续与继续

「跳过继续」替代原来与「继续」重复的「断点继续」按钮。对当前待恢复步骤或已暂停且未完成的动作开放：人工明确放弃该步骤，读取原命令确认停止、资源释放后，记录 `manual_skips` 并进入下一执行步骤；原始失败和回执保持不变，不重试该动作，不更新它未被证实的效果。相邻的核验节点也标为人工跳过。规划失败、运行中、尚无动作的暂停和已成功步骤不能跳过。

请求为 `POST /api/task_skip`，JSON 必须包含 `task_id` 和状态接口提供的 `skip_step_id`（请求字段名为 `step_id`）。双重身份校验避免旧页面或重复请求跳过另一个任务/步骤。`can_skip` 表示可以申请跳过，实际受理仍要核对停止回执。`继续` 则核验或用新尝试重新执行原步骤，不放弃它。

下一步仍遵守现有接口前置条件：接待 VLA 要求真实导航成功凭证，因此跳过失败导航会进入抓取步骤，但可能停在抓取交接检查，不能伪造成功凭证强行下发。跳过抓取也不代表手上已经持物。模拟下游沿用这些约束，未添加特殊放行。若希望导航失败后仍无条件启动抓取，必须先明确修改真机的业务前置条件和接口合同。

页面将人工跳过显示为「人工跳过，未确认成功」，不显示成功勾。后续步骤走到末尾时返回 `state=failed, flow_finished=true, all_done=false`，显示「流程结束（含人工跳过，未全部成功）」。反思包含人工跳过记录，不将其总结成全部成功。

### 同时验收通用规划、识别和反思

保留接待协议模拟，并将通用执行模块设为 Desk 模拟：

```bash
venv/core/bin/python scripts/execution_mode.py apply --execution simulation --execution-sim desk
```

自然语言如「二号桌那罐可乐送到一号桌」先经任务网页的 `/api/task_intent` 分流，再经正式发布入口由 LLM 匹配单罐 SOP。核对状态中的 `selection.source=llm` 与 `selection.sop.id=reception.single_can`；精确触发词「开始接待」仍直接选取已登记 SOP。

通用规划需另用非 SOP 任务，例如「抓取 tissue_ball_2，然后放置到 trash_bin，只处理这一件物体」。大脑读取 Desk 实际对象和目标区，LLM 产生计划，统一 Runtime 执行并核验。核对 `selection.package=generic`、规划解释、逐步尝试及核验结果。该例只验证通用规划在 Desk 能力范围内执行，不代表接待 NAV/VLA 支持任意物体和路线。

任务结束后，反思异步消费不可变账本，包含目标、物体、业务选择、下游报告、证据等级、已确认事实和错误信息。通过任务状态中的 `reflection` 或 `data/tasks/learning/` 核对真实来源；`LLM(deepseek)` 与模型不可用后的模板回退分别标记。模型可返回无新增经验；反思仅保存候选，不自动更改 SOP 或驱动重试。运行这些在线验证需要已配置的模型连接可用。

意图识别、执行结果核验、异常识别均可在本配置验证；真实相机视觉识别没有输入，不能由成功模拟回包代替。

## 两个进程与状态

| 服务 | 地址 | 手动启动 |
|---|---|---|
| 导航模拟 | `http://127.0.0.1:18001` | `venv/core/bin/python -m execution.reception_sim nav` |
| 操控模拟 | `http://127.0.0.1:18091` | `venv/core/bin/python -m execution.reception_sim vla` |

两个进程默认共用 `data/reception_sim/state.sqlite3`。SQLite 事务保存请求、原命令 ID、时间、终态及模拟场景，跨进程串行化动作通路。相同 ID 与相同请求重复 POST 返回原事务；不同请求使用相同 ID 返回 409。重启不会创建新命令或清空终态；未完成的定时逻辑按原受理时间继续推进，下一次查询可观察到完成。停止进程不等于取消命令，取消应使用任务控制入口。

每个新任务初始化一罐位于 `table_2` 的独立模拟场景；同一任务按实际模拟抓放更新 `holding` 和位置。已有其它任务持物时禁止初始化新搬运任务。正常成功后可用新任务 ID 重复演示。故障实验建议使用独立 `--state` 路径，两服务必须使用同一路径；不通过清空当前账本或数据库解除未核清状态。

`/health` 保留正式服务身份字段，并添加 `simulation` 元数据（类型、角色、共享状态实例 ID、场景、延时）。环境应用与大脑端口创建都会核对两端身份，拒绝不匹配的服务或状态文件。默认只绑定本机回环地址，模拟服务不导入机器人控制 SDK，不向真机下发动作。

## 接口对应与明确差异

动作请求的契约版本仍是 `fq/reception-lan/v1`，字段、坐标、导航段组合使用共用合同。测试逐条与 `tests/contracts/reception_wire.json` 核对，动态任务 ID、命令 ID 及导航凭证引用保持关联。

| 接口 | 模拟行为 |
|---|---|
| `POST /v1/navigation/goals` | 校验字段、有限坐标、固定路段、同任务段序与独占通路，202 异步受理 |
| `GET /v1/commands/{command_id}` | 原命令状态、带时区时间、到达与导航停止结果；未知 ID 返回 404 |
| `POST /v1/navigation/cancel` | 校验任务归属，202 受理取消；原命令查询确认终态与停止 |
| `GET /v1/status` | 导航活动命令、通路就绪与可选控制器凭证 |
| `GET /v1/world`、关系图 | 单罐 SOP 的固定对象目录；不提供物理地图 |
| `POST /v1/vla/tasks` | VLA 通过 HTTP 查询原导航命令和 NAV 状态，再在共享事务中核对当前位置、持物与通路；202 受理，前置证据不符则记录未启动策略的失败终态 |
| `GET /v1/vla/tasks/{command_id}` | 原操控状态、抓取／放置结果、策略停止及通路归还 |
| `POST /v1/vla/tasks/{command_id}/cancel` | 取消原事务，不把已完成动作改写成未执行 |
| `GET /v1/vla/control/status` | 策略、动作通路与可选控制器凭证 |
| 相机、快照及 inspection | 相机状态为未就绪；创建快照和 inspection 返回 501，不伪造图像。正式 SOP 的可选 inspection 应关闭 |

默认成功场景模拟的是文档规定的完整物体结果合同；物体证据的 `source=protocol_simulator`。**它不代表当前真机已具备这些证据。** 当前真机的 `hand_state_only` 能力与完整合同有差距；可以用同名故障场景回放该差距，大脑仍停在核验断点。

### 控制器凭证扩展

这是本轮新增的、模拟与真机共用的可选状态契约，不声称现有真机服务已经实现。动作提交与查询接口没有增加新路径。目标服务在现有状态响应中提供 `control_receipt`：

```json
{
  "contract_version": "fq/control-receipt/v1",
  "task_id": "protocol-reception-001",
  "source_command_id": "nav-table2-original-id",
  "kind": "to_vla",
  "controller": "manipulation",
  "active_command_id": null,
  "confirmed": true,
  "observed_at": "2026-09-28T10:00:00+00:00"
}
```

`to_nav/navigation` 由 NAV 状态返回，`to_vla/manipulation` 与 `safe_idle/safe_idle` 由 VLA 状态返回。凭证必须来自控制器当前实际接管／待机状态，绑定刚完成的原任务和原命令；不能由“大脑认为上一动作完成了”推导。模拟器的凭证只证明持久化模拟控制器状态。

共用适配器同时要求原命令身份正确、成功终态、停止与资源归还、两侧无活动命令且通路就绪，再验证凭证版本、任务、原命令、交接类型和控制器。观测时间不得早于原命令完成时间，最多 10 秒旧、容许最多 2 秒时钟超前。凭证缺失、错误、过期或忙碌均阻断，不因为选择模拟后端而放行。

因此，后续真机联调仍须实现并现场验证该凭证扩展，或依据双方确认的真实接管协议更新共用适配器；只换 IP 并不能补上真机缺少的物体与控制器证据。

## 可控故障与验收

手动启动可指定 `--delay 5` 与 `--scenario`。故障设置不塞进正式动作请求体；被受理时写入原事务，进程重启或参数变化不修改旧命令。

| 场景 | 预期行为 |
|---|---|
| `success` | 默认延时成功，完整单罐流程闭环 |
| `nav_failure` | 导航失败、停止已确认 |
| `pick_failure` / `place_failure` | 操控失败、策略停止和通路归还，不伪造物体效果 |
| `hand_state_only` | 服务报告完成但物体证据弱；大脑不继续搬运 |
| `missing_receipt` | 动作成功但不提供接管凭证；大脑停在交接断点 |
| `waiting_navigation` | 导航停在 `waiting_operator_approval`，不会自动成功，可取消原命令 |

`tests/brain/test_reception_protocol.py` 覆盖请求校验、段序、幂等、跨任务导航凭证、取消、重启、弱证据、凭证身份与时效；进程测试实际启动两个解释器，通过正式 HTTP 客户端与大脑任务 API 跑六条动作并核对冻结合同。完整回归入口为 `venv/core/bin/python scripts/run_tests.py`。测试不连接真机，也不验证在线模型理解质量。

本轮离线验收（2026-09-28）：完整回归 364 条测试通过，DREAM 自测 27 项通过。双进程测试从正式大脑入口完成六条动作，另验证弱证据／缺接管凭证阻断，以及取消后重启仍查询同一命令。没有切换本机现有生效配置，没有进行真机验收。

后续已实际切换本机环境并完成网页及浏览器联调，发现的进度显示问题已修复，详见[实际联调记录](联调说明_接待协议模拟.md)。上段为实现轮次的离线记录，当前运行状态以联调记录为准。

取消动作后，协议模拟器在逻辑场景未改变、没有活动命令且前序动作真实成功的情况下，重新报告前序控制器的就绪回执；失败／取消动作仍保持原回执。该模拟行为不代表真机已经提供了同等控制器回执，真机缺失回执时仍拦截执行。
