# 接口说明：控制面板

更新日期：2026-10-09。维护面板功能、服务启停、三端启动与收工流程；安装依赖见[项目 README](../README.md#安装和启动)，VLA 独立操作见[操控接口说明](接口说明_操控VLA.md#操控侧检查与独立启停)。

独立进程面板，默认监听 `0.0.0.0:5678`。管理本机服务、运行环境和日志，支持 DREAM / VLA 健康探测与远程启停。**不会发布接待任务。**

第一版没有登录。任何能访问 5678 的局域网设备都可以启停 Redis / Master / Deploy / 飞书 / 语音入口 / Slaver / Desk 仿真。请只在可信网络使用。

侧栏分为三个工作区：

- **大脑层**：大脑、网页、飞书、语音四个紧凑卡片在桌面端同排显示，点击卡片切换下方同一个日志窗口，默认选择大脑。直接显示完整运行输出，不分日志类别、不筛选级别、不折叠事件。启停按钮和打开网页链接执行各自动作。页面和日志均可上下滚动，查看历史时自动刷新保留阅读位置。语音入口监听 `:8890`，把已识别文本交给大脑，不采集、不筛选。
- **运行环境**：全局与模块环境配置、Desk / MuJoCo / 3DGS 三个仿真服务，以及各自日志。折叠的「高级：仿真执行依赖」保留 Redis / Slaver 的状态、启停与日志。MuJoCo / 3DGS 的动作执行仍走 Slaver 和 Redis 传输，Desk 则直连；这两个服务不是另一个大脑，不能仅因统一了 Runtime 就删除。
- **真机层**：DREAM 导航与 VLA 操控的健康检查、远程启停与日志。

Desk 是通用任务用的本机 mock 后端 `:5008`，没有相机画面。MuJoCo 是带画面的厨房仿真 `:5001`（RoboCasa 资产未下完时先起轻量台面）。3DGS 是扫描场景仿真 `:5002`（MotrixSim + 高斯点云）。网页 `:8888` 四宫格是**配置中观察后端的四路相机**，不是四个仿真，也不会因某个服务停机自动切到另一个环境。

## 开机自启（只起面板）

```bash
sudo apt install tmux
sudo bash infra/systemd/install_panel.sh
```

日常：

```bash
sudo systemctl enable --now fqplanner-panel
sudo systemctl restart fqplanner-panel
sudo systemctl status fqplanner-panel
sudo journalctl -u fqplanner-panel -f
```

单元没装时 `systemctl restart` 会报 `Unit not found`。装好之前：

```bash
venv/core/bin/python -m ops
```

业务进程开机后默认全停，在面板里用「启动／重启」「停止」管理。三个输入通道在各自卡片使用「开启入口／关闭入口」。**每个服务一个独立 tmux session**，名字就是服务 id：

```bash
tmux ls
tmux attach -t redis
tmux attach -t master
tmux attach -t deploy
tmux attach -t feishu
tmux attach -t slaver
tmux attach -t desk
tmux attach -t mujoco
tmux attach -t gs
```

各服务日志都在 `logs/YYYY-MM-DD/<服务>/`。日常任务过程统一查看大脑日志；网页与飞书的入口进程诊断日志仍保留在各自目录，也可通过 `/api/services/deploy/logs`、`/api/services/feishu/logs` 查询。面板只读日志目录，不把 tmux 窗口当主日志。飞书不再写 `data/feishu/feishu.log`。DREAM / VLA 的探测和 SSH 输出写在当天的 `monitor.log`。

页面直接附带服务卡片信息，打开即显示卡片并读取日志；健康状态按服务层独立更新，初次检查完成前显示「检查中」。日志加载和轮询不等待健康检查，慢的仿真或远端服务不会阻塞大脑日志。状态列表不重复枚举各进程的子进程树，启停操作仍使用完整进程管理。

默认读取所选服务最新一次启动的进程日志（最多最近 8000 行，完整文件保留在磁盘）。大脑排查只看这一份 `logs/日期/master/启动时间.log`。格式对齐 RoboAgent，一条事件一行：`时间 - master - LEVEL - 中文说明与英文字段`。已经写明原因的失败不再另附调用栈；进程自己崩掉时，堆栈仍另起行。`brain.log` / `brain.jsonl` 仍作存档并保留完整堆栈，面板不拿它们当主日志。

过程日志按事件顺序写在同一文件里：收到的任务、预检、步骤、下游调用和模型转发都带方法、地址、状态、耗时和摘要。错误保留中文原因、英文错误码和完整原始错误，不截断堆栈。未知事件原样保留。重启只读显示原任务状态，不自动继续任务。

不在进程日志重复展开“分析、依据、原始诊断”或建议 JSON；正常恢复建议和复盘结果正文留在 `brain.jsonl`。生成建议或复盘本身失败仍直接打印。Flask 启动横幅、原始访问日志和 httpx 的单行 `HTTP Request` 不进入这份文件。

后台监测照常执行。场景认知、相机画面、机器人现场状态以及其它已知只读轮询，成功时不逐条打印；检测不到或下游异常时打印一条，写明有没有发出请求、目标地址、HTTP 状态和错误原文。同一故障不重复刷屏；原因变化、恢复、恢复后再次失败各再打印一次。导航/VLA 的面板健康探测同样只记录异常与恢复。

日志上方不再单独挂当前状态红条。任务状态看大脑卡片和这份日志。`/api/brain/overview` 仍只读核对大脑健康、任务和生效环境，历史 `brain.pin` 不作为告警。查看日志不会清理账本、确认故障或改变真机动作许可。

`systemctl restart fqplanner-panel` 只重拉监视进程（单元 `KillMode=process`），不会停止 Redis / Master 等业务。

Redis 的启动日志在 `logs/YYYY-MM-DD/redis/*.log`。`tmux attach -t redis` 里若只有一行 `[log] redis -> …`，去看这个文件，或重启 Redis 让窗口同步打出 `Ready to accept connections`。

面板重启 Master 前会弹出确认，因为它会中断当前 Master 进程和在处理任务。是否清空 Redis 协作库由 `config/brain.yaml` 的 `collaborator.clear` 决定；当前为 `false`，不会主动清空，只有显式改成 `true` 才会在启动时清库。

## 运行环境

侧栏「运行环境」可统一选择仿真／真机，也可单独覆盖接待、通用执行、观察环境。「一键全…」会清除覆盖；「应用当前选择」保留覆盖。切换侧栏不会提交配置，未应用的表单选择仍保留。应用会检查在途任务并重启需要加载配置的本机业务服务，不重启 Redis，也不启停远端本体。接待选真机时同时打开真机动作许可，选仿真、协议模拟或停用时关闭；下游闸门仍可拦住派发。配置格式、命令行用法与能力边界见 [统一环境配置](../config/README.md#统一切换仿真与真机)。

## 三端启动与任务发布

本仓库的面板调用已按 `src/ops/dream_remote.py`、`src/ops/vla_remote.py` 核对。远端一键脚本内部顺序、人工闸门和停止范围沿用 2026-09-17～20 现场记录；本次文档合并未执行远端启动或真机动作，现场应核对所部署脚本的提示与版本。

### 地址与大脑服务

地址从 `config/networks.yaml` 的 `active` 网络及对应角色读取，不复制旧网段地址。默认端口为大脑 `5000`、网页 `8888`、面板 `5678`、DREAM `8001` / 审核页 `9882`、VLA `8091`，以生效配置为准。下文 `<大脑IP>`、`<导航IP>`、`<操控IP>` 应替换为当前配置；SSH 别名 `dream`、`gpu4090` 需事先配置。

1. 按上节启动面板，打开 `http://<大脑IP>:5678`。
2. 核对「运行环境」并应用本轮配置。真机接待以已应用配置为准，不沿用旧指南的 `RECEPTION_MODE` 单一判断。
3. 启动大脑卡片（服务 ID `master`，运行 `python -m brain`），再开启任务网页（`deploy`，运行 `entries.web`）；按需开启飞书和语音入口。启动命令及依赖安装统一见项目 README。
4. 仅使用 Slaver 执行路径时启动 Redis / Slaver；固定真机接待直连 DREAM / VLA，不依赖 Desk 或这些仿真执行进程。

大脑 HTTP 可用、入口已连接只证明本机服务运行，真机还需完成下列启动和现场确认。

### 导航一键启动与人工闸门

开始前由现场人员确认机器人有支撑、肩带挂好、急停可用，MID-360 视野及运动区域无人靠近。

面板 DREAM 卡片「启动」在导航机的 `<DREAM_ROOT>` 执行 `bash tools/g1_three_party_oneclick.sh start`，先静态检查，再自动输入 `READY`。脚本准备或复用 NX SONIC、相机、灵巧手，再启动 VLA HTTP / 导航 relay 和 DREAM 定位工作流。VLA 单独检查或重启见[操控接口说明](接口说明_操控VLA.md#操控侧检查与独立启停)，不重复启动控制器。

| 顺序 | 操作 | 完成判断 |
| --- | --- | --- |
| 1 | 等待一键脚本接收 `READY` | 面板日志进入远端启动流程；仍可能需要现场处理 NX 登录提示 |
| 2 | `adapter` 提示出现后，点一次「站立 Enter」 | 完成接管，保持肩带，等待 stage 1 稳定 |
| 3 | 下一提示出现后，再点一次「站立 Enter」 | 进入 POSE 站立；每次点击只发送一个 Enter |
| 4 | 站稳、现场解肩带并清空视野后，在导航机 `strap-check` 窗口回车 | 人工确认完成，定位和审核服务继续启动；面板不代确认 |
| 5 | 打开 `http://<大脑IP>:9882`，点初始位置、朝向并 Approve | 查看定位收敛和导航状态，确认其可接受本轮命令；面板不代点 Approve |

历史工作流的两次站立 Enter 和解肩带确认有 600 秒等待窗口，以现场提示为准。出现 `POSE ready file was not created; navigation remains locked.` 表示外层编排已退出，机器人能站立不代表 9882 已启动。恢复方法见下方故障表。

一键脚本运行在导航机 tmux `g1_panel_oneclick`，日志位于 `/tmp/fqplanner_dream_oneclick.log`；面板只跟随日志。面板重启或 SSH 断开不会带走该会话。人工接手可在导航机执行 `tmux attach -t g1_panel_oneclick`。不用面板时，在导航机执行：

```bash
cd <DREAM_ROOT>
tmux new-session -s nav 'bash tools/g1_three_party_oneclick.sh start'
```

脚本要求真实 TTY；手动启动仍需完成上述人工闸门。已有编排时先核查原会话，不重复启动。

9882 若只监听导航机 `127.0.0.1`，面板会建立转发，可点「打开 9882」。不用面板时可在大脑机执行 `ssh -L 9882:127.0.0.1:9882 dream`，从该机器访问 `http://127.0.0.1:9882`。

### 发任务前核查与执行

只读检查示例（先替换地址）：

```bash
curl --noproxy '*' -s 'http://<大脑IP>:5000/api/task_status'
curl --noproxy '*' -s 'http://<导航IP>:8001/v1/status'
curl --noproxy '*' -s 'http://<操控IP>:8091/v1/vla/control/status'
```

核对大脑当前任务、生效环境、导航定位及活动命令、操控依赖和控制权；存在未核清旧命令时先处理。各字段与动作前置分别见[导航接口](接口说明_导航NAV.md)、[操控接口](接口说明_操控VLA.md)。面板绿灯主要证明服务健康，不等同于任务可执行。

**当前 `/api/task_preflight` 只返回 `ready=true`、`required=false` 的兼容结果，不查询下游，不能用它作为真机就绪证明。** 当前实现见 `src/brain/api/facade.py`；具体动作仍可能被执行前检查或下游拒绝。

从 `http://<大脑IP>:8888` 发布任务，或按飞书入口规则提交。网页、飞书与语音文本入口分别直连大脑 `:5000`，飞书不经过网页进程。飞书 `dry_run` 只生成卡片，`active` 才提交。仅导航测试选择「开始接待（仅导航）」，不会下发抓放。

任务失败后保留原任务、步骤和 `command_id`，处理原因，再按[大脑任务控制规则](接口说明_大脑%20Brain.md#12-任务控制接口)使用暂停、继续、跳过或取消任务；完整按钮语义见该文档第 1.2 节。继续会核查原命令，并非从旧 `failed_phase` 无条件重发。取消任务只结束大脑编排，不代表机器人停止。

过程看大脑日志 `logs/YYYY-MM-DD/master/`，原始错误与完整记录按任务和命令关联。成功应以当前大脑核验规则为准；`hand_state_only` 不足以证明物体效果，不再沿用旧指南的 `COMPLETED_HAND_STATE_ONLY` 通过口径。

首次部署或链路变更时，分阶段保留证据：只读接口 → 导航至 table2 与 pick → 单独 place 的批准及收尾 → 完整接待。每个动作阶段须由现场单独组织，不代表当前网页已有这些分段按钮。具体测试结果按发生日期写入多端联调记录。

## 收工与故障处理

1. 确认任务结束、原导航或操控动作已停止，核清现场控制权。若仍在执行，通过任务暂停或对应端的停止流程处理，并确认结果；“取消任务”不能代替物理停机。
2. 在面板 DREAM 卡片点「停止」，调用一键脚本 `stop` 并收掉 `g1_panel_oneclick`。历史脚本只停止 DREAM 与 VLA HTTP / relay，保留 NX SONIC、相机和灵巧手；核对实际输出，不能据此认定机器人已坐下或断电。
3. 机器人坐下、控制器退出和断电由现场按导航侧已验证流程处理。旧记录中的 `g1_fixed_map_relocalize_navigation_workflow.sh shutdown-sonic` 未实跑验证，不列为本指南可直接执行的收工命令。
4. 按需关闭网页、飞书、语音入口和大脑；如使用 Slaver / Redis，先停使用者，最后停 Redis。面板可保留运行。单独停止 VLA 的范围见[操控接口说明](接口说明_操控VLA.md#独立停止)。

| 现象 | 核查与处理 |
| --- | --- |
| 9882 打不开 | 查看编排、人工闸门和远端监听，再核查面板隧道；不能只凭 `connection refused` 判定定位问题 |
| `POSE ready file was not created` | 核查是否超过人工确认窗口；在导航机 `<DREAM_ROOT>` 先执行 `bash tools/g1_three_party_oneclick.sh stop`，再执行 `bash tools/g1_three_party_oneclick.sh resume`；按原现场记录 resume 只重起 DREAM，不重起 SONIC / relay / 相机 / 灵巧手，先核清保留组件状态。面板未提供 resume 按钮 |
| SONIC 或 safety attestation 失败 | 检查控制器是否就绪及启动顺序，查原始 blocker；不要仅凭历史已修复记录假定本次通过 |
| 8091 在线但不可执行、place 等待、VLA 停止被拒绝 | 按[操控独立操作](接口说明_操控VLA.md#操控侧检查与独立启停)核查依赖、原命令及人工批准 |
| 面板导航日志停更 | 查看导航机 `/tmp/fqplanner_dream_oneclick.log` 与原 tmux；刷新面板重建 follower，不因显示断开重跑任务 |
| SSH 校验失败或命令被拒绝 | 核对当前网络、角色地址、SSH 配置和原始错误；任务拒绝原因以返回报文为准，不一律归因于预检 |
