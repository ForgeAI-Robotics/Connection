## 问题与闭环

### 迁移与配置隔离

迁移时原任务 `7f05d4b1e9d34accbe3128dd4b74ed46` 暂停，原导航命令仍未知。停写、模型验证和入口检查前后任务哈希保持，没有自动继续、跳过、取消或补发。旧实例与目标旧目录保留恢复依据，不能把旧账本覆盖迁入的当前状态，也不能同时开启两套入口接受同一业务任务。[D2](#e-d2)

发现的 Slaver `.env` 路径错误已改为统一工作区解析；配置隔离将本机 YAML／凭据与公开模板分开。首次升级备份、来源哈希、原修改的恢复和 Git 同步证据保留在原记录。原无显示探针失败不能被默认 3DGS 相机检查覆盖；启动健康不能代替本体动作就绪。

### 就绪检查与旧命令

10-16 启动前只读检查中，原命令查询 404／`UNKNOWN_COMMAND_ID`，同时导航没有活动命令；两者不能合并推断为旧动作未执行或机器人已安全停止。任务仍阻塞新动作，未清账本解除阻塞。[D3](#e-d3)

接口预检曾返回通过，但导航实际运动门禁、定位和操作者批准不满足；操控也报告策略／真实后端及相机未就绪。首点 table2 的 Y 配置与参考声明相差约 0.40m，告警不是重新标定或放行证据。温度数值和临时门限仅是当时回包，不代表当前温度或厂家标准。

### 网络与端到端时延

10-16 主采样导航状态 P95 约 6.18 秒，补测有 10 秒超时；16:53 轮保留 18/120 超时。后续 17:41 旧／新机同接口比较 240/240 成功，但请求来源与路径已不同，不能据此重写早期结果。

18:45 的真机 NX 与服务器双向对照包含 400 次正式 HTTP 和 200 次 ICMP，零超时／丢包；每方向每指标 50 对配对样本。服务器使用有线接口时，网络往返中位数约减少 2–3ms，轻量 HTTP 约减少 5–6ms；完整状态查询收益较小。**NX 本身仍通过无线连接**，不能称全链路有线或全部业务提速同一比例。[D4](#e-d4)

状态查询还包含服务处理及操控端对导航的内部调用，不能用健康请求代表交接或控制时延，也不能简单相减两个独立中位数求转发开销。云端大图片上传与模型等待另见[模型本地／云端对照](多端联调_模型接入与评测.md#本地与云端)，不在本文复制模型性能表。

## 待验证事项

- 真实业务时延应同时记录来源、路径、载荷、并发、版本、采样窗口与后台负载；HTTP、ICMP、模型推理和动作完成分开。
- 新部署先核实磁盘版本、实际进程、配置和原任务，不能从一次健康查询推断所有运行端已升级。
- 旧命令、定位、现场批准、操控能力和图像证据按当前状态复核；本次整理未重新做现场检查、迁移或服务重启。
- 同一问题复验时说明条件变化和未隔离因素；保留早期超时和失败，不只留下最快一轮。
