发生日期：2026-10-16。主运行端从原大脑机迁至 SSH 角色 `gpu-nav-AI`。
本轮授权为迁移并达到可直接使用的大脑服务；未恢复原任务或下发机器人动作。

## 1. 版本与迁移范围

源代码基线为 `73204eb`，目标旧基线为 `2459bf9`，两版本相差 135 个文件。
先建立隔离副本，复用目标已适配的 Python 3.10.18 core／GPU 环境和仿真资产，再同步当前源码与配置。
目标保留自身 CUDA／渲染环境，补装源机已有的 `pyrender==0.1.45`，没有覆盖整个虚拟环境。

用户随后明确不需为可用大脑搬运大文件：迁移任务账本、记忆、飞书数据库、任务时间线、运行环境快照和必要运行资源，
共 983 个文件、48,422,612 字节；历史实验视频、旧验证副本、历史备份和旧日志保留在源机。
目标既有日志与配置保存在旧目录中，不混入当前任务账本。

地址仍以 `config/networks.yaml` 为唯一角色来源：目标大脑、操控角色适配新机账号与地址，导航角色保持原端。
`VLA_REMOTE_DIR` 指向已经迁入目标工作区的 VLA 桥接目录；SIMPLE 地址沿源机当前配置。
凭据只进入目标私有 `.env`，不进入源码或本文。

## 3. 发现的问题与修复

- 两机间传输出现严重重传及间歇 SSH 超时。保留源服务运行，缩小传输为代码与必要状态，采用压缩增量后完成。
- 原 Slaver 工具模块将 `.env` 路径算到旧源码层级。新机独立启动检测到模型凭据仍为未展开占位符。
  修复为复用 `shared.paths.workspace_root()`，沿统一工作区读取 `.env`，保留显式环境变量优先级。
  新增从工作区外启动及显式环境覆盖的两个回归用例，部署后重新启动 Slaver，凭据展开与 `FQrobot` 注册均通过。
- 独立 `pyrender` 无显示窗口探针遇到 `NoSuchDisplayException`；这不作为可选合成渲染通过证据。
  面板默认 3DGS 路径使用 `--no-composite`，其检查与上述可选探针分开记录。
- 最初源机回归受执行沙箱的本地套接字限制阻塞，已停止该测试进程；后续在允许本地假服务的环境重新完成，
  不将受限运行记为通过。
