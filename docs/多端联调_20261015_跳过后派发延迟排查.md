## 大脑阻塞机制与离线复现

`BrainService._drive()` 在调用 `runtime.drive()` 后仍同步调用 `_advise()`。
应用通过 `owner.wait(planner.submit(...))` 等待模型；`RuntimeOwner.wait()` 期间只处理控制队列，
不执行普通工作队列内的新 `_drive`。因此跳过接口可以返回受理，下一段却未被派发。
旧建议返回时会经过版本校验，但版本校验不能解除此前已发生的等待。

离线复现使用现有 ReasoningIntegrationTests 的临时账本与 FakeBody，通过 Event 阻塞异常建议：
人工跳过返回 accepted=true，状态 running、步骤已到 relay2，FakeBody 只有原 table2 一次提交；
释放模型等待后立即出现 relay2 提交。该复现未联网、未连接真实模型或机器人。

## 导航两次失败原文

首次，`NAVIGATION_EXECUTION_FAILED`：

```text
9882 rejected /set-agent-world-goal: HTTP 400: {"error": "terminal correction scan coverage is insufficient; largest_gap_deg=45.5"}
```

导航认为末端修正扫描覆盖不足，最大角度空缺 45.5°，并非大脑拒绝导航。

第二次，`NAVIGATION_TERMINAL_UNREACHABLE`：

```text
9882 rejected /set-agent-world-goal: HTTP 400: {"error": "terminal correction has a live nearby obstacle; holding stand; nearest_m=0.209, angle_deg=-172.5, near_returns=4, required_m=0.450, scan_age_sec=0.095, frame=base_scan"}
```

`terminal_heading_recovery_requires_replan`，距目标约 0.417 m。实际障碍来源需导航核对扫描，不能仅凭回包判断为人或噪声。
