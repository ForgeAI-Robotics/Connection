# 接口说明：机器人统一网关

> **2026-10-28 当前新增接线：** `body_control.mode=source_gate` 使用下述接收源开关；原联合模式以 `mode=unified` 保留。两者不可混用。后续第 1—16 节是联合控制合同和历史验证，不是 source_gate 的调用前置条件。

## SONIC 接收源开关（source_gate）

NAV／VLA 数据直连 SONIC，网关只认证大脑指令并调用 SONIC 本机开关。SONIC 新进程默认 navigation，网关重启不改变选源；同源设置不重置、不重连，换源隔离旧来源全部消息及待处理缓存。网关不做身体、任务或运动模式检查；O6／手部 CAN 不在此开关范围内。远端交付正文：NX `/home/dev/workspace/g1_robot_gateway/SOURCE_GATE_API.md`，2026-10-28 已通过 SSH 只读核对；该文件不在本仓库。

沿用原 HTTPS 地址、CA 与大脑 Bearer 凭据。合同 `g1/source-gate/v1`：

| 接口 | 请求／回执 |
| --- | --- |
| PUT `/v1/input-source` | `request_id`、`source=navigation/vla/none`；可绑定 `receiver_instance_id`。只有 `state=applied` 才生效 |
| GET `/v1/input-source` | SONIC 当前 `receiver_instance_id`、`effective_source`、`revision`、`pending_requests`、`data_forwarding=false` |
| GET `/v1/input-source/requests/{request_id}` | 原操作；pending／unknown 只查询原请求，不换 ID 补发 |

设置示例（仅展示协议，不代表发出操作）：

```json
{"request_id":"brain-select-vla-001","source":"vla","receiver_instance_id":"<当前 SONIC 实例 UUID>"}
```

HTTP 200 示例：

```json
{
  "contract_version": "g1/source-gate/v1",
  "request_id": "brain-select-vla-001",
  "source": "vla",
  "receiver_instance_id": "<当前 SONIC 实例 UUID>",
  "state": "applied",
  "changed": true,
  "effective_source": "vla",
  "revision": 1
}
```

request_id 为 1—128 位字母、数字或 `_.:-`，新意图用新 ID；不确定请求沿原 ID 查询。同源设置 changed=false、revision 不变、不清缓存；真正换源／全关才增加 revision，并由 SONIC 在接收隔离边界处理旧输入和队列。屏蔽期间的积压不补执行。消息 topic 不是来源身份。

| HTTP／回执 | 处理 |
| --- | --- |
| 200／applied | 接收端已确认；不等于动作完成、模式恢复或身体停稳 |
| 202／pending、unknown | 先查原 request_id；不换 ID 自动重发 |
| 400／401 | 请求字段无效／认证失败；NAV、VLA 角色 token 无权代替大脑操作 |
| 409／REQUEST_CONFLICT | 同 ID 不同请求；保留冲突，不能覆盖旧操作 |
| 409／RECEIVER_CHANGED | 绑定的 SONIC 实例已改变，不能复用旧回执作为新实例证明 |
| 503／RECEIVER_UNAVAILABLE | SONIC 管理端不可用，不返回缓存成功 |

查询原操作时，相同请求的历史回放可带 replayed=true；不会重新执行原选源。未确认操作遇到 SONIC 重启返回 unknown／RECEIVER_RESTARTED，不自动转交新实例。已确认历史成功也只说明当时状态，当前来源另查 GET。网关自身重启恢复记录，不自动关开；SONIC 自身新进程才恢复默认 NAV。

同 ID 同请求返回历史回执，不重新执行；历史 applied 不能代替当前状态。实例改变、回执身份不符、仍 pending 或接收端不可达时，不凭旧成功派发。SONIC 未运行返回 `503 RECEIVER_UNAVAILABLE`；原 `/v1/body-input/*` 不再由此模式提供。关闸只表示输入已屏蔽，不证明身体停稳。

**当前大脑范围：真实 NAV、direct-v1 VLA，以及原两个模拟混合变体。** `reception_real.body_control.enabled=true, mode=source_gate` 使用现有 gateway URL／CA／token 配置；NAV 仍用 nav_token_env。无需旧 robot_serial／action_endpoint／permit_mode 来组织准备。大脑在每条 NAV 派发前读取当前来源，已是 navigation 则不 PUT；需要切换时先持久保存原请求、绑定接收实例，核清 applied 和当前状态才发目标。没有 NAV prepare、grant、allow_execute、身体保持或旧控制会话门禁。NAV 原业务字段与 Bearer 保持，不附加 control_authorization／联合会话字段。真实 VLA 业务及持物结果消费已接入，具体字段和边界见[direct-v1 操控接口](接口说明_操控VLA.md#direct-v1直连操控与接收源选择)；本地模拟操控不切到 vla。

**取消与恢复：** Runtime 先结束本地编排，沿现有工作器通知原 NAV／VLA cancel 并设置 none；两个结果分别保存。NAV 取消结果不明只查原 command_id，选源不明只查原 request_id，不重放旧指令。取消后的历史停止／关闸未知只保留为证据，不阻止新任务发布或导航派发。新导航按 SONIC 当前选源结果与 NAV 自身接单条件执行；未确认的实际选源操作仍按原请求查询，历史成功不能冒充当前来源。旧收尾与新派发使用同一 I/O 锁，排队的旧收尾发现当前任务已变化时只标记 superseded，不再发送旧 cancel 或全关；不伪造 stopped／completed。收尾失败时原 `/api/task_control_recovery` 可重新查询：task_id 与 expected_lease_id 都填原取消任务 ID；已完成收尾不重新关闸。旧接收实例未确认的选源记录保留 unknown，新实例不会重放它。无周期续期或新的业务执行循环。

控制 I/O 复用原 `body_control.json` 的 source_gate 扩展，保留原 leases／requests 及错误；不删除旧账本来放行。新任务的 execution_target 绑定模式和端点，旧联合任务不能通过改配置静默恢复到新接线。源码与私有配置已应用并重载大脑，运行状态已确认 source_gate；已开展 NAV 和 VLA 真机尝试，但完整接待未通过。离线证据见[接收源适配验证](多端联调_大脑任务与恢复.md#brain-source-gate)。

## 1. 本版决定了什么

**大脑唯一发权，机器人独立网关统一放行，执行方按任务发流；身体和手部共同服从同一任务授权。**

```text
任务链：大脑 ──登记／准备／执行／取消──→ NAV、VLA
授权链：大脑 ──签发／续期／撤权──────→ 机器人独立网关
                                           └──手部许可／封禁──→ O6 服务
数据链：NAV ──本机 ZMQ──→ 网关 NAV 输入 ─┐
                                       ├→ 单一本机输出 → SONIC → 身体电机
        VLA ──网络 ZMQ──→ 网关 VLA 输入 ─┘
        VLA ──手部数据───────────────────────────────→ O6 → CAN → 双手
反馈链：执行方、网关、SONIC、O6 的原始身份和证据最终汇总给大脑
```

图中身体／手部为逻辑分流，不要求把现有 VLA pose 消息拆成两个发布器。可以保留同一消息中的身体和 O6 字段，由不同接收方分别验证与消费。

与旧提案的区别必须统一：

| 方案 | 本版处理 |
| --- | --- |
| 工作站旧 relay；relay 与 VLA 轮换发布端口 | 正式新链路退出，不启动、不保留运行时兼容分支 |
| SONIC 同时直接订阅 NAV、VLA 两个发布端 | 不采用；双源接入和选择放到机器人网关，SONIC 保持一个正式数据入口 |
| 独立接收管理服务只管理、不转发 | 更新为独立统一网关：管理接收会话，同时转发获准身体流 |
| NAV／VLA／网关周期性查询大脑全局授权 | 新链路改为大脑主动向网关签发、续期、撤权；发布端不再周期性查询全局归属 |
| 两个发布器无任务也持续推进动作 | 不采用；连接可保留，但无任务不发业务运动流，准备与执行严格分开 |

移除旧 relay 不等于删除停止、会话隔离和保持核验。网关转发不修改运动内容，不重标旧帧，不为不合法数据补身份。回退通过完整旧发布版本完成，不在新代码同时维护两套通路。

## 2. 谁负责什么，优先复用什么

| 负责方 | 职责 | 复用边界 |
| --- | --- | --- |
| 大脑 | 唯一任务和授权权威；登记命令、推送许可、组织交接、取消与恢复、汇总证据 | 原 Runtime、BodyControl 及任务／授权账本；不转发高频动作帧 |
| 导航 | NAV 发布器、机器人网关和 SONIC 配套接收／退出；构建与启动管理 | 导航算法、本机 PUB、会话封装、native prepare／activate／fence／retain 和日志；不另作授权裁决 |
| 操控 | VLA 任务生命周期、准备参考、执行与停止；O6 接收端许可、CAN 写入与保持／持物证明 | 原模型、RTC、pose 数据格式、O6 驱动及反馈；不另建手部抢权账本 |
| 网关 | 认证两来源和大脑指令，安装有期限许可，选择与封禁流，协调 native／O6 操作 | 可复用旧 relay 的 ZMQ 收发、会话过滤和原操作留痕；不照搬自动扫描发布进程、共享端口争用和反向授权轮询 |
| SONIC | 单一输入的会话检查、模式采用、内部缓存隔离、身体控制、断流与保持 | 保留现有控制策略和本地保护，不按每帧远程 HTTP 决策 |

网关有自己的当前许可、会话绑定、撤销标记和操作回执，这些是大脑决定的执行记录，不是第二个全局授权账本。O6 的执行许可同理，不能独立批准另一份任务。

最小实现原则：先保留原帧格式和控制算法，替换发布端点、交接适配及准入条件；复用现有 worker 与事务日志，不再增加一套接待执行循环。

## 3. 接线、认证与独立生命周期

### 接线候选值

以下为待三端确认的接线，不是现场已应用配置。实际主机地址只从现有网络／机器人 profile 解析。

| 项目 | 暂定 |
| --- | --- |
| NAV PUB | 机器人本机 `tcp://<NX_IP>:5556`；若确认无需对外订阅，可统一改为 loopback，但三端配置须一致 |
| VLA PUB | 工作站 `tcp://<WORKSTATION_IP>:5556` |
| 网关输入 | 两个独立 SUB，分别连接上述来源，不混入无法区分连接来源的 socket |
| 网关 PUB | `tcp://127.0.0.1:5558`，须检查本机端口冲突 |
| SONIC SUB | 只连接网关本机输出，不再直接连接 NAV、VLA 或旧 relay |
| 网关管理 HTTP | 机器人独立服务，暂定 `18001`；不位于 NAV 业务服务 `8001` 中 |
| O6 管理 | 优先扩展现有私有 Unix IPC；具体操作映射由操控补齐，不为本草案先新增端口 |
| O6 数据 | 可继续订阅 VLA 的原 pose 源；写 CAN 前独立检查同一授权下的手部许可 |

两个输入主机不同，均用 5556 不冲突；网关本机输出与 NAV 本机发布必须使用不同地址／端口，禁止形成回环。

来源身份不能只靠端口、IP 或帧内自报的 source。暂定复用标准 ZMQ CURVE：网关固定核验两个 PUB 的不同来源密钥；VLA PUB 的订阅白名单需要同时考虑网关与受管 O6，不能只允许旧 SONIC 客户端。SONIC 只承认本机网关来源，O6 只承认配置的 VLA 数据来源及网关控制凭据。C++／Python 构建能力、凭据角色和密钥部署由三端确认；不得用“能连上”冒充认证通过。凭据不进入普通状态回包、示例和源码。

独立生命周期规则：

- 网关有独立进程／服务单元，不放在 NAV 或 VLA 的子进程树、随其删除的 tmux session 或共用服务单元中。
- 停止／重启 NAV 只处理 NAV；VLA 正在执行时，不能替换 SONIC、重启网关或封禁 VLA。
- 版本不匹配时拒绝新的接管，不为了启动 NAV 擅自打断已有 VLA 会话。
- 网关故障影响当前运动输入，但不能关闭 SONIC 或清空手部参考来“恢复”；SONIC 断流保护与 O6 本地有效期独立生效。
- 同主机恶意进程隔离能力不因本提案自动增强；正式旁路必须关闭：身体数据只经网关，手部业务只经受管 O6 服务写 CAN。

## 4. 身份与授权对象

暂定 `contract_version=fq/vla-handoff/v1`，新修订候选为 `20261027-robot-gateway-push-draft1`。它不同于早期 `20261027-direct-dualsource-v1`；大脑与导航先冻结 NAV 阶段的共同修订、支持范围和字段后启用，VLA／O6 接入时再核对扩展兼容性，不能混接或仅凭修订字符串宣称支持完整三端功能。分阶段边界见第 14.1 节。

| 字段 | 生成方／语义 |
| --- | --- |
| `robot_serial / control_resource` | 固定机器人和唯一身体控制资源，例如 `g1:EXAMPLE_ROBOT:body`；两来源共用一个 owner／epoch 序列 |
| `task_id / command_id` | 大脑的原任务和本次命令；业务重试按原 Runtime 规则生成新命令 |
| `control_authorization` | 原 `lease_id / authority_id / ownership_epoch` 三元组，仍由大脑签发 |
| `source_id` | `navigation` 或 `vla`；必须匹配调用角色、来源连接、任务及授权 |
| `publisher_instance_id / input_session_id` | 执行方在本次发布生命周期生成；先返回给大脑，单次绑定，重启或重新接管不得复用旧会话 |
| `gateway_instance_id / controller_instance_id / o6_instance_id` | 实际进程／控制器身份，由目标端报告；不能只凭配置填写 |
| `action_endpoint` | 对应发布源地址，不是控制权资源键；请求只能匹配 profile，不准临时指定任意地址 |
| `permit_seq` | 大脑在本授权内单调递增的许可消息序号；涵盖签发、升级、续期、撤权，拒绝 bool、倒序和同序号改内容 |
| `request_id` | 每次操作的唯一身份；同 ID 同内容查原回包，同 ID 改内容冲突；不同操作不得复用 |
| `phase` | `prepare` 或 `execute`；准备许可不能放行业务运动 |
| `hand_mode / hold_reference_id` | 手部业务或只保持的限制与原参考；NAV 不获得手部开合权限 |

标识符沿现有三端可接受集合统一；会话暂沿用 32 位小写十六进制。controller 保留合法 `boot UUID:PID:start_ticks`，发布和管理进程必须有可区分重启的实例标识。

同一资源最多一份可执行授权。许可撤销不等于资源已空闲：退出未核清时大脑仍保留收尾占用，不给下一源签发执行许可。

## 5. 任务登记、准备、执行与数据发布

| 执行方阶段 | 发布行为 | 网关／接收端行为 |
| --- | --- | --- |
| 无任务 | 不发布业务运动帧；连接可以保留 | 无许可就不放行，不因连接存在自动选源 |
| 会话已登记 | 创建发布实例和 session，返回身份；不推进任务动作 | 尚未授予准备许可时不接纳本轮数据 |
| 准备中 | 只发本任务 IDLE／保持参考帧，持续发送以等待真实接收 | 只允许获准来源的准备帧；native 接收准备态不等于激活或业务开始 |
| 已准备／等待执行 | 维持准备参考，不从模型轨迹中间取一帧接管 | 核验实际新鲜帧、参考、身体和 O6；尚未获得执行许可不放行业务数据 |
| 执行中 | 按任务发布运动流，目标频率沿用原方案 | 本地校验许可、会话、序号和阶段后转发；不在每帧等待 HTTP／SSH |
| 取消／结束 | 停止推进动作，按退出流程封禁并停止本会话发布 | 封禁旧流，完成 native 缓存隔离及 O6 退出；保持不依赖旧业务继续发帧 |

本版要求把“返回会话身份”与“完成整次准备”分开。优先扩展原任务接受回包／原请求进度查询，在正式准备效果之前返回 publisher/session；是否需要新的登记路由由 NAV／VLA 给出最小适配，不先建立第二套任务系统。

NAV 原外层 prepare 仍可聚合 native prepare、准备帧核验和静止 activate；**若复用它登记会话，必须先异步暴露会话身份，大脑才能推送准备许可，不能等全部准备成功才返回身份。** 若采用独立登记入口，则先登记、再 grant、后调用 prepare；具体 HTTP 映射按第 14.1 节冻结。大脑不再另外重复调用一次 NAV activate。

VLA 复用原任务 worker 的准备／暂停／激活能力，但从“准备完成”进入业务运行必须等待大脑的明确 execute 指令及已生效许可。现有 `/finish` 是效果确认，不能改作 execute。该命令的路由及原有 resume 能否复用由操控确认。

准备许可不是对某个 topic 的无限放行：网关必须依据可信的准备参考校验内容，不能仅相信帧自报“IDLE／准备”。native 静止 activate 后、execute 许可确认前仍只能维持该参考；NAV 业务 goals 和 VLA 轨迹推进均保持关闭。准备帧内容无法验证时继续拒绝，不把另一条流的当前动作截取为准备帧。

## 6. 暂定管理接口

以下均为待实现合同。保留 NAV 业务接口和大脑任务入口；共用网关路由沿导航草案命名收敛，减少重新设计。

| 接口 | 调用方 | 暂定用途 |
| --- | --- | --- |
| `POST /v1/body-input/permits` | 仅大脑 | `grant / renew / allow_execute / revoke`；这是本版替代网关反查授权的新增入口 |
| `POST /v1/body-input/operations` | 按角色授权的大脑或执行方 | `prepare / activate / fence / retain`，管理网关与 native 接收效果，不签发 owner |
| `GET /v1/body-input/requests/{request_id}` | 大脑及获准查询本关联的执行方 | 统一查询许可／接收操作原结果；包括拒绝和未知，不重做效果 |
| `GET /v1/body-input/status` | 大脑、NAV、VLA | 能力、当前绑定、有效期、接收／转发计数、分项准备／退出证据和实例 |
| NAV 原 prepare／yield 及任务查询 | 大脑 | 保留外层准备和退出聚合，底层接入网关；不再操作工作站 relay |
| VLA 原任务提交／停止／效果确认／查询 | 大脑 | 保留任务语义，适配阶段授权和 O6；不自行批准本轮控制 |
| 大脑原 lease 查询、acquire／release | 按最终角色限制 | 保留账本和原事务能力；新链路不靠执行方周期查询维护通行许可。执行方单次回调若复用这些路径，只能关联同一命令，不另发第二份许可 |

停止和原请求查询不能要求旧执行许可仍有效。查询权限由服务身份及原关联决定；否则撤权后将无法查询退出证明。执行方只能操作自己的关联，大脑可以明确指定目标撤销，不提供无目标的“随便停当前 owner”。

本版正常流程由大脑收到会话登记后发起授权，不以 VLA 先完成旧 acquire 为生成 session 的前提。操控应去掉这条前置等待；原 release 若保留为单次退出通知，也必须先有真实退出证据，由大脑核销授权。单次回调的具体保留范围在第 14 节冻结，不改变第 10 节的依赖顺序。

### 许可操作语义

| 操作 | 要求与确认范围 |
| --- | --- |
| `grant` | 大脑已登记本命令并核清旧占用，目标实例、来源和会话确定；只建立 prepare 许可，禁止直接赋予业务执行 |
| `renew` | 同一已生效绑定、同一阶段，序号更新且未过期／撤销；不得换源、换会话或偷偷升级到 execute |
| `allow_execute` | 当前 native 已采用合法准备参考，所需身体／O6 证据通过；网关及 O6 对应执行许可确认后才 completed，大脑随后通知源端开始业务 |
| `revoke` | 立即将目标许可置为不可再用并记录撤销，触发身体与手部封禁；不等待发布端、模型或长效果操作。许可已撤销不代表身体／手部退出已确认 |

大脑发送成功不等于接收方已安装许可。grant／renew／allow_execute 的 pending 或 unknown 都不能当作生效确认。执行许可部分安装失败时保持源端未执行并封禁该次会话，不自动重新打开；原有保持参考不清零。

### 接收操作语义

| 操作 | 要求与确认范围 |
| --- | --- |
| `prepare` | 与大脑已经推送的 prepare 许可一致；绑定唯一会话、清除旧输入缓存、建立准备接收态。completed 不证明准备帧已收到 |
| `activate` | 同一绑定与有效许可，新鲜准备帧和参考匹配，native 确认采用。仍维持准备参考，未获 execute 许可不得推进业务 |
| `fence` | 目标许可可以已撤销；优先停止转发并完成 native 接收隔离、缓存失效及旧 session 退休。它不等于身体／O6 保持已完成 |
| `retain` | 原关联的停止／参考退出步骤，不激活任何输入；复用 native 已有机制，具体字段映射由导航确认 |

大脑取消和执行方退出可能同时触发 fence；网关按目标关联合并已发生的封禁与收尾，分别保留请求回执，不重复执行 native 效果。fence 自动停止／保持与显式 retain 共享原子步骤记录。封禁不能排在等待首帧、授权、激活的长操作后面；GET 不触发新效果。

## 7. 有期限的主动推送与续期

**已经决定的是主动推送和本地到期封禁；以下具体时效协议与数值为本版暂定，NAV 阶段先由大脑与导航冻结，O6 派生许可随后续接入核对。** 不再同时保留“网关周期查询大脑”的正式分支。状态查询只获取事实，不授予或延长权限。

暂沿用每 1 秒一次续期、单轮控制往返预算 500 ms、许可最长 1.5 秒作为评审基线。高频转发独立执行本地校验；这些不是身体停止时延承诺。大脑实际停止续期后，网关和 O6 不能无限沿用最后一次许可。

主动推送不能简单使用“收到消息时刻＋1.5秒”，否则积压的旧续期可延长权限。本稿暂定复用 status 获取一次性**网关时效锚点**：

1. 大脑以新 observation_id 请求 status；网关返回 gateway_instance_id、一次性 challenge_id 及本机创建时间。锚点本身不授权，也不执行动作。
2. 本轮 grant／renew／allow_execute 回显 freshness_ref。网关查自己保存的锚点计算截止时间，不能相信发送方自填的本机时间；只接受本实例、未过期、未消费的锚点。
3. 暂定锚点到接收许可的窗口不超过 500 ms；`valid_until = 锚点本机创建时间 + min(请求有效时长, 1500 ms)`。延迟只会缩短剩余时间，不把截止时间向后重标。
4. 请求重传或原结果查询只返回原期限，不再次消费锚点或延长期限。过期、撤销和退休状态不可被续期复活，重新接管使用新 epoch 和 session。
5. 网关给 O6 的业务许可截止时间不得晚于对应上游许可；同 NX boot 可使用同机单调时钟。实例／boot 不一致时拒绝沿用，不比较不同主机 monotonic。

该暂定方式每轮需要一次轻量 status 和一次推送，不是每帧访问，也不是网关反查大脑。若三端选择有明确时钟误差上界的绝对到期方案，必须在冻结前替换本节并给出测试；不能各端自行理解 TTL。revoke 不需要等待新时效锚点，先按认证及目标关联封禁。

所有许可消息同时核验 authority、epoch、permit_seq、目标实例、来源、命令和 session。即使 renewal 先发后到，只要撤销已生效或版本过旧，就不得恢复转发。大脑与网关换实例后默认无执行许可，不能仅恢复磁盘数据就恢复执行。

网关许可／接收操作及 NAV 外层交接的共同回执统一为以下四态；NAV goals 的原业务任务状态和大脑内部账本状态保持原合同，不机械替换为这四个值。旧端或 native 的原始失败状态和错误仍保留在证据中。

POST 202 携带 pending；完成或已进入执行的未知结果通过 200 查询并检查 state；可识别的明确拒绝落盘 rejected 并保存首次 HTTP 错误。进入操作后发生的失败不得伪装成受理前拒绝，须保留明确失败的原子步骤及已发生效果。404 UNKNOWN_REQUEST 不证明未执行。请求冲突不覆盖原记录，通信异常后仅查原 ID。大脑授权查询若保留，state、owner、authorization_current 必须同一快照且一致。

## 9. O6：业务动作与只保持分开

| O6 模式 | 准入与允许行为 |
| --- | --- |
| execute | 身体授权属于 VLA；手部许可、实例、命令、session、序号、期限匹配，允许更新业务开合目标 |
| hold | 拒绝新的业务目标，只维持已确认保持参考；允许身体交给 NAV。必要的闭环保持写入不等于恢复旧 VLA 任务 |
| unknown／fault | 不接收新业务动作，明确报告反馈、保持或实例异常；不伪造持物成功，不默认张手、归零或关闭驱动 |

准备阶段在 hold 限制下接收／核验保持参考，身体和手部均准备通过后才升级执行许可。网关许可未生效、源指令已取消或会话已封禁时，VLA 不得推进轨迹等待中途接入。

操控侧优先扩展现有 O6 bind／activate／fence／status／request，补齐许可截止时间与明确可查询的转入保持操作；实际操作名由操控在冻结前反馈。网关通过受认证的本机管理通路下发权限，O6 在接收及 CAN 写入前本地检查；不只在网关做一次检查。

保持回执至少给出原任务／抓取命令、controller 和 O6 实例、hold_reference_id、已采用目标摘要、双手实际反馈、采样年龄、旧业务会话封禁状态，以及独立 holding_evidence。不得把“目标没变”当作“已抓稳”。

抓取结束后先确认原目标和反馈，锁定保持参考，封禁旧 VLA 业务会话，再授权 NAV。持物证明继续关联原抓取记录，不恢复旧 VLA 执行权。反馈过期或参考被改变时，NAV 的持物条件必须重新检查，不能自行延长旧物体证明。

取消／过期发生在动作中途时，操控的本地停止策略决定如何保留当前有效参考，不能一律退回初始姿态。没有可核验参考时如实报告 unknown／fault，不通过大脑填一个 hold=true。新 VLA 授权和新会话准备完成后才能解除只保持限制。

## 10. 全流程与大脑的通过条件

### 正常开始

1. 大脑只读检查网关、SONIC 和 O6 的实例、构建、配置与当前退出／保持；无有效 owner 是正常初始状态，不要求“先有授权才算服务可用”。
2. 大脑创建任务并要求执行方登记本命令的发布实例和 session。执行方返回身份，不执行任务动作。
3. 大脑推送 prepare 许可并确认安装；执行方调用共用 prepare，持续发送合法准备参考帧。
4. 网关验证来源、许可和准备内容，再转发至 SONIC；等待真正接收及参考匹配。VLA 同时完成 O6 准备。
5. 执行方通过网关完成 native 静止 activate，维持准备参考，报告真实控制采用和身体／手部就绪。
6. 大脑发送 allow_execute，确认网关与相关 O6 执行许可已生效，再向源端发业务执行指令。NAV 正式 goals 是业务开始，不重复 native activate。
7. 续期从第 3 步 prepare 许可确认安装后即纳入调度，覆盖准备、静止激活等待和执行阶段；不等业务开始才续期。续期只延长当前已确认阶段，不能替代 allow_execute。具体周期及失败处理按冻结后的第 7 节执行；源端和网关高频路径不等待远程授权 HTTP。任务结果和现场证据仍通过原查询路径核验。

### 正常切换与取消

大脑停止后续派发、撤销当前许可，并行通知源端停止与网关封禁。网关隔离身体流并触发 native 退出，同时要求 O6 封禁旧业务输入、保持参考；任何一路停止不等待另一路 HTTP 超时。只在当前退出条件通过后结束占用、准备下一源。

| 判定 | 必须具备的证据 |
| --- | --- |
| 服务可用于准备 | 匹配版本与实例、配置及来源认证可用，当前接收隔离、可信保持参考与必要反馈成立；不要求已有业务许可 |
| 准备完成 | 绑定原身份、实际收到合法新会话准备帧、参考匹配；原子 prepare completed 本身不够 |
| 可以开始业务 | 当前有效 execute 许可、native 已采用本会话、源端准备完毕、身体保持和所需 O6 条件通过 |
| 旧授权可以结束 | 旧许可不可再生效、旧会话与缓存隔离、无未隔离的在途效果、身体停止／保持、O6 业务封禁及所需保持／持物证据通过 |

源端发布已关闭应单独报告。源端失联时允许使用可靠的当前接收隔离、旧会话永久退休、身体／手部保持和许可失效证明恢复，不把 source_output_fenced=unknown 改为 true。旧动作结果可以继续 unknown，但不能仅因历史 unknown 永久占用；也不能仅因许可过期、端口关闭就宣称身体已停。

## 11. 故障、重启与迟到结果

| 情况 | 处理 |
| --- | --- |
| 准备前取消 | 大脑记录取消并撤销目标；网关记住封禁，后到登记／prepare／续期不得恢复会话 |
| 准备中取消或 activate 并发 | 优先封禁；隔离屏障和自动保持不排在长操作后；迟到成功仍不能重新打开输入 |
| 许可推送／续期失败 | 不把未确认推送当作已安装；按既有许可截止时间封禁。过期后不自动续活同一会话 |
| 当前发布端故障 | 网关无合法新帧及 SONIC 断流保护分别生效，不无限重复最后一条运动；不自动切另一源 |
| 闲置 NAV 服务故障 | 不影响当前有效的 VLA 会话；不得连带关闭网关、SONIC 或 O6 |
| 网关故障／重启 | 停转发；SONIC 本地断流／会话隔离兜底，O6 本地许可到期进入退出／保持。新网关实例默认无许可，原记录只用于恢复 |
| 大脑重启 | 换 authority 实例；原推送窗口到期或显式封禁，新大脑先核查现场和旧占用，不恢复磁盘中的旧执行权 |
| SONIC／O6 重启 | 新实例拒绝旧执行绑定；当前反馈及退出核清前不发新业务。不凭磁盘 holding 字段假定仍抓稳 |
| 旧回包、旧帧、旧授权迟到 | 保留历史，按实例、epoch、permit_seq、session 和帧序号拒绝恢复；不同目标的旧停止不得误停新源 |

恢复创建的是有独立身份的当前退出核验，不是把旧 prepare 换号重做。重复查询不产生新效果；大脑与网关不能持有账本锁等待对方 HTTP／native 回执，避免取消和释放回调互等。

## 12. 诊断与最小验收闭环

status 提供同一一致快照，明确分离服务可用、许可有效、准备完成、业务执行和整体退出；保留当前阻断与历史错误的区别。至少包含：

- 当前 robot/resource、来源、任务／命令、授权版本、许可阶段与剩余时长、各进程实例和实际构建指纹。
- NAV／VLA 各输入的收帧数、拒绝数及原因；网关转发数、最后 session/topic/sequence；SONIC 实际接收／采用证据。必须按同一会话关联计数。
- 源端封禁、网关封禁、native 回调隔离与缓存失效、身体停止／保持、O6 封禁／保持／持物分项证据，未知明确为 null。
- 任务请求、许可签发／续期、首次响应、原请求查询、取消接收、封禁、隔离、停止和保持的时间。跨机器不用 monotonic 相减，端到端按调用方完整往返计时。

按以下顺序分阶段验收，不用测试数量或健康绿灯代替实际数据到达；NAV 阶段不等待 VLA／O6 功能完成，手部范围按第 14.1 节限制：

1. 纯软件合同测试：版本／身份／角色、单 owner、许可阶段、时效锚点、重复请求、迟到续期、撤权先到与新实例恢复。
2. NAV 隔离数据测试：真实 NAV 格式 ZMQ 发布器＋网关＋native 替身；第二来源可用测试发布器验证无许可不放行，不要求真实 VLA worker。覆盖错误源、旧 session、重复帧、失联、许可过期及源未停仍不能穿透。
3. NAV 闭环：先离线串联大脑，再按真机授权范围验证准备数据完整到达、静止激活、首段行走、取消、退出核清及再次发布；包括大脑／网关／NAV／SONIC 重启、通信故障与取消竞态。
4. 接入 VLA／O6：补双真实来源数据测试、VLA 单段及手部 execute→hold；覆盖许可过期、反馈丢失、目标被改、旧开合帧重放，再验 NAV→VLA→NAV 与保持持物运送。
5. 三端异常恢复通过后，再验完整接待。各阶段测量实际发送频率、许可延迟、封禁时延及对应身体／手部停止和保持时延；NAV 阶段通过不代表手部或完整接待通过。

资源解耦应准确定位：当前 `lease_identity(robot, task, command)` **已经不含发布地址**，无需为了换网关重新生成历史 lease_id。耦合位于 `BodyControl.binding`、lease 行和合同 `IDENTITY` 中的单一 `action_endpoint`，以及 `relay_base_url` 和端口释放判据。新 `control_resource` 表示同一机器人身体，NAV／VLA 地址按来源 profile 绑定；换源不能建立第二个 owner 或独立 epoch 序列。

具体缺口及实施约束：

1. **本地 register 不等于源端登记。** 现有 register 只写大脑授权记录，没有 publisher/session 回包。NAV 当前先 `relay-enable` 再等待完整 prepare；VLA 当前先提交任务，由外部 acquire 回调推动授权。必须让原受理回包或进度查询提前暴露源端会话，不能把旧同步 prepare 完成当作取得会话的前置条件。源端登记请求也须发送前留痕，丢回包只查原请求，不能新建 session 重试。
2. **业务提交意图需要准确分层。** 现有 `business_submission` 同时参与防重放和“从未提交业务”的恢复判定。VLA 新流程的任务受理只登记／准备，不能因此声称已经推进轨迹，也不能在取消时当作完全没有远端效果。分别记录原登记／准备与 execute 请求身份，在现有账本保留两者；只有明确证明业务从未提交时才能沿用原未执行判定。
3. **请求机制可复用，等待方式不能照搬。** `BodyControl.exchange` 在 HTTP 前落盘、HTTP 时不持账本锁，重入查询原请求，可保留。`ControlDriver.exchange` 当前会一直等 pending 到终态；会话早期回包需有单独的阶段观察出口，不能靠它等 prepare 完成才发 grant。续期每轮是新 request_id／permit_seq，原请求查询不刷新期限。
4. **取消必须绕开长操作等待。** 当前 `_cleanup()` 在执行停止前等待全局 busy，最长 30 秒；`ControlledBodyAdapter.cancel()` 先等源端取消，再组织退出。新实现先在同一账本事务记录撤销意图、停止续期和新派发，再用既有工作器并行推进源端停止与网关撤权／封禁；收尾核验可以等待，封禁不能等待 busy 清空。并行任务不能因共用线程池被准备查询占满而互相等待。
5. **恢复证明扩展到两来源。** 现有新退出检查主要覆盖 NAV；VLA `_cleanup()` 仍依赖 stop／release 回调。新合同允许源端失联后的接收隔离恢复，必须对 NAV 和 VLA 都检查旧许可不可复活、旧会话与在途效果隔离、身体及 O6 当前退出证明；源端停发未知继续保留为未知。不能仅删除 `publisher_stopped` 检查而不补接收侧证据。
6. **续期和撤权也需并发保护。** 许可发送前与确认时核对 authority、epoch、目标实例、当前阶段及撤销状态；许可序号分配在现有账本锁内，网络等待在锁外。阶段升级与同阶段续期的重排处理须冻结，不能让迟到 prepare 续期降级 execute，或让迟到执行许可覆盖已记录撤销。
7. **迁移保留来源，不恢复执行权。** 当前 store 只接受 schema=1，启动时 binding 变化直接拒绝。迁移应先核清旧占用，备份并记录原 schema／binding／摘要，显式映射新 resource 与来源 profile，保留任务、lease、epoch、原请求及回执。新启动仍无有效执行许可；不靠清空账本或把旧身份字段整体重写为新修订完成迁移。

上述清单将改动集中在已有控制内核、执行适配和应用接线；源码级“最小改动”不能省去新增许可机制及取消并发保证。Runtime 是否需要补充证据映射，应以新适配输出和现有恢复判据的合同测试为准，不预先改写任务状态机。

| 续期 | 从 prepare 许可安装后调度 renew，复用现有工作器和账本；与升级、撤销串行分配序号 | 高频路径本地验期，拒绝过期、撤销或阶段不符的续期，不因迟到请求复活 |
| 取消 | request_cleanup 先记录撤销并停止续期／新派发；改造 _cleanup 与 cancel，使 NAV 停止和网关撤权／封禁并行发起 | 按原目标分别举证源端停发、网关封禁、SONIC 隔离及身体停止／保持；与 NAV yield 内部效果合并，不能排在长 prepare 后 |
| 再次发布 | 当前退出核清后按 Runtime 规则建立新命令和新授权；保留旧请求、失败与未知结果 | 新建 session，退休旧 session；迟到旧数据／许可／停止请求不能影响新源 |

**登记的 HTTP 映射需选定一条。** 优先复用原 prepare 的早期回包／查询，但不能把逻辑阶段误写成重复 POST：

- 若原 prepare 同时承担登记：大脑先发送一次原 prepare，NAV 在任何需要许可的效果之前返回 pending 和 publisher/session；大脑推送 grant，NAV 从网关确认已安装许可后继续同一 prepare。大脑查询原 prepare 至完成，不再发送第二次 prepare，也不反向轮询大脑授权。
- 若导航已有可复用的独立登记入口：先登记取得 session，再 grant，确认后调用一次原 prepare。具体路由及受理回包由导航提供；不为这两种映射同时维护两套正式执行分支。

两种映射均要求本轮授权关联在登记前确定或有明确的后续绑定操作；现有 `register()` 的 ownership_epoch 初始为 null，不能把它直接当成完整许可。尚未取得 session 时取消，先按已知 task／command／lease／authority 等稳定身份留撤销记录，禁止后到登记触发 grant；网关如何接收未完成绑定的撤销目标须在冻结时给出样例。许可未知时不得发送 goals；业务已提交后的续期失败必须进入封禁／退出流程。

**共同字段与回执范围：** 使用第 4 节身份及第 8 节四态回执，不另起字段体系。第 8 节 VLA 示例不直接当作 NAV 请求模板；两端须提供按登记、grant、prepare、allow_execute、renew、revoke、fence／retain、查询划分的必填／可空字段及回显表。许可回执除原身份外，必须能核验 permit_seq、已安装阶段、目标实例与不因重查改变的截止；具体字段名及单位随时效方案冻结。保留请求唯一 ID，不使用业务 command_id 代替各操作 request_id。

**VLA／O6 后接的边界：** 网关独立生命周期、两来源身份和唯一身体资源保持不变，本阶段只放行 navigation 身体许可，VLA 输入无许可不得转发。NAV 的 hand_mode=hold 表示不授予手部开合权限，不证明 O6 已收到许可或已经保持；未接入的 o6_instance_id／hold_reference_id／退出反馈不得填造值，必填性和未接入表示法须冻结。NAV 阶段验证范围限定为无 VLA 业务、无持物依赖的身体闭环，旧 VLA／O6 业务写入通路及遗留占用需先核清隔离。涉及现存握持、旧手部动作未知或 required_holding 的任务，仍要求真实 O6 证据，不能以阶段范围豁免。该范围下的 NAV 退出证明不得宣称整体身体与手部退出已验收。

**冻结前还需两端共同确认四项交付：**

1. NAV 登记入口映射，以及登记早期回包、prepare 完成、goals 准入和取消先到的正反样例。

4. 同一 NAV 阶段修订号及能力范围、源端／网关重复取消合并规则、重启／迟到结果测试矩阵。确认后大脑和导航并行实现，不以 VLA／O6 功能完成为前提；VLA 执行与跨授权持物另行冻结后接入。

## 15. NAV 阶段实际大脑接线（2026-10-27）

导航交付信息明确：NX 独立网关已安装，NAV 已改接，但 native 退出隔离存在缺口。大脑本轮只读取得网关及 NAV 适配源码，按 `fq/vla-handoff/v1`／`20261027-robot-gateway-push-draft1` 实现对接；使用交付修订号不等于宣称整份草案或真机验收已冻结通过。源码和验证证据见[网关接线验证](多端联调_大脑任务与恢复.md#brain-gateway-offline)。

### 当前调用与证据

- 复用 Runtime、BodyControl、ControlStore、原命令与请求查询。正式控制适配已移除 relay 调用及 VLA acquire/release 路径，所有真实导航后端（body_real、reception_real、reception_real_sim_manipulation）必须启用并绑定唯一 BodyControl，不允许关闭网关后回退旧直接派发。混合适配复用同一 ControlledBodyAdapter：导航是真实身体执行，操控与虚拟持物只在本地模拟；允许“开始接待（导航真机＋操控模拟）”，但不签发任何手部权限或向 NAV 传真实携物要求。仿真后端保持原接线。
- NAV 原 prepare 只 POST 一次。通过原 NAV 查询读取 `execution_stage=session_registered` 及 `evidence.publisher.publisher_instance_id/input_session_id`，先安装 grant，再查询同一 prepare 至完成；核验同会话、fresh_preparation_output、navigation_not_started、mode_confirmed、hold_verified 后发送 allow_execute，确认后才登记并发送 goals。
- 网关使用 HTTPS、独立 `BRAIN_GATEWAY_TOKEN`（支持 `_FILE`）及指定 CA 文件；正常校验证书与主机名，鉴权请求不跟随重定向，也不向其他 origin 发送凭据。NAV 沿用自己的 `nav_token_env`，不混用网关 token。
- 网关 status 不带旧 NAV 的 updated_at，因此单独校验修订和实例，并通过本次 freshness_anchor 与 native.observed_monotonic 的同机差值检查 native 观测不超过 150 ms；不能跨机器比较 monotonic。每轮许可申请新的 observation_id／challenge，要求安装回执的完整 identity、绑定、permit_seq、phase、hand_mode=not_required、hold_reference_id=null 和截止与请求一致。
- grant／renew／allow_execute 必须 `completed + accepted=true + effect_status=confirmed + evidence.permit_installed=true`。blocked／unknown／拒绝和丢回包均不能放行业务。revoke 要求 `evidence.permit_revoked=true`，只表示许可不可再用；`execution_started` 是管理操作效果，不是机器人已经走动。
- 当前网关限制：锚点窗口小于 500 ms，许可整数时长不超过 1500 ms。大脑公开默认为 1500 ms 许可、400 ms 续期、单请求 200 ms 超时，覆盖准备和执行阶段；这是软件配置，尚无现场调度时延保证。grant／renew／升级串行分配并确认，revoke 不等这把网络操作锁；发送前及回包后均重查取消和当前 authority。大脑用请求开始时间计算保守本地期限，重启清空，不将 NX 截止时间当作本机时间。续期调度同样按最近一次已确认许可的原请求起点计算下一次应发时间，将 HTTP、锁等待与落盘耗时计入间隔；处理超过间隔时串行立即推进，不在确认后额外固定等待，也不批量补发历史续期。
- 许可工作器只维护当前身体许可，不增加任务循环或第二本账本。两个有界退出工作器让 NAV 停止和网关撤权独立发起；账本锁不跨 HTTP。续期失败先撤销本地执行资格并组织退出，不能自动重新 grant。同一请求只首次 POST，后续只查原 ID，保留首次错误和历史回执。

### 退出和恢复的实际限制

正常 NAV 结束在原执行等待路径组织 yield／revoke／fence；任务取消另外在确有业务提交意图时发送原 command 的 cancel。退出发送不等待长 prepare 完成；最终释放占用才等待本地准备收尾。状态查询不执行任何效果。

网关现在通过 status.exit_status 给出当前退出证明，原请求查询可以另附 current_exit，原历史 unknown 不改写。大脑核验当前证明的完整身份绑定、exit_confirmed、body_forwarding_fenced、receiver_callbacks_sealed、receiver_decoded_caches_cleared、input_session_retired、body_stopped、body_hold_verified；还需网关无许可、last_binding 同一目标以及新鲜 native 的 receiver_isolated、body_stopped、body_hold_verified。手部范围必须 not_required、old_hand_task_pending=false；O6 保持／封禁和 hand reference 明确为 null，不填造 true。原 fence 未知可与有效当前退出证明并存，原请求及错误保留；源端停发未知仍单独为 null。

登记前没有任何对端写请求的本地意图可以按账本核销；已发 NAV 登记但从未记录 grant 时，仍须目标撤销、NAV yield 及当前隔离／保持证明。已发许可或存在 session 的路径不得使用此简化出口。原操作未知保留，`new_exit_check=true` 为同一原目标创建独立当前退出请求，不重发旧 prepare。退休或缓存证据缺失仍阻断，不凭重启推断旧效果已经退出。跨重启核清须由认证网关的当前退出证明完整关联原绑定：新网关明确启动未恢复许可，当前许可为空；SONIC 实例变化时还须证明旧控制器进程已不存在、当前控制器身份一致、无任务绑定及待处理操作，并提供新鲜的隔离和身体停止／保持观测。缺少任一条件继续阻断。已有退出请求或旧大脑身份的恢复先核验当前证明，证明完整时直接释放旧占用，不再向旧实例补发效果；历史子请求 unknown 和原任务失败保留。

首次交付缺少 native fence／退休字段的历史失败保留在联调记录。导航随后交付 native-session-exit-v2 和身体独立模式，本轮已按实码对接；这不代表真实安全状态已通过。NATIVE_SAFETY_NOT_CLEAR 仍阻断准备与执行，不能随 O6 解耦忽略。真实 VLA、手部业务许可和携物任务不在首阶段范围。

### 续期与静止核验的阶段区别

2026-10-27 真机准备排查发现，大脑此前把身体静止保持用于每次续期，会误拒绝静止激活的过渡阶段和正常行走。已修正：准入、allow_execute 和退出仍要求静止保持；同阶段 renew 校验原绑定、阶段、许可期限、当前控制器、执行时 active_session、新鲜控制观测，以及同机锚点下 100 ms 内 LowState、safety_override=false、policy_output_selected=true，不要求机器人行走时静止。不修改网关租期、时效锚点或身体安全保护。

封禁回执完成后，身体停止／保持窗口可能尚未形成。大脑现按原 operation_timeout_sec 有界查询当前 exit_status，直至完整退出或超时，不重发 native 效果；单次状态读取超时也只在原预算内重查 GET，原未知回执继续保留。首次自动撤权错误保存为 revocation_reason／revoked_at，避免被后续 cleanup_error 覆盖。证据见[准备取消排查](多端联调_大脑任务与恢复.md#brain-nav-prepare-cancel)。


## 16. 会话持续授权：大脑与导航隔离接线

2026-10-27 用户明确要求：导航／操控控制主体未改变时，不因大脑到真机网络波动使授权过期。大脑仍是唯一授权方，独立网关仍负责准入与转发，不回退 relay；取消原短期执行许可对云端周期续期的依赖。本节描述已对齐的候选实现；现场部署状态须单独核查。

### 生命周期与边界

- 控制会话与业务命令分离：持续授权绑定 robot／body、控制授权身份与代次、来源、发布进程、网关／SONIC 实例和输入 session；task_id／command_id 保留为业务关联与原请求账本身份，不再因其变化自动撤权。仅 source_id 相同仍不足以接管；新进程或新输入会话不能继承旧权限。字段拆分采用下述修订，原命令身份保留。
- 首次取得控制权保留 grant(prepare) → 实际收帧与静止 activate → allow_execute → goals 的顺序。准备许可不等于业务执行许可；同一控制会话内更新导航目标或切换小任务不重复 grant／prepare／activate，不重建发布器或输入 session，也不靠周期 renew 维持有效。新命令由大脑认证业务接口明确下发，NAV 仅在上一段停止且当前保持已确认时接续，新目标忙时返回 NAV_COMMAND_BUSY，不排队、不隐式替换，旧命令的迟到结果／取消只能影响其自身，不能误停新的活动命令。
- 云端短暂或持续失联，不单独触发已授权任务停止；真机继续执行已收到的当前业务。大脑状态查询失败只记为观测未知，不自动撤权或重复派发。云端失联不允许执行方自行编造新业务命令、切换来源或创建新控制会话；此前已明确接收的业务按既定顺序执行。
- 数据流断流、源端进程变化、接收实例变化、本地故障及急停仍由真机及时处理；不得把源端断流保护一并取消。小任务完成时停止该任务的业务动作，源端按本地保持机制维持合法数据流并等待下一命令，不把任务间保持当作退出，不继续旧业务运动；本地故障按故障范围决定停止业务或封禁会话，不因一般业务失败一律撤权。
- 明确释放控制权、整体停止／取消及 NAV↔VLA 交接结束本会话；小任务正常完成或新 command_id 到来不结束会话。单命令取消与整体停止必须区分，网页整体“取消任务”立即终止大脑流程并允许新发布，同时持久记录原控制目标，并行通知源端停止和网关撤权；物理退出独立核清，原会话不再阻断本地发布。网关收到撤权即封禁，新执行权仍由接收端准入。断网中取消仅能显示已请求／待送达，不能宣称实体已停；现场本地停止能力独立保留。
- 网关／SONIC 重启不恢复磁盘中的旧执行权。大脑重启不自动续跑或换身份抢占；先查询、核清旧关联，旧网关会话不会仅因大脑进程换代被视为已释放。
- 保留 request_id 幂等、permit_seq 递增、防重放和撤销记录；已退出会话不得因迟到 grant／allow_execute 或恢复网络复活。请求新鲜度约束可以保留，但不能再作为已安装授权的周期到期条件。

### 最小实施分工与切换条件

| 负责方 | 必要改动 |
| --- | --- |
| 大脑 | 复用 Runtime、BodyControl 和原账本；移除周期续期工作器及本地短期截止作为执行存活条件；改按已确认绑定、阶段、取消／退出状态判断；网络观测未知与明确失效分开；将控制占用与单命令完成解耦，保留取消恢复与原命令查询 |
| 导航／网关 | 提供明确的会话持续授权能力和修订；安装许可不再依赖时间到期，状态与回执不再把 remaining_ms 当作唯一有效性；NAV 本地验权适配新状态；支持同源新业务命令连续执行及任务间保持，保留数据断流、本地保护、明确释放与旧会话封禁 |
| 双方 | 冻结授权生命周期字段、有效状态及取消待送达回执；同步更换运行版本，不以超大 TTL、伪造续期或单端停发 renew 代替实施 |

导航已交付完整 HTTP 回执，大脑按同一修订接入；不得在仍仅支持 1500 ms 期限的现场网关上单方面移除续期。NAV 首阶段保持 body_only、hand_mode=not_required，真实 VLA／O6 功能仍未启用，后续使用相同生命周期原则。

验收覆盖：云端断网超过旧 1.5 秒时，同一已授权 NAV 业务继续；联网取消及时生效、断网取消保持待送达；NAV 数据断流仍本地停止；连续新 command_id 不封禁、不重复激活，旧命令迟到结果／取消不干扰新命令；小任务结束进入保持，整体结束明确释放；换源前核清旧会话；进程重启与迟到授权不能复活旧输入。验证这些结果后才能把本节标为已实施。


### 16.1 冻结字段与大脑实现

- contract_version=fq/vla-handoff/v1、coordination_revision=20261027-control-session-v1-draft1、permit_mode=control_session、renew_required=false。新候选不保留旧定时许可运行分支，拒绝 renew；请求不发送 lease_duration_ms 或 freshness_ref。
- 大脑创建不复用的 control_session_id，lease_id 标识整个接管会话，ownership_epoch 只在新会话增加。permit_seq 只用于 grant／allow_execute／revoke。同会话 command_seq 跨 task_id 递增；每条 goals 仍保留原 task_id／command_id，并带独立 request_id、control_session_id、control_authorization、command_seq、dispatch_policy=when_idle。
- 原 NAV prepare 只在首次取得控制权调用，注册采用 registration.publisher_instance_id／input_session_id；完成回执须精确回显 identity，nav_instance_id 与 query_nav_instance_id 一致、historical=false、current_prepare_valid=true。身体静止激活、实收帧及同会话证据继续核验。
- status.freshness 使用网关单调时间和 sample_age_ms／body_sample_age_ms；身体观测上限 100 ms、native 观测上限 150 ms，缺失／过期阻止新准入或退出核清，不使已安装的执行许可因云端心跳缺失自动到期。公开 gateway_timeout_sec 改为 2 秒，它是单次 HTTP 等待预算，不是控制许可期限。
- goals 的 current_hold 必须 applicable=true，精确关联四元组 control_session_id／task_id／command_id／command_seq，并确认 command_stopped、motion_held、body_hold_verified、control_session_retained；publisher／输入 session／SONIC 实例必须匹配。旧命令查询 applicable=false 不得核销新命令。当前保持证明可补充历史停止未知，原业务结果不改写。
- 单命令取消 POST /v1/navigation/cancel 携带 cancel_scope=command，pending／丢回包后 GET /v1/navigation/handoff/requests/{原request_id}，不重复停止。整体取消／释放采用 cancel_scope=control_session 的 NAV yield 与网关 revoke 并行；原 yield unknown 保留，当前完整退出证据可独立解除占用。
- BodyControl 继续使用原 body_control.json，schema=3；每个控制会话的 commands 保存业务关联、原请求、序号、派发与保持记录，不另建任务系统。Runtime 的步骤资源释放只指该命令执行槽；适配器明确附带 resource_scope=command、body_control_released=false、control_session_retained=true，不能冒充整个身体占用释放。
- 正常同源会话保持时 control_recovery.occupied=true、blocked=false；异常／重启／退出未核清仍 blocked=true。网页显示“控制会话保留”，整体“取消任务”仍触发独立退出。当前支持 NAV 身体及本地模拟操控，真实 VLA 未接入。

### 整轮取消与新任务准入（2026-10-27 更新）

用户明确要求整体“取消任务”后立即结束大脑当前流程并允许发布新任务，不把旧退出 unknown 继续作为本地发布阻断。Runtime 先持久取消并关闭后续派发；BodyControl 在同一目录锁下将对应控制会话标为 task_cancelled／revoked，解除 current 和仅属于该会话的 busy 指针。原命令、失败、unknown 与请求记录保留，不改写为物理退出成功。

源端停止和网关撤权仍按原控制会话身份后台收尾，工作器按 lease 分别跟踪；重复取消不重复派发效果。旧退出完成只能更新旧记录，不能清掉新会话 current／busy；旧准备／授权迟到回包不能恢复旧流程。重启不将已取消会话重新放回当前占用。status 的 blocked／pending／occupied 只反映当前任务准入，previous_exit_unconfirmed 独立统计历史未核清退出。

新任务可以登记／发送准备请求，不在大脑入口等待旧收尾。真正安装新执行许可仍需导航／网关核验旧流隔离与当前接收准备；旧网关若拒绝接管，应作为新请求的真实回执显示，不能在大脑伪造授权或忽略接收保护。本次没有改变网关的接管规则。

### 网关自动接管与 NAV 原接单边界

2026-10-27 导航已应用网关 brain-takeover-v1 能力，大脑按相同 control-session 修订接入：新控制会话仅 grant 携带 takeover=true、完整新绑定及递增 ownership_epoch；同会话新命令仍发送 dispatch_policy=when_idle，不发送 replace_current，不在大脑或网关新增业务排队／自动替换。

大脑先确认网关能力，再调用原 NAV prepare 获取登记身份。NAV 自己决定忙时拒绝或按原规则处理。登记后大脑核对目标 SONIC 实例，不在发送接管 grant 之前要求旧流已经隔离，否则会与网关接管互等。网关收到 grant 可返回 202/pending，由其自动封禁旧流、核验 SONIC 隔离和保持后安装 prepare 许可；大脑保留原请求并 GET 查询，不重发 grant。只有安装回执、原准备完成与当前身体证据都通过，才 allow_execute、下发业务。旧实例或本地故障仍由网关明确拒绝或返回未知，不伪造成功。

此修改只接入网关授权接管；NAV 业务接单规则、规划算法和真实 VLA 范围均未改变。缺少 brain-takeover-v1 时大脑拒绝新会话授权，不静默退回旧逻辑。

2026-10-28 错误显示更新：NAV 可返回 current_prepare_blockers／current_prepare_observation。大脑在 current_prepare_valid 不为 true 时保留完整原回执及分项原因，页面说明具体准备失败原因和目标尚未下发；不因历史 completed 或诊断字段出现而放行。缺少诊断字段时仍拒绝并显示“导航准备未通过当前状态检查”。编号生成、授权合同和证据标准未改变。

### 16.2 VLA 按需接入（2026-10-28，代码、隔离联测与大脑应用）

控制基线继续为本节 control-session 修订；大脑已接入 `vla-gateway-v1-candidate1`，沿用原 Runtime、BodyControl、schema=3 控制账本和退出工作器。2026-10-28 已取得网关正式源码交付并完成初步单动作隔离联测；最新 lock1 正式源码已补齐退出账本读取锁，11 个模块哈希核对及新包 HTTPS 三端 10 项复验通过；旧包失败与修复证据见[故障与复验](多端联调_操控与抓取.md#brain-vla-gateway)。2026-10-28 13:35 已按用户要求重载大脑并核对新能力生效，网关仍报告 NAV-only、VLA 真实依赖仍未就绪，真机未验收。本段替代第 15 节“真实 VLA 在派发前统一拒绝”的当前源码描述；第 15 节的部署和历史证据仍保留。

**按当前命令检查依赖。** 规划阶段的大脑能力目录只声明已实现的动作，不查询全部执行端的在线状态；具体动作提交时再核验所选执行端、网关及本动作需要的证据。普通 NAV 仍为 hand_mode=not_required、hold_reference_id=null，不查询 VLA／相机／O6，也接受声明扩展能力的网关。真实 VLA 仅支持 open_fridge／grasp_cola，准备为 hold、执行为 execute，必须核验双手；混合模式仍只模拟操控。身体独立网关明确报告旧手部动作未退出时，在 grant 前阻断，因为其不能完成手部隔离。缺席的另一端不等于有旧占用，旧占用未知也不能视为已退出。

| 大脑调用／记录 | 对齐要求 |
| --- | --- |
| POST `/v1/vla/handoff/prepare` | 内含完整 business_request；先返回 registration，随后 GET 原 request_id，不重发准备 |
| business_request.control | coordination_revision、permit_mode、control_session_id、control_authorization、command_seq=1、prepare_request_id；准备与执行使用同一份落盘业务请求 |
| registration | 原 GATEWAY_BINDING 加 o6_instance_id、hold_reference_id；VLA 的 action_endpoint 来自本次认证登记，允许与 NAV 来源地址不同，由网关校验受信来源与端点 |
| grant／allow_execute | 仅大脑发权；grant 带 takeover=true、hand_mode=hold，allow_execute 带 hand_mode=execute；绑定同一发布器、输入会话、网关／SONIC／O6 实例及准备保持参考 |
| GET 原准备请求 | 精确回显 request／request_id、registration、业务身份；vla_instance_id=query_vla_instance_id、historical=false、checked_at 新鲜、current_prepare_valid=true；保留 current_prepare_blockers 与原回包 |
| current_observation／网关状态 | 检查当前授权、SONIC 采用本输入、身体保持与安全；双手实收准备帧、权限、反馈、保持参考和实例必须匹配；native≤150ms、body≤100ms、O6≤250ms，VLA 准入计入查询 RTT |
| POST `/v1/vla/tasks` | 与 prepare.business_request 完全相同；先落盘提交意图，超时只查原 command_id，不重复启动 |
| pause／finish | 沿用原业务接口和独立效果核验凭据；finish 只确认效果，不用于开始动作 |
| 结束／取消 | 沿原退出工作器并行 VLA handoff/yield 与网关 revoke；网关 fence 与当前退出证明核验身体隔离、缓存清除、输入退休、身体保持及真实 O6 封禁／保持。原未知回执保留，不能由策略结束替代退出证明 |

**O6 安装时序已按网关交付对齐：** 大脑 grant 不携带业务 task_id／command_id，只安装身体准备许可并核验当前 O6 保持参考；不把 grant 回执当作 O6 已绑定新业务。VLA 首次 native prepare 经网关 operations 提供原业务身份，网关固定本会话业务关联，先安装 O6 hold，再执行 native prepare。随后接收准备帧、activate，大脑才要求 current_prepare_valid 及 O6 当前绑定通过。allow_execute 先确认 O6 execute，再确认身体 execute。网关以 `vla-prepare-installs-o6-v1` 声明该时序；大脑当前准备检查位置无需提前或放宽。

VLA 的大脑 fence 请求须保留原 o6_instance_id／hold_reference_id。grant 后、首次 prepare 前取消时，可能没有新 O6 绑定；仅当网关给出精确关联原会话的完整当前退出证明、o6_never_bound=true、原 O6 实例匹配，且接收器已封禁、双手新鲜反馈及保持参考通过时，才接受这一未安装分支。若仍有 O6 permission，只能是更早且不同的会话；新会话、同代或更高代许可、缺失证据均不放行。这不把“手部没有启动”当作已保持，也不将旧安装结果未知转换成未安装。

每个 VLA 控制会话只接一个动作；再次动作创建新会话、command_seq 重新为 1，原授权编号按现有机制递增。NAV 同源连续目标仍复用会话；切换执行来源时沿原退出流程核清后准备下一端。持久化记录 VLA source_url，未退出时改变地址不会把查询改发给另一服务；重启不恢复旧执行权。普通状态接口、原请求查询与大脑效果 query 不触发授权或重发；Runtime 原执行／恢复流程负责结束后的控制退出。

**作业准备证据由大脑组织，VLA 不查询 NAV。** 业务请求携带 `worksite_evidence`，schema=`fq/vla-worksite-evidence/v1`，绑定 task_id／command_id／operation／object_id／target_area、机器人、SONIC 实例及本次 control_session_id，包含 ready、pose_verified、reference、pose_reference、observed_at、valid_until。仅 ready=true 不够。

- 现有接待的 navigation_proof 由大脑在操控准备时核验原成功命令、完成时间和当前 pose。NAV 当前观测须关联相同目标、原命令、机器人／SONIC 实例，并给出有效 map_id／localization_epoch／navigation_epoch；缺失则明确阻断。核验后转为 kind=navigation_arrival，附 navigation_command_id／navigation_result_reference，原始命令与观测保留在控制账本。有效期从原位姿观测起 60 秒，不因查询续期。
- 已有经授权业务请求携带 operator_ready 或 navigation_arrival 时，适配器验证身份、来源参考、位姿、实例和原有效期，不访问 NAV；允许有效期不超过原观测后 300 秒。大脑只补上新控制会话关联，不自动生成现场确认、不延长证明期限。2026-10-28 新增“导航模拟＋操控真机”接待按钮，通过原发布入口记录现场作业确认，详细模式与时限唯一维护在[大脑接待入口](接口说明_大脑%20Brain.md#81-流程与请求身份)；普通全真机接待仍需要实际导航到位证据。

网关须按来源与动作类型提供 VLA CURVE 订阅、原 pose 校验、streamed_motion 准备／激活、VLA 独立角色，以及 O6 许可／封禁／保持事实。大脑不直接操作 O6 CAN，也不替网关验证运动载荷；旧 relay 不参与。NAV 不携物时不能因 O6 未运行而被统一门禁阻断。

**剩余范围：** 真实持物 NAV 的 hand_mode=hold、跨授权持物证明及有效期仍待下一阶段对齐；当前大脑继续拒绝真实 required_holding，不能将抓取单动作支持解释为完整搬运已通。生产网关接线、现场 NAV 当前位姿投影、准备时延和三端真机切换均待验收。验证方法和结果见[大脑 VLA 网关隔离联测](多端联调_操控与抓取.md#brain-vla-gateway)。

### 16.3 切换与账本迁移

本轮先完成代码及隔离验证，随后用户明确要求直接应用大脑：已备份私有配置、更新 permit_mode／HTTP 超时，保留未核清占用迁移账本结构为 schema=3，重载大脑／网页／本机面板。未由大脑启动或重载 NAV／网关／SONIC，未发送真机动作。

1. 现场旧任务退出核清后，停止旧版本服务并保留配置／账本备份。导航按其迁移工具取得明确退出证据、持有服务锁，提供完整迁移回执。
2. 大脑旧 schema=2 账本须无在途写入：已 released 记录原样保留；未核清占用只有在导航迁移回执 previous_gateway_state 完整匹配原绑定、分项退出证明完整时才追加迁移退出证明并 released，原 evidence 和失败请求另存保留，不能删除未知记录解锁。沿原迁移脚本先预览再应用：

```bash
venv/core/bin/python scripts/migrate_body_control_gateway.py --root data/tasks --session-migration-receipt /absolute/path/to/verified-nav-migration.json
venv/core/bin/python scripts/migrate_body_control_gateway.py --root data/tasks --session-migration-receipt /absolute/path/to/verified-nav-migration.json --apply
```

脚本持有同一大脑服务锁，创建 SHA-256 对应的原始字节备份；完整保留旧请求／失败／unknown，读取 minimum_next_ownership_epoch，下一会话代次不低于本机历史高水位及导航要求，不恢复旧许可。不匹配原 session／实例或缺少分项证明的回执不能解除占用。若先应用大脑而导航尚未迁移，可用 --stage-control-session --apply 只升级结构、标记旧记录 legacy_control 并继续阻断；取得完整回执后按同一脚本完成核清，期间大脑服务锁必须释放。

3. 匹配版本共同配置 permit_mode=control_session，移除旧 lease_duration_ms／renew_interval_sec，核对 capabilities／status 修订与 renew_required=false 后启动。若大脑先应用，必须采用上述保留阻断的结构迁移，不得让新任务进入尚未迁移的网关；新代码明确拒绝旧配置和 schema。
4. 现场验收同会话连续目标、云端管理链路中断、命令取消、整体取消与再次发布；离线通过不代替真实行走和本地停止验收。

实现与验证证据见[持续会话大脑联测](多端联调_大脑任务与恢复.md#brain-control-session-integration)。
