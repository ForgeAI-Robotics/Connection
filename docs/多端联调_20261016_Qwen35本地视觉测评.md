## 3. 视觉内容与失败记录

输入来自仓库现有 `lite_kitchen.py` 场景：每个初始场景步进 200 次，保存 XML、来源哈希、图像与标签。六个场景涵盖三个视角、移除蓝色物体、仅保留蓝色物体和空桌面；另测重复输入、双图变化、无法确认的交接／检测结果、用户图中的模型型号，以及历史 O6 录像帧的任务状态文字。O6 帧的来源哈希与帧号保存在 `cases/o6_provenance.json`，只是本次读图输入，不是新的导航实跑。

首轮 `results/20261016-183433/`：模型输出都带 Markdown 代码围栏，严格 JSON 0/14；另行去除围栏后的内容审计为 13/14，不能用该审计覆盖原严格失败。提示明确禁止 Markdown 围栏后，`results/20261016-183629/` 复测达到严格 JSON 14/14、内容 13/14。两轮侧视图都计数错误，未改标签或删除样本。

正式大脑的实时相机任务使用 `head_cam` 和 `robot0_frontview` 两个视角：

- 普通桌面：正确描述橙色圆柱、红球、蓝色圆柱、白色扁平圆柱、红色圆柱，整任务约 1.56 秒。
- 空桌：回答“眼前桌面上有一个白色的胶囊状物体”，整任务约 1.06 秒。核对场景几何及保存画面，该物体是前景机器人末端，并非桌面物体。**任务 succeeded 仅表示取得描述，不能记作视觉语义正确。**

因此不能只依据接口成功或 Runtime 的描述步骤成功判断 VLM 效果。多视角目标归属与复杂角度计数仍有实测错误。

## 4. 大脑实测发现的合并动作问题与修复

首次实际规划返回 `抓取 milk_1 并放置到 milk_area`。原 Desk 解析通过局部匹配得到抓取，归一化后丢失放置；任务显示 succeeded，但物体仍被持有，`place_miss` 故障也未消费。

证据为 `http_runs/20261016-183758/`、`http_runs/compound-plan-evidence-1792147140411494847.json`。首次脚本只检查状态，部分 `passed` 标记不能证明目标完成；原文件保留，并以同目录 `audit.json` 明确纠正其验收范围。

修复沿原职责实施：

1. `PlanningInputs` 的 Desk 能力上下文明示一个步骤只能包含一个动作，抓取、放置必须分开。
2. `normalize_subtasks` 使用既有动作解析器的严格完整匹配，整份计划不合格时在任何动作派发前拒绝，进入 recovery_required。
3. 保持其他后端既有搜索抓取合同、Runtime 状态权威、原命令查询和核验标准。补回归验证“有效前缀＋非法合并步骤”时零派发。

独立模块实验最初还使用了缺少 Desk `execution_rules` 的手工场景上下文，Qwen 编出了导航加抓放步骤，被实验范围检查拒绝。复测改为使用生产 `PlanningInputs.snapshot`，不手工补写模型输出。

## 6. 其他故障、验证与交付

- 下载中出现 SSL 中断、读取超时、进程中断，日志保留；最终完整文件均按官方哈希校验。下载分段只作为传输中间文件，不是模型验收依据。
- Transformers 5.20.0 与现有 Torch 不兼容，报缺少 `torch.distributed.checkpoint.hf_storage`；5.3.0 导入和 CUDA 检查通过。
- 初版本地推理服务未把纯文本消息转换为处理器要求的 content parts，报 `TypeError: string indices must be integers`；修复服务适配后复测通过。
- 终端 SOCKS 代理格式导致一次客户端构造失败；本机直连环境复测通过，没有修改系统代理。
- Qwen 加载前通过正式入口做负向测试，任务因 `Connection error.` 进入 recovery_required，按原任务 ID 取消，没有伪造视觉成功。
- 本次完整回归：`venv/core/bin/python scripts/run_tests.py`，570 项＋27 项通过；日志为实验目录 `connection-full-regression.log`。文档链接及 `git diff --check` 另作检查。

最终汇总在实验目录 `evaluation-report.json`，当前完成状态在 `pipeline-status.json`；首次自动流程失败状态另存 `pipeline-status-first-attempt.json`。完整输出、耗时、标签、相机帧、任务账本及代码哈希均可追溯。首轮结束时保留测试服务，正式配置未切换；后续服务升级见第 7 节。尚未进行真实采样现场、实体机器人或长期稳定性验收。

## 7. 完整推理配置复测（19:31～20:18，已完成）

用户要求使用完整能力后，单独核查了权重与实际推理设置。前述实验使用的是官方未量化 BF16 权重，但采用了关闭 thinking、额外 1024 像素缩图、400 tokens 视觉请求／2048 tokens 服务上限，不能称为完整推理配置。保留前述结果作为受限基线，不以其时延代表本节配置。

权重文件共有 775 个张量、9,653,104,368 个元素：9,653,100,528 个 BF16 元素和 3,840 个 F32 元素，四个分片共 19,306,310,880 字节。原 Transformers 类的状态字典覆盖 760 个张量，没有缺失主干键；其余 15 个为 `mtp.*` 辅助权重。新 vLLM 同时加载主模型、视觉编码器和 MTP，启动日志及运行中的 draft／accepted token 计数验证其实际参与解码。

本轮按 [Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-9B#best-practices)和 [vLLM 官方模型配方](https://github.com/vllm-project/recipes/blob/main/models/Qwen/Qwen3.5-9B.yaml)配置：

| 参数 | 本轮实际配置 |
| --- | --- |
| 服务 | vLLM 0.18.0，`qwen35-vllm.service`，端点仍为 `127.0.0.1:18035` |
| 权重／视觉 | BF16，无量化，不启用 language-model-only；原图交给官方处理器，不额外 thumbnail |
| 上下文 | 原生 262144；已由实际 `/v1/models` 响应核对 |
| 思考与输出 | thinking 开启，`max_tokens=32768`，独立返回 reasoning 与最终答案 |
| 采样 | temperature=1.0、top_p=0.95、top_k=20、min_p=0、presence_penalty=1.5、repetition_penalty=1.0 |
| MTP | 原生 MTP，num_speculative_tokens=1 |
| 执行 | eager；首次图编译报 `standalone_compile` 缺少 `FakeTensorMode` 后采用此兼容方式，模型和生成设置不变 |

模型加载约 18.12 GiB，另分配 KV 缓存；不能将模型权重占用与整进程显存混为同一指标。`full-serving-config.json`、`full-models-response.json`、`server-vllm.log` 保存设置与运行证据。

Connection 的固定生成参数已改为配置读取，默认行为保持。测试工作区显式采用 32768 tokens、官方 thinking 采样参数、1800 秒模型 HTTP 等待与观察步骤期限。对应代码的完整离线回归为 574 项＋27 项通过，见 `connection-full-generation-regression.log`。

本轮设计为 16 个图像用例各三个随机种子、整段历史 O6 录像三次、约 22 万输入 tokens 的检索测试，以及五个正式大脑 HTTP 场景。重复测量不等于 51 个独立场景，也不等于跑完公开视觉基准。所有回答保留实际 token 用量、结束原因、格式检查和错误；原图尺寸、MTP 计数与抽帧设置可追溯。最终状态见 `full-mode-status.json`，审计汇总见 `full-evaluation-report.json`。原始请求、失败与补测均保留。

思考模式、采样、分辨率和后端同时变化，本轮与首轮不是只改变一个变量的消融实验；上述结果不能泛化为公开基准成绩或真实采样现场准确率。

**保留的错误。** 侧视图三个种子均将 5 个物体计成 6 个；双视角空桌仍误报。部分内容正确的回答使用代码围栏，另有单引号 JSON。seed=7 的侧视图生成 18635 tokens、约 309.7 秒后仍错误；更多计算没有消除该样本的误判。长上下文项目是合成检索容量验证，不代表完整长程机器人业务已验收。

**视频接入修正。** 初始三次视频请求在预处理阶段被拒绝，原因为 vLLM 默认只预读 32 帧，随后处理器按 2fps 使用原视频元数据采样，触发 `IndexError: index 38 is out of bounds for axis 0 with size 32`。依官方方式设置 `--media-io-kwargs '{"video":{"num_frames":-1}}'`，预读完整视频后交给官方处理器按 2fps 采样；没有缩短视频或减少采样要求来回避错误。此修改在大脑任务及推理队列均结束后应用。

视频重测中，seed=2026 全部正确；seed=7 内容正确但附代码围栏；seed=42 将最后状态 `succeeded` 读成 `placed`，其余字段正确。最初三次预处理失败不计作有效模型回答，也未删除。
